# session-handoff — 成本超预算自动交接

预算触顶前把状态落成本地文档，并排定新会话接续，避免超预算后上下文丢失导致任务中断。只交接，不替新会话干活。

## 一、触发条件（命中任一即启动）
- `[cost-meter]` 等效成本超阈值预警，或单步未命中 >10k 的「极高」提示。
- `[reasoning-watchdog]` 连续纯推理步告警。
- 步数 >= 150，或每步未命中（uncachedInputTokens / steps）> 10k。上下文压力不再作为触发条件：1301 个历史会话中压力 >60% 触发 0 次（最高 51%），属死阈值；精确判定用 `handoff-policy.mjs` 的 `shouldHandoff()`，勿凭感觉。
- 用户明示：交接 / 换会话 / 成本超了 / 接不上就开新的。

## 二、护栏（何时不触发）
- 只在**步骤边界**执行；下列时刻禁止交接：commit / build / 测试进行中、前端验证门（截图未出、用户未确认）、ask 等待中、工具调用返回前。
- 「前端验证门禁止交接」仅适用于**已进入可验证态**的阶段（UI/页面/交互改动、需出图与用户确认的环节）；尚未进入可验证态的阶段（纯分析、规划、尚无生产产物）不受此门限制，可正常交接，但须在载荷第 7 节携带当前验证状态与失败原因。
- 命中触发但正处于上述状态 → 先完成当前原子动作，再在下一个步骤边界启动。
- 一会话只交接待办进行一次；排程已建则不重复建。

## 三、交接载荷（9 节，固定顺序）
落盘路径：`D:\plan\<工作区目录名>\HANDOFF-CHAIN-<chain_id>-hop<N>-<yyyyMMdd-HHmm>.md`（用 `write` 新建，不覆盖既有同名人；目录不存在先建）。
- `chain_id`：任务名稳定串（去空格、保留中文与字母数字），同一任务链各跳共用；首次交接 hop=1，此后由新会话从文档读取并 +1。
- `maxHops`：默认 10（取 cost-meter `maxHandoffHops`）；hop≥maxHops 即终止链路、不再排程。
- 九节标题逐字如下：

1. `## 交接原因与阈值证据` — 触发类型 + cost-meter / 压力原文。
2. `## 原始目标` — 用户原话逐字，含验收口径。
3. `## 已完成` — 每项带 文件:行号 或命令证据。
4. `## 未完成` — 待办清单，按优先级排。
5. `## 关键决策与约束` — 用户确认过的选项、P0 硬门、不可违背的前提。**链式续接元信息（必填，置于本节首行）**：`chain_id=<稳定串>`、`hop=<N>`、`maxHops=<M>`、`原始目标=<第2节逐字>`、`完成判定=<可客观核验的收尾条件>`。新会话据此判断续接或终止。
6. `## 文件锚点` — 已改/待改文件:行号；关联计划文件路径与其 approved_sha256。
7. `## 验证状态` — build/test/产物证据路径；未执行项写明原因。**交接必须携带当前验证状态（已通过/失败/未验证/未执行）及失败原因**，不得因「未验证通过」而拒绝交接；验证门只管「是否允许提交/回写」，不阻止如实交接状态，由新会话据此续接。
8. `## 已知坑与禁止重做` — 已试错失败的路径、不要重复的宽搜/整读。
9. `## 新会话第一步` — ≤3 条带可执行命令的动作，首句指明先回报目标与待办；**第一动作必须是读第 5 节 chain 元信息**：若第 4 节「未完成」为空或 `hop≥maxHops`，回报「链路终止（任务完成/达跳数上限）」且**不排下一跳**；否则才按第 36-50 行排 hop+1。

载荷只写**事实与证据**，不写推理过程；每条带路径/行号/命令，便于新会话零成本采信。

## 四、排定新会话
写完载荷后调用（参数不得缺省）：

```
schedule_create(
  prompt = "读取 <HANDOFF 绝对路径> 并按第 9 节接续任务。先回报你接到的目标与待办，不要重跑已完成项；文档与你的上下文冲突时以文档为准并说明。本链 chain_id=<稳定串> 第 <N> 跳（上限 <M>）：若第 4 节未完成项非空且你再次触顶，继续按本 skill 交接 hop=<N+1>；未完成项为空或 hop≥<M> 则回报链路终止、不排程。",
  title = "接续 <任务名>（成本交接·hop<N>/<M>）",
  rrule = "DTSTART;TZID=Asia/Shanghai:<当前+10~20秒，Get-Date现算现用，≤30秒>\nRRULE:FREQ=DAILY;COUNT=1",
  target = "new_once"
)
```

- `DTSTART` 取当前本地时刻 + 约 10–20 秒（`Get-Date -Format 'yyyyMMddTHHmmss'` 现算现用，配 TZID=Asia/Shanghai，总计 ≤30 秒），必须严格晚于当前时间；禁止 +N 分钟/小时；`COUNT=1` 保证只投一次。
- `new_once` 让新会话继承本会话工作目录与 preset；不同会话的新会话用 `new`。
- 建后必调 `schedule_list` 核验写入成功；目录不存在先 `New-Item -Force` 创建，写入失败则回报错误并停止，不得空排程。
- **触发来源**：cost-meter 在累计等效成本越过 `autoHandoffAt` 档位时注入 P0 硬交接指令（每会话一次）。插件层**只能注入文本、无法替你写文档或排程**——收到指令必须真正执行上面两步，否则链路静默断掉且本会话不再提醒。这是当前宿主能力的天花板，靠 agent 遵守指令闭环。

## 五、收尾回报
给用户一行：交接文档绝对路径 + 新会话排程时刻 + 一句话任务状态（含当前验证状态与失败原因）。随后停手，不在本会话继续推进任务。

## 验证（本 skill 的实施验证，非交接动作本身）
- 静态：SKILL.md frontmatter 仅 name/description；正文五节标题齐全（上述一~五）。
- 载荷自检：dry-run 生成样例到 `$env:TEMP`，逐节 grep 九个标题存在。
- 排程参数自检：rrule 为 DTSTART+RRULE 两段、COUNT=1、target=new_once；真实投递不在本 skill 验证中执行（避免污染用户任务列表）。
