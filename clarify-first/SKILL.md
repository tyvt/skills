# 不确定先问（clarify-first）

核心：**凭据与外部地址类信息，猜错代价远高于问一次。** 缺这类信息时直接弹选项问用户，别去检索试错、别硬编一个默认值。

本 skill 只解决「哪些信息必须问用户」，不重复「怎么弹框」——那是 `decision-options` 的职责，提问一律走它的 `ask_user_question` 选项框。

## 必须问、禁止猜

出现下列信息缺口时，**先问再做**：

- **凭据**：账号、密码、token、api key、私钥/密钥、验证码渠道。
- **仓库**：仓库地址、分支名、目标 worktree、子模块归属。
- **部署/环境**：部署地址、环境名（测试/预发/生产）、端口、域名。
- **数据库/中间件**：连接串、库名、实例名、Redis/Kafka 地址。
- **外部服务**：第三方 API 的 URL、回调地址、AppId/Secret。
- 以及任何「无法从上下文或代码推断 + 猜错代价高于一次提问」的信息。

判据（同时满足才问）：① 没有它结果无法唯一推进；② 代码/配置/历史里确实拿不到；③ 猜错要返工或造成污染。

## 可以自答、不必问

别退化成事事都问。以下情况自己查、自己定，不要打扰用户：

- 能 `grep`/`read`/`glob` 得到的代码事实（方法名、字段、目录结构）。
- 能在现有配置文件、`.env`（已存在的）、系统参数里读到的默认值。
- 公开约定、语言/框架标准做法、明显唯一的实现路径。
- 用户上一轮已经明确给出过的信息（不要重复问）。

## 怎么问

- **一次问清**：同类缺口合并成一次 `ask_user_question`（多个 question，≤3），别挤牙膏式追问。
- 用 `decision-options` 的规范：2–4 个选项、推荐项置顶并标「（推荐）」、每个选项写清代价。
- 密码/token 这类敏感值让用户自己填（custom），不要给猜测选项。
- 正文说清「为什么需要它 / 缺它卡在哪」，选项框只放要用户拍板的内容。

## 正例

> 任务：连测试库跑迁移。
> 缺连接串 → 问：「测试库连接串用哪个？」选项：贴现有 .env 里的 / 我手填 / 先不跑。
> 缺库名 → 同一次 ask 里一并问。
> 不做的：去翻全仓找 .env、猜一个 localhost 默认值。

## 反例

- 猜仓库分支为 `main` 就往里提交 → 应该先问分支。
- 把某个测试密码硬编码进脚本试登录 → 应该问用户要可用账号。
- 反过来：为了找一个已存在的 `.vue` 文件也要弹框问路径 —— 这是该 grep 的代码事实，不该问。
