# 仓库安全

## Worktree

1. 会形成提交的代码改动放在独立 worktree，不直接改主工作区分支。文档和 agent 规则，或用户明确要求在主分支做时除外。
2. 开工先 `git worktree list`，再看已有 `*-wt-*` 的状态。每个任务新建自己的 worktree，不复用别人未提交的目录。
3. 用户说「在主分支做 / 别碰某个 worktree」时照做，不进入、不合并、不删除那个目录。
4. 验证通过后合并回原分支，再 `git worktree remove`。先提交推送，最后才回写禅道。

## 零填充

`D:\repository\skills` 及记忆快照提交前，暂存文件不得含大量 NUL。逐路径暂存，不用 `git add -A`。写完读回开头，确认是正常文本。已全零的文件先找副本恢复，不用占位内容冒充已修复。

## 提交顺序

1. 用具体路径暂存，核对 diff，不夹带无关文件、截图和凭据。
2. 最深层子模块先提交并在需要时推送，确认远程已有该提交，再更新父仓库 gitlink，直到最外层。
3. 不强制推送、不重置、不丢弃他人改动。失败时保留已完成结果并报告阻碍。
4. 只有相关仓库都已提交，且要求推送时均已与远程同步，才能说提交推送完成。仅要求提交时，不把未推送说成失败，也不要声称已推送。
