## 经验：慢 I/O 与快调用混在同一批 → 批处理封口失败

**归类**：工具调用卫生 / 批处理

**现象**：整轮报 `native call arrived after its batch was sealed`（批处理已封口后仍有 native call 到达）。

**根因**：把**慢速 I/O 操作**（读大文件、网络请求、截图、编译等）与**快速工具调用**放进同一个工具批（batch）一起并行。慢调用迟迟不返回，批在超时/封口后，后到的 native call 被拒，整轮报废。

**修复**：
1. **一慢一快分开批**——每个批次只放一个重 I/O 调用，并单独配置 `timeoutMs`。
2. 快调用（读小文件、grep 等）另起批次，不与重 I/O 并行。
3. 不要在一次并行调用里混入 read 大文件 / web_fetch / playwright 截图 / 构建等慢操作。

**验证**：拆批后同一任务不再出现封口报错，慢调用各自返回正常。
