### s0208 · Vue2 中直接调用 this.$options.data() 未绑定实例，导致 mixin/data 里 this.xxx 全是 undefined

🟡 踩坑 ｜ 验证于 苏房V3 ｜ 距代码最后改动 49 天，引用前请核对

现象：点击列表「重置」或开关弹窗时控制台报 `TypeError: this.getId is not a function`、`Property or method "elForm" is not defined on the instance`，并沿 zs-dialog → 业务弹窗 → zs-tabs 链路层层打断渲染。

根因：代码用 `this.$options.data()` 取默认值做重置。`$options.data` 是未经 Vue 包装的原始函数，裸调用时 `this` 不是组件实例，data() 内存活的 `this.getId()`、`this.patterns`、`this.$route` 等全部取到 undefined，于是生成一份残缺的 form/queryParams，后续模板与事件就报未定义。

做法：
1. 全部改为 `this.$options.data.call(this)`，集中在 `mixins/table.js` 的 resetQuery() 与 `mixins/dialogMixins.js` 的 reset()，一次修好所有继承这两个 mixin 的列表/弹窗；另有 11 处业务文件直接调用需逐一改。
2. data() 内不要调用 methods 取实例值，例如 `workBankId: this.getId()` 应移除，改为在 onOpen/onClose 里通过 getDefaultForm()/resetForm() 赋值。
3. 当 rules 依赖 data() 里的字段（如 this.patterns）时，把 rules 移到 computed，否则每次重置重跑 data() 都可能让校验规则失效。

注意：全库仍有 90+ 处 `$options.data()`，多为纯字面量 data（不引用 this），属低风险，可按需再批量替换。
