### x0019 · 登录图形验证码 E2E：扭曲算式图用 Tesseract+规则纠错不可靠，测试环境应返回 answer 或降难度

⚪ 套路 ｜ 验证于 2-0 ｜ 无 git 基线，引用前请自行核对

情况：login.spec.js 用 OCR 识别 `/code` 返回的 GIF 算式验证码自动登录，常 skip「OCR 未识别到有效验证码」或识别结果为 yee/CW 等无数字串。
为什么：验证码为 `data:image/gif;base64,'+res.data` 的纯数字运算图，但扭曲/噪声下 Tesseract 多轮 PSM+sharp 预处理仍常看不出算式；规则映射（O→0、字母转运算符等）对无数字输出无能为力。与「从 Vue 表单状态读验证码」的注册 E2E 不同，登录页若过早识别会在图片未渲染时拿到空图。
怎么做：测试环境优先让 `/code` 增加 `answer` 字段或专用 `/test/code`，E2E 有 answer 则直填并跳过 OCR；或测试环境换无扭曲简单算式图。OCR 仅作无 answer 时的兜底，并必须 wait 验证码 img/src 就绪后再截屏。稳定自动化登录不要依赖继续堆字母映射。

> 依据（摘）：会话 44f9e8a5 诉求 3–6 与最终结论：三字段未填、识别内容 yee/CW、用户指出图片未出现就识别；结论建议测试环境 answer + 前端预留 res.answer。

文件：`zhi2-web-admin/tests/e2e/login.spec.js`、`assets/views/login.vue`

### x0499 · [产品2.0] 真实接口 E2E 报「该业务未配置流程」是后端工作流缺失，不是前端/脚本问题

⚪ 套路 ｜ 验证于 产品2.0 ｜ 无 git 基线，引用前请自行核对

什么情况：企业注册真实接口全流程 E2E（saveCompanyRegister → saveLegalPersonInfo → 要件上传 → saveDraft 均通过）在最后 editAndSubmit 提交审核时返回 HTTP 500，业务消息「该业务未配置流程」，前端所有步骤（股东信息、协议勾选）都已完成。为什么：提交审核接口会按业务编码去 flowable 找已发布的审批流程，新业务或新环境没配置流程时后端直接 500，报错形态像代码故障但实际是环境配置缺失。怎么做：先从对应 api 文件（如 companyRegister.js）查出业务编码（040100=开发企业注册），登录管理端进入工作流/流程配置菜单（tool/workflow 相关），为该业务编码配置并发布审批流程，再重跑 npm run test:e2e:real-api-flow 验证；不要在前端或测试脚本侧找原因。

> 依据（摘）：会话 63a99906：Step1-Step4 保存全部通过，仅 editAndSubmit 500「该业务未配置流程」；结论明确为后端工作流未配置，需为业务编码 040100 配置并发布流程后复测。
