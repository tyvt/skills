1) 上传失败 → 检查小程序管理后台的 uploadFile 合法域名。uploadFile 与 request 是两套独立白名单，request 通了不代表 uploadFile 通（例如 https://www.ylzhwy.com:19002 必须单独加进 uploadFile）。

3) 其余情况 → 读 console 里 [ZsUploader] 前缀的诊断日志。

### x2112 · 苏住房C 小程序静态资源解析：分包迁移后按 SUBPACKAGE_STATIC_IMAGES 映射回退 pages_main，否则主包空态图 500

什么情况：苏住房C（zhi2-mobile-shimin）把 empty.png / apply-empty.png 等空态图从主包 src/static/images/ 迁入各分包（pages_credit / pages_main / pages_owner …，同源提交 17443e68）后，代码里仍写 images/empty.png，微信开发者工具报「Failed to load local image resource /static/images/empty.png … 500」，整块空态图空白。

为什么：静态地址统一走 resolveStaticUrl，它按当前页面所属分包推断真实目录。① 主包 Tab 页（pages/index/*）路由根是 pages，无法推断分包；② 未单独登记该图的分包（pages_guard、pages_my、page-query 等）也推不出来。两种情况都落到默认的 /static/images/，而主包里文件已被迁走，于是 500 而不是 404。

怎么做：在 src/utils/index.js 增加 SUBPACKAGE_STATIC_IMAGES 映射表（分包 → 该包内实有的图片名），resolveStaticUrl 改为「当前分包有该图就用当前分包，否则回退 pages_main/static/images/<file>」，因为 pages_main 一定存在且随主包一起加载。后续任何图片迁包，都要同步这张表和 scripts 下的迁移脚本，两者是同一份口径；排查这类报错先 git log 定位迁包提交，再核对映射表里有没有登记。
