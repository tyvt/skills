### 最终结论
## 原因说明

登录后多处硬编码 `router.push('/todo')`，并把 `DEFAULT_LANDING_PATH` 设为 `/todo`。但 **待办页路由来自 `listRouters` 动态注册**，真实 path 可能是 `/flowable/.../todo` 等，并不一定是 `/todo`。

更关键的是守卫里的竞态：

1. 第一次导航触发 `GetInfo` 后 **`roles` 已有值**，但 `GenerateRoutes` + `addRoute` 还没结束。  
2. 此时若再次进入守卫（例如登录立刻 `push('/todo')`），会走 `roles.length > 0` 分支直接 `next()`。  
3. 此时访问 `/todo` 尚未注册，命中通配符 `*` → `/404` → 提示「**页面未授权或不存在**」。

部分账号更容易中招，往往与网络慢、菜单较大、`GetInfo` 与 `listRouters` 耗时不一有关，看起来像「没授权」，本质是 **先跳落地页、后挂动态路由**。

## 修复要点

1. **`router/index.js`**：用 `needsDynamicRoutes()`（`roles` 为空 **或** `addRoutes` 为空）+ `loadDynamicRoutes` 单例 Promise，保证菜单注册完成后再 `next`。  
2. **`utils/defaultLanding.js`**：按菜单 component（`home/index`、`flowable/todo` 等）解析真实落地页，不再死磕 `/todo`。  
3. **登出 / 登录**：`RESET_PERMISSION` 清空 `addRoutes`，避免换账号或重登仍认为路由已加载。  
4. **`/`、`/index`**：在守卫里先加载动态路由再解析落地页，减少常量 `redirect: '/todo'` 抢先跳转。

请用之前会报错的账号再登录验证；若仍异常，在控制台看 `listRouters` 里待办菜单的 `path` / `component` 是否落在上述候选里，必要时可把实际 component 路径发我补进候选列表。
