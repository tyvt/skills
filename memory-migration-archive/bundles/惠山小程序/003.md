## 数据来源

一般表决进入 `participate.vue` 时，会调用 `selectVote`，请求接口 `GET /estate/AppDecision/{decisionId}`，并把返回的 `myOptionList` 原样映射到 store：

```319:337:d:\repository\惠山小程序\src\stores\vote.js
    async selectVote(payload) {
      const colors = ["green", "red", "yellow"]
      const res = await selectDecisionViewById(payload)
      const detail = res.data
      const data = {
        ...res.data,
        themName: detail.decisionTitle,
        projectName: detail.propertyProjectName,
        electionType: detail.decisionWay,
        myOptionList: detail.myOptionList?.map((e, i) => {
          return {
            color: colors[i],
            ...e,
            checked: false,
          }
        }) || [],
      }
      this.selectView = data
      return data
    },
```

`myOptionList` 里通常包含「同意」「不同意」「弃权」等项，每项带有 `optionId`、`optionName` 等字段，**弃权不是前端写死的**。

## 前端如何处理

在 `participate.vue` 里，接口返回的弃权项被**主动过滤掉**，不在页面上展示：

```19:21:d:\repository\惠山小程序\src\pages_vote\vote\participate.vue
        <button class="btn" :class="{ 'is-active': item.checked }"
          v-for="(item, index) in useVote.selectView?.myOptionList?.filter(e=>e.optionName!='弃权')" :key="index" @click="clickResult(item)">
          {{ item.optionName }}
```

也就是说：
- 数据：接口有返回弃权
- 展示：当前页面不显示弃权按钮
- 提交：`faceSuccess.vue` 只提交 `myOptionList` 里 `checked === true` 的项，用户目前无法在一般表决页选弃权

## 和其他表决类型的对比

| 表决类型 | 弃权来源 | 前端表现 |
|---------|---------|---------|
| **一般表决**（MAINTAIN） | `myOptionList` 接口字段 | 有数据但被 `filter` 隐藏 |
| **选项/排序表决**（OPTION/SORT） | 单独字段 `res.waiver` → `waiverList` | 底部有写死的「弃权」按钮，提交时用 `waiverList` |
| **图表统计** | `waiverWeight` / `waiverArea` 等接口字段 | 图例文字「弃权」是前端写死的 |

**结论**：一般表决的弃权选项（含 `optionId`）是接口 `selectDecisionViewById` 在 `myOptionList` 里返回的；前端没有单独造这个选项，但当前参与页把它过滤掉了，所以用户看不到、也选不了弃权。若需要支持弃权，应恢复展示或增加独立弃权入口，并用接口返回的 `optionId` 提交。
