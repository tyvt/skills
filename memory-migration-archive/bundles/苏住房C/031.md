### 最终结论
## 问题根因

忘记密码页使用共享组件 `PhoneForm.vue`。点击【获取验证码】后，`VerifyCode` 会先把按钮置为「发送中…」，并传入成功回调 `countDown` 和失败回调 `onFail`。

原 `sendCode` 存在两个问题：

1. **未处理失败回调**：`sendPhoneMessage` 失败（如图形验证码错误）时没有调用 `onFail`，`sending` 一直为 `true`，按钮卡在「发送中…」
2. **失败未刷新验证码**：校验失败后没有刷新图形验证码、也没有清空输入框

## 修复内容

### 1. `PhoneForm.vue`（忘记密码 / 修改密码共用）

- 为 `ImgCode` 增加 `ref`，失败时调用 `resetImageCode()` 刷新图片并清空输入
- `sendCode` 对齐 `phone.vue`、`cancellationForm.vue` 的模式：
  - 成功 → `countDown()`，进入倒计时
  - `sendPhoneMessage` 失败 → `resetImageCode()` + `onFail()`
  - 表单校验失败 → `onFail()`
- 补全 `form` 中 `imageCode`、`udid` 的初始字段

### 2. `VerifyCode/index.vue`（兜底）

- 用 `settle` 统一处理成功/失败，避免重复回调导致状态异常

## 关于短信发送逻辑

当前项目中**没有独立的图形验证码校验接口**。`/msg/sms/sendVerificationCode` 会携带 `code` + `udid`，由服务端在校验图形验证码通过后才发送短信。前端现在**仅在接口返回成功（code 200）时**才调用 `countDown()`，失败则立即恢复按钮，不会进入倒计时。

## 验收对照

| 场景 | 预期行为 |
|------|----------|
| 错误图形验证码 | Toast 提示错误 → 按钮恢复「获取验证码」→ 图形验证码刷新并清空 → 不进入倒计时 |
| 正确图形验证码 | 短信发送成功 → 按钮进入 60s 倒计时 |

该修复同时覆盖**忘记密码**（`CT_LOST_PASS`）和**修改密码验证**（`CT_UPDATE_PASS`）两个使用 `PhoneForm` 的页面。可在微信开发者工具中按上述步骤验证。
