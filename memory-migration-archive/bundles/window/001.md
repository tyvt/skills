## 建议按优先级处理

### 1. 立刻减负（最有效）

1. **关闭多余 Cursor 窗口**，只保留 1 个
2. **完全退出 Cursor**（托盘图标 → 退出，不要只关窗口）
3. 任务管理器确认没有残留 `Cursor.exe`，再重新打开
4. **不要以管理员身份运行** Cursor（右键 → 属性 → 兼容性 → 取消「以管理员身份运行」）

### 2. 避免在主目录工作

你现在的工作区是用户主目录，Cursor 会扫描大量无关文件（`AppData`、各种工具目录等），很容易卡。

- 用 **File → Open Folder** 只打开具体项目目录（如 `D:\repository\xxx`）
- 或新建项目到 `~/Projects/` 再打开

### 3. 清理缓存与历史

在 Cursor 中按 `Ctrl+Shift+P`，依次尝试：

- `Developer: Reload Window` — 轻量刷新
- `Cursor: Clear Agent History` — 清理 agent 历史（你有 198 条）
- 若仍卡：完全退出后，备份并删除 `%APPDATA%\Cursor\Cache` 和 `%APPDATA%\Cursor\CachedData`

### 4. 排查扩展与 MCP

日志里有 **Linter 超时** 和 **MCP 反复初始化**，说明扩展宿主可能被拖住：

- `Ctrl+Shift+X` → 暂时禁用非必要扩展（尤其 ESLint、Vue、Git 相关、leek-fund 等）
- **Cursor Settings → MCP** → 暂时关闭不用的 MCP（如 `tencentdb-memory` 当前连接失败也会重试）
- 用 `cursor . --disable-extensions` 启动测试是否还卡

### 5. 网络相关（若卡在 Agent/补全）

你 settings 里代理被注释掉了。若网络不稳定，可尝试取消注释：

```json
"http.proxy": "http://127.0.0.1:7890",
"http.proxySupport": "override",
"cursor.general.disableHttp2": true
```

（端口改成你实际代理端口）

### 6. 查看卡死时的具体原因

卡死时按 `Ctrl+Shift+P` → **Developer: Open Process Explorer**，看哪个进程 CPU/内存最高。

或打开日志目录：`%APPDATA%\Cursor\logs\` 最新文件夹里的 `main.log` / `renderer.log`，搜索 `blocked`、`timeout`、`unresponsive`。

## 推荐选择：**`manager`**

选 **`manager`**（Git Credential Manager），并勾选 **“Always use this from now on”**，然后点 **Select**。

### 各选项含义

| 选项 | 说明 |
|------|------|
| **`<no helper>`** | 不保存凭据，每次 `git push` / `git pull` 都可能要重新输入用户名和密码 |
| **`manager`** ✅ | **Git Credential Manager (GCM)**，当前 Windows 上最推荐的方式，支持 GitHub / GitLab / Azure DevOps 等，OAuth、2FA 也能正常处理 |
| **`wincred`** | 旧版 Windows 凭据助手，功能比 `manager` 弱，新项目一般不必选 |

### 为什么选 `manager`

- 凭据保存在 Windows 凭据管理器里，相对安全
- 配合 GitHub 等平台的浏览器登录 / token 流程更顺畅
- 支持双因素认证（2FA），`<no helper>` 和 `wincred` 在这方面体验较差

### 操作步骤

1. 选中 **`manager`**
2. 勾选 **“Always use this from now on”**（以后不再弹出此对话框）
3. 点击 **Select**

如果之后 push 时弹出 GitHub 登录窗口，按提示在浏览器里完成授权即可。
