### 最终结论
**不能完全不编码。** `backUrl` 里本身就有 `#`、`?`、`&`，如果不用任何编码直接拼进 query，会被截断或解析错乱，例如：

```
...&backUrl=https://wygl.wxwgzx.com:8989/szh5/sfb/#/pages/webview/home?realName=张三&certCode=xxx
                                                              ↑ 这里 # 后面的内容会丢失或被当成 hash
                                                                        ↑ 这里的 & 会被当成外层参数分隔符
```

所以 `backUrl` 必须做一层「安全包装」，常见只有两种：

| 方案 | 说明 |
|------|------|
| `encodeURIComponent` | 第三方需正确 `decodeURIComponent`，且对含 `#` 的 hash 路由容易出问题 |
| **Base64** | 不含特殊字符，第三方 `atob` 解码后直接用，更稳定 |

第三方重定向异常，多半是因为改成 `encodeURIComponent` 后，对方按 **Base64** 方式解析 `backUrl`。已改回 Base64 方案。

## 复制到小程序项目时

| 场景 | 是否需要注册 |
|------|-------------|
| 小程序里用 `web-view` 嵌入 H5（例如 `/pages/common/webView?url=xxx`） | **必须注册** |
| 小程序里已有自己的 web-view 容器页 | 不必再注册这个，把 `@message` 逻辑合并到现有页面即可 |

## 总结

- `webView.vue` 是**小程序原生页**，用来承载 `<web-view>` 加载 H5。
- uni-app / 微信小程序里，**所有页面都必须在 `pages.json` 注册**，否则 `navigateTo` 跳不过去。
- 若小程序端已有等价页面，只需合并 `@message` 处理，不必重复注册 `webView.vue`。

**`filePreview.vue` 是一定要注册的**；`webView.vue` 取决于你是否用它作为 H5 容器页。
