## H5 空白原因

「参与选举」页（`Participate.vue`）在 H5 里也会调用 `loginWithWxCode()`。但 H5 的特点是：

1. **Token 不持久化**（刷新或部分跳转后会话可能丢失）
2. **内页跳转 URL 不带 `code`**（从选举须知 → 参与选举属于 SPA 内跳转）
3. 此时 `loginWithWxCode()` 会因「缺少 code」直接失败，`loadElectionDetail` 不会执行，`showPage` 一直为 `false`，页面只剩背景图

表决详情页 `votedetail.vue` 在 H5 上是**直接加载数据、不走登录**，选举页之前没对齐这个逻辑。

## 修复内容

**1. `Participate.vue`** — H5 与小程序分开处理（与表决页一致）：

```javascript
// H5：直接加载选举数据（复用当前内存中的 token）
await loadElectionDetail(decisionId, options)

// 小程序：先登录再加载
loginWithWxCode().then(() => loadElectionDetail(...))
```

**2. `wxLogin.js`** — H5 防御性修复：URL 中 `code` 已用过，但内存里仍有有效 token 时，直接复用会话，不再报错。

## 原因分析

### 1. 跳转被接口阻塞（主要原因之一）
之前的逻辑是：

```
人脸认证成功 → 等 getOauthInfoByIdNumber → 等 initMyHouseInfo → 再跳转
```

只要 `getOauthInfoByIdNumber` 慢、超时或失败，用户就会一直停在实名页。接口超时配置是 **100 秒**，慢的时候体感就是“卡住了”。

### 2. `initMyHouseInfo` 本身不返回 Promise
```146:152:src/stores/user.js
    initMyHouseInfo(payload) {
      if (!this.idNumber) return;
      selectMyHouse({ idNumber: this.idNumber }).then((response) => {
        if (response.code == 200) {
          this.syncProjectInfoFromHouseList(response.rows)
        }
      })
    },
```
它不会 `return` Promise，房屋查询其实是“发了就算”，并不是可靠的等待点。真正卡住跳转的，主要是前面的 `getOauthInfoByIdNumber`。

### 3. E 证通返回时的竞态（“有时候”的关键）
从 E 证通人脸页返回时，小程序页面可能被销毁重建。如果：
- 回调刚执行了一半（已标记处理、已清掉 pending）
- 但还没来得及 `reLaunch` 跳转

新页面加载后就找不到 pending 结果，也不会再跳转，表现为**偶发**回不去。

## 已做的优化

刚才又做了一轮加固：

1. **先跳转，后刷数据** — 认证成功后立即 `reLaunch` 首页（或回到表决页），房屋信息在后台异步刷新，不再等接口。
2. **pending 结果延后清除** — 只有跳转流程真正完成后才清 pending，避免 E 证通返回时结果丢失。
3. **`onLoad` 提前消费 pending** — 页面重建时尽早处理认证结果，不只靠 `onShow` 600ms 延迟兜底。

| 现象 | 原因 |

| 等很久才跳转 | 接口慢，跳转被 `refreshUserAndHouse` 阻塞 |

| 偶尔回不去 | E 证通返回时页面重建 + pending 被提前清掉 |

所以：**接口慢会加重问题，但根因是跳转不该依赖接口完成。** 现在已改为“认证成功即跳转”，接口慢只影响房屋数据加载，不应再挡住回首页。可以在网络较差的环境下再试一次验证。
