### 最终结论
`dynamicForm.vue` 里只动了一处：**给 `mulInputBw`（权证号那种「苏（年份）+ 中间县区文案 + 号」）的外层容器加了 `:key`**。

```224:224:src/components/dynamicForm/dynamicForm.vue
        <div class="form-items rows mul-bw" v-if="!e.hide && e.formType == 'mulInputBw'" :key="(e.firProp || index) + '-' + (e.split || '')">
```

### 作用

新产权登记里，县区名称写在表单项配置的 **`split`** 上（例如从「涟水县不动产权第」改成「金湖县不动产权第」）。父组件用 `$set` 改 `split` 后，**数据已经变了**，但 Element UI 的 `el-input` 里 **`slot="prepend"` 那一段文字有时不会跟着重绘**，界面上仍显示旧的「涟水县」。

给这一块 DOM 绑一个依赖 **`split` 的 `key`**：一旦 `split` 变了，Vue 会**拆掉旧节点、新建一块**，中间的 prepend 文案就会和 `split` 一致。

### 和产权登记逻辑的关系

- **谁决定显示哪个县**：仍是 `propertyRegisterInfo.js` 里按协议号前两位改 `formData.*.split`，以及 `agreementNo` 的 `watch`。
- **`dynamicForm` 的 key**：只负责**把 `split` 的变更可靠地画到页面上**，属于展示层补丁，不改变业务规则。

### 影响范围

所有用到 `formType: 'mulInputBw'` 的页面都会走这段模板；只有 **`split` 变化**时才会因 key 变化而重挂载，平时输入年份、序号不受影响。
