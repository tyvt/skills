### 最终结论
`decision-policy` **不是后端接口返回的**，是前端父组件手动传给子组件的 **prop**，用来区分不同表决业务走哪套逻辑。

## 1. 定义位置

在子组件里声明为 `props`，默认值是 `'maintain'`：

```252:255:zhi1-web-admin/src/views/estate/decisionCommon/components/MaintainResultDialog.vue
    decisionPolicy: {
      type: String,
      default: 'maintain'
    },
```

常量定义在：

```7:11:zhi1-web-admin/src/views/estate/decisionCommon/config.js
export const DECISION_POLICY = {
  MAINTAIN: 'maintain',
  GENERAL: 'general',
  OPTION: 'option'
}
```

## 2. 谁传的（各详情页）

| 页面 | 传值方式 |
|------|----------|
| `ownerDecision/detail.vue` | `:decision-policy="isVote ? 'vote' : 'maintain'"` |
| `maintainDecision/detail.vue` | `decision-policy="maintain"` |
| `generalDecision/detail.vue` | `decision-policy="general"` |
| `optionDecision/detail.vue` | `decision-policy="option"` |
| `sortDecison/detail.vue` | `decision-policy="sort"` |

业委会选举这里：

```643:647:zhi1-web-admin/src/views/estate/ownerDecision/detail.vue
    <MaintainResultDialog
      :form="form"
      :decision-policy="isVote ? 'vote' : 'maintain'"
      :visible.sync="isMaintainResultDialogVisible"
      @go="afterSubmit"
```

其中 `isVote` 是根据**路由**算的，不是接口字段：

```787:789:zhi1-web-admin/src/views/estate/ownerDecision/detail.vue
    isVote() {
      return ['vote', 'supervisory'].includes(this.routeSegment)
    },
```

- 路由是 `vote` / `supervisory` → 传 `'vote'`（昆山选举逻辑）
- 否则 → 传 `'maintain'`（维修资金逻辑）

## 3. 列表页用法

列表页不传给弹窗，而是在 `data` 里自己设，用于调不同列表接口：

```javascript
// generalDecision/index.vue
decisionPolicy: DECISION_POLICY.GENERAL

// maintainDecision/index.vue  
decisionPolicy: DECISION_POLICY.MAINTAIN
```

再通过 `fetchDecisionList(this.decisionPolicy, ...)` 配合 `config.js` 里的 `decisionPolicyConfig` 决定查什么数据。

---

**总结：** `decision-policy` 是前端根据**当前模块/路由**写死的业务标识，不是接口 `return` 的。如果你在某个页面没传，就会走默认值 `'maintain'`。
