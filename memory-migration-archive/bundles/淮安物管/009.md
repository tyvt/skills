### 最终结论
问题已定位并修复。刷新后偶发「丢失数据」，根因是**初始化竞态**，不是接口真的没返回。

## 原因

1. **平台配置加载太晚**：`platformConfig`（含 `region`）在 `App.vue` 里异步请求，路由守卫**没有等待**它完成就渲染页面。
2. **区域数据未真正 await**：`saveAreaInfo`、`getRegions` 等 action **没有 return Promise**，`Promise.all` 实际上立刻结束，页面在区域字典就绪前就渲染了。
3. **computed 里弹错误**：`area.js`、`zs-region-select` 在 `platformConfig.region` 还是 `undefined` 时就调用 `msgError`，刷新时配置尚未加载就会误报「获取行政区域配置失败」。
4. **表格不随字典更新**：`provinceFormatter` 读的是 `store.state.common.allAreas`，字典晚到后表格不会自动重绘，行政区域/街道/社区列可能短暂显示编码或空白。

## 修复内容

| 文件 | 改动 |
|------|------|
| `router/index.js` | 新增 `ensureBaseDataLoaded()`，进入页面前等待平台配置 + 区域数据 |
| `store/modules/common.js` | action 正确 return Promise |
| `store/modules/app.js` | 增加 `platformConfigLoaded` 标志，并去重并发请求 |
| `mixins/area.js` | 移除 computed 中的 `msgError`，改为配置加载完成后再提示 |
| `zs-region-select.vue` | 同上，避免配置未就绪时误报 |
| `mixins/listMixins.js` | 区域字典加载后刷新表格，保证列名正确显示 |

刷新后应不再出现该错误提示，行政区域、街道、社区列也会稳定显示名称。若后端 `/system/platformConfig/getInfo` 本身失败，仍会在配置**确实加载失败**后提示一次，而不是误报。

请重新编译/刷新页面验证。若仍有问题，可在浏览器 Network 里看该接口是否偶发 4xx/5xx。
