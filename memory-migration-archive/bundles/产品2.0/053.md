### 最终结论
## 原因

`task.vue` 里对 **`formData.dataType`** 的监听，在**每次**触发时都会执行这段逻辑：

- 删除 `flowable:assignee` / `flowable:candidateUsers` / `flowable:candidateGroups`
- 并 `delete this.formData` 里对应字段  

面板初次加载时流程是：`data()` 里 `formData` 先是 `{}`（没有 `dataType`），`created()` 里再整份换成 XML 解析结果（含 `dataType: 'fixed'` 和 `candidateGroups`）。  
这时 **`dataType` 从 `undefined` 变成 `'fixed'`**，监听器照样跑了一遍「切换时清空」，**把刚解析出来的候选组从内存模型里删掉了**，所以详情再进来看回显是空的；若再点保存，还会把**已删过的模型**写回 XML，看起来像「保存了再打开就没了」。

`formData.userType` 那边用了 `if (oldVal)`，初次不会误删；只有 **`dataType`** 这段少了对「首次赋值」的判断。

## 修改

为 `formData.dataType` 增加 **`oldVal`**，并只在**用户真的改过指定方式**时清空人员相关字段：

- `oldVal` 为 `undefined` / `null` / `''` 视为初次绑定解析结果，**不清空**  
- 且要求 **`val !== oldVal`**，避免无意义的重复清空  

文件：`zhi2-web-admin/src/components/Process/components/nodePanel/task.vue`。

---

**说明**：若某次保存时已经带着「被清空后的画布」点过保存，库里那份 XML 里的候选组可能已被写没，需要在该流程上**重新选候选组并保存**一次才能恢复数据。之后用当前代码再打开详情，回显应正常。

    return {
      localForm: {}
    }
  },
  watch: {
    form: {
      immediate: true,
      handler(val) {

      }
    }
  },

- 不再直接对 `form` prop 做 `v-model` 绑定，警告会消失
- `localForm` 与父组件 `form` 仍是同一引用，父组件的校验、保存逻辑不受影响
- 父组件整体替换 `form` 时（如 `this.form = { ... }`），`watch` 会同步更新 `localForm`
