3. **人员 ID 类型不一致**  
   下拉选项的 `userId` 是字符串，模型里解析出的 `assignee` 可能是其他类型，导致回显为空。

### 最终结论
## 原因

`DetailTemplate` 里 **`type: 'image'`** 会先按 URL 取后缀，只有 `jpg/jpeg/png/gif/bmp/webp/svg` 才用 `<img>`；否则走「附件」分支，用 **`detail-link`** 当可点链接（避免把 PDF 等当图加载）。

你们接口里的地址往往是**无后缀**或**路径里不带 `.jpg` 这类后缀**（例如 `/profile/xxx`、带 token 的查询串），就会被当成非图片，于是看起来像「链接」而不是缩略图。

## 修改

1. 增加计算属性 **`stepPictureUrlList`**：从 `stepImages`（或对象里的 `url` 等字段）统一整理成**字符串 URL 数组**（与 `detailCallback` 里编辑态用的数据一致）。

2. 查看模式改为 **`type: 'images'`**：`DetailTemplate` 对 `images` 是直接用 `resolveServerAssetUrl` 拼 `<img>`，**不做后缀判断**，无后缀的站内图也能正常显示。

3. 没有图片时仍用 **`type: 'text'`** 显示占位，和原来空图时的 `-` 行为一致。

核心片段如下：

```92:108:d:\repository\产品2.0\zhi2-web-admin\src\views\dataProperty\recordProcess\components\recordProcessStepDialog.vue
    /** 查看模式用 images：无后缀的站内地址仍用 <img>；type: image 会按后缀判为非图而显示成链接 */
    stepPictureUrlList() {
      const raw = this.form.stepImages
      if (!raw) return []
      if (Array.isArray(raw)) {
        return raw
          .map((item) => {
            if (item == null) return ''
            if (typeof item === 'string') return item.trim()
            return String(item.url || item.fileSite || item.path || item.link || '').trim()
          })
          .filter(Boolean)
      }
      return String(raw)
        .split(',')
        .map((s) => s.trim())
        .filter(Boolean)
    },
```
