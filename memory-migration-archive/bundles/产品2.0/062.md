
所以 `prop="buildType"` → 自动变成 **`build_type`**，并请求：

```javascript
POST /system/dictData/listByType  { dictType: 'build_type' }
```

这就是为什么你在网络面板里看到 `build_type`，但全局搜索找不到这个字符串。

## 实现方式

对后端返回的 `/zhi2/...` 先去掉开头的 `/`，得到 `zhi2/...`，再用：

`new URL('zhi2/...', window.location.href)`

这样会按浏览器规则相对**当前地址**解析，例如：

| 当前页面 | 结果 |
|---------|------|
| `https://…/sz/login` | `https://…/sz/zhi2/…` |
| `https://…/sz/` | `https://…/sz/zhi2/…` |
| `http://localhost:5173/login` | `http://localhost:5173/zhi2/…`（仍指向站点根下的资源，与原先用 `origin + /zhi2` 一致） |

`env/.env` 里与 `VITE_APP_PUBLIC_PATH` 相关的注释已删掉。

## 部署时注意

若用户访问的是 **`https://…/sz`（没有尾斜杠）** 或 **`https://…/sz#/…`（`sz` 与 `#` 之间没有 `/`）**，浏览器会把最后一段当成「文件名」，相对解析可能仍落到根路径下的 `/zhi2`。建议在 Nginx 里把 `/sz` **301 到 `/sz/**`，并保证带 hash 的地址形如 **`/sz/#/login`**（`sz` 与 `#` 之间要有 `/`）。
