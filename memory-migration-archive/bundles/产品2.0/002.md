## 原因

`zs-table-column` 确实会根据内容动态计算列宽，但**只有未写 `width` 的列**才会走这套逻辑。

在 `guaranteeDepositAccount/index.vue` 里，「业务账号」列之前配置了 `width: 180`：

```160:163:d:\repository\产品2.0\zhi2-web-admin\src\components\zs-table-column\zs-table-column.vue
      if (this.explicitWidth != null) {
        // 页面写死了 width：原样透传，固定宽度
        return props
      }
```

一旦写了 `width`，组件会**原样透传固定宽度**，不再按内容算 `min-width`。业务账号是长数字串（如 `3205050000000000422`），180px 放不下，再加上 `showOverflowTooltip: true`，就会出现 `...` 省略。

## 已做修改

1. **`guaranteeDepositAccount/index.vue`**：已去掉「业务账号」列的 `width: 180`，改由 `zs-table-column` 按内容计算宽度。
2. **`guaranteeDeposit/components/index.vue`**：同样去掉了「业务申请编号」「业务账户」的 `width: 180`，避免同类问题。

## 使用规则（简要）

| 列配置 | 行为 |
|--------|------|
| 不写 `width` | 按表头 + 单元格内容算 `min-width`（弹性列） |
| 写了 `width` | 固定宽度，长文本会省略 |
| `type: 'index'` | 固定 80px |

刷新页面后，「业务账号」应能完整显示。若仍偏窄，可把鼠标悬停查看完整内容（tooltip）；动态宽度上限为 500px，一般账号长度足够。
