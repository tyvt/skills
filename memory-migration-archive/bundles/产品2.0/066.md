### 最终结论
**问题原因**

`zs-table-column` 原先通过 `!this.$scopedSlots.default` 判断是否为自动宽度列。角色管理页的「状态」列使用了自定义插槽（`el-switch`），因此被排除在自动宽度计算之外，**没有设置 `width` / `min-width`**。

在 `zs-table` 中 `fit: false` 时，未设宽度的列会吸收表格剩余空间。其他列有固定宽度，操作列 `fixed="right"`，中间「状态」列就会撑出大片空白，左侧数据列反而被压窄。

**修复方案**

调整了 `zs-table-column.vue` 的宽度逻辑：

1. **`isAutoWidthColumn`**：仅当列未显式设置 `width` / `min-width` 时启用自动宽度，不再因自定义插槽而跳过。
2. **`hasCustomSlot` + `getCustomSlotContentWidth`**：对插槽列按类型估算宽度（如 `type: 'custom'` 按 switch 约 60px），也支持 `slotWidth` 属性。
3. **`shouldMeasureRowData`**：文本类插槽（`text` / `link` / `dict` 等）仍按行数据测量；switch 等非文本插槽用固定宽度估算。

修复后，「状态」列会得到约 100px 的合理宽度，并参与 `zs-table` 的剩余宽度分配，空白区域会消失。

刷新角色管理页即可验证。若其他页面的自定义插槽列宽度仍不合适，可在列配置中加 `slotWidth`，或将 `type` 设为 `'custom'`（switch 类内容）。
