### 用户诉求 2
为什么知识库管理目录下面的知识库和引用记录菜单显示的是正确的呢？

### 最终结论
原因很简单：**两组子菜单的 `meta.icon` 配置不一样**，而当前缩进逻辑会受图标占位影响。

## 数据对比

| 菜单 | 父级 icon | 子菜单 icon |
|------|-----------|-------------|
| **工单管理** | `#` | `null`（无图标） |
| **知识库管理** | `#` | `#`（有图标） |

从 JSON 里可以看到：

```
workOrder 子项：icon = null  → 督办记录、报修工单等
knowledgeBase 子项：icon = '#' → 知识库、引用记录
```

## 为什么看起来一个对、一个不对

`RecursiveMenu.vue` 里，父级和子级的渲染方式不同：

**父级目录**（工单管理 / 知识库管理）：
- `paddingLeft = 24px`
- 有图标 → 占约 24px（16px 图标 + 8px 间距）
- **文字起始位置 ≈ 48px**

**子级叶子节点**：
- `paddingLeft = 父级 24 + 18 = 42px`
- 图标只在 `getMenuIcon(child)` 有值时才渲染：

```49:51:d:\repository\园区物管2.0\zhi2-web-admin\src\layout\components\Sidebar\RecursiveMenu.vue
                <span v-if="getMenuIcon(child)" class="menu-title--icon">
                  <svg-icon :name="getMenuIcon(child)" />
                </span>
```

因此：

| 子菜单 | paddingLeft | 图标占位 | 文字起始位置 | 相对父级 |
|--------|-------------|----------|--------------|----------|
| 督办记录（无 icon） | 42px | 0 | **42px** | 比父级文字还靠左 6px |
| 知识库（有 icon `#`） | 42px | ~24px | **66px** | 比父级文字靠右 18px |

「知识库」「引用记录」看起来缩进正确，是因为配置了 `icon: "#"`，图标区域**碰巧补上了**本应由缩进逻辑处理的宽度；「工单管理」下的子项没有 icon，就暴露出缩进计算的问题。

## 结论

这不是两套渲染逻辑，而是**同一套逻辑对不同数据产生了不同视觉效果**：

- 有 `icon` 的子菜单 → 缩进看起来正常  
- 无 `icon` 的子菜单 → 文字反而比父级更靠左，像没缩进

## 修复思路

1. **数据层**：给工单管理下的子菜单也配上 `icon: "#"`（临时方案，治标不治本）
2. **代码层（推荐）**：无论有没有图标，都保留等宽的图标占位，或统一用 `level` 计算 `paddingLeft`，不依赖子项是否带 icon

需要的话我可以直接改 `RecursiveMenu.vue`，让所有子菜单缩进表现一致。
