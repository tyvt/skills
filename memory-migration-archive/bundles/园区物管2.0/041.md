## 问题原因

页面加载时的调用顺序是：

1. `listMixins` 的 `init()` 立即调用 `getList()`（此时没有 `parentDeptId`）
2. 区域树异步加载完成后，默认选中节点并触发 `nodeClick`，再次调用 `getList()`

因此会先展示全量数据，再切换为按部门筛选的数据，出现闪烁。

## 解决方案

**1. `table.js`** — 使用 `RegionTreeLayout` 的页面在树状模式下延迟首次列表请求：

```javascript
shouldDeferListForRegionTree() {
  // 平铺模式 / B端终端 不延迟
  if (this.value) return false
  if (this.$store.state.user.terminalType === 'B') return false
  return !!(this.$options.components?.RegionTreeLayout)
}
```

**2. `regionTree.vue`** — 树加载完成后发出 `tree-ready` 事件（初始化时不再触发 `nodeClick`，避免重复请求）

**3. `RegionTreeLayout.vue`** — 监听 `tree-ready`，设置 `parentDeptId` 后再调用父页面的 `getList()`

**4. `complexChange/index.vue`** — 该页重写了 `init()`，同步加入延迟逻辑

## 效果

- 树状模式：等树加载并选中默认节点后，只请求一次带 `parentDeptId` 的接口
- 用户手动点击树节点：仍通过 `node-click` 正常刷新列表
- 平铺模式 / B 端：行为不变，立即请求列表
- 树数据为空：也会触发列表加载，避免一直 loading

所有使用 `RegionTreeLayout` 的页面无需单独修改即可生效。刷新页面后应不再出现先全量、再筛选的闪烁。
