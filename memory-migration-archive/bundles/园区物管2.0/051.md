## 原因分析

查看模式下「所属社区」通过 `contentInfo` 里的 `dictFormatter` 转译：

```532:535:zhi2-web-admin/src/views/property/complex/detail.vue

```

`dictFormatter`（`main.js`）会从 `this.communityOptions` 里按 `dictValue` 找名称：

```118:130:zhi2-web-admin/src/main.js
    dictFormatter(row, column, cellValue, index) {
      if (!cellValue) return ""
      const dictOptions = this[column.property + "Options"]
      // ...
      const option = dictOptions.find(e => e.dictValue == value)
      return option?.dictLabel || value
    },
```

而 `communityOptions` 来自 `area` mixin 的异步接口：

1. **`created` 阶段**：`getCommunityList()` **不带** `subdistrictCode`，会拉一份社区列表。
2. **`detailCallback` 阶段**：详情加载后又调用 `getCommunityList(this.form.subdistrict)`，按街道再拉一份。

两个请求**谁先返回不确定**，后返回的会**整表覆盖** `communityOptions`。若详情页先渲染、列表还是空的或已被无参请求覆盖，`dictFormatter` 就匹配不到，只能显示编码。

另外还有两点会加重问题：

- 本页原先 `mixins: [detailMixins, area]`，`detailMixins` 已包含 `area`，**重复挂载**导致 `created` 里无参 `getCommunityList` 可能执行两次，竞态更严重。
- 编码类型不一致（数字/字符串、首尾空格）时，`==` 匹配也可能失败。

同项目的 `complexChange/detail.vue` 里已有注释说明同类问题，并用了 `formatCommunityDisplay` + `loadCommunityOptionsForDetail` 处理。

## 已做修复

已按变更详情页的思路对齐修改：

1. 新增 `formatCommunityDisplay`：统一 `trim` 和类型比较。
2. 新增 `loadCommunityOptionsForDetail`：详情回调里**只按当前街道**拉社区列表并写入 `communityOptions`。
3. 查看模式改用 `formatCommunityDisplay`，不再依赖 `dictFormatter` 的 `communityOptions` 时序。
4. 去掉重复的 `area` mixin，减少 `created` 里的重复无参请求。

刷新详情页后，所属社区应能稳定显示名称。若仍偶发显示编码，可再排查接口返回的 `community` 是否与 `/system/community/list` 中 `communityCode` 一致。

## 问题原因

切换展示模式时调用了父组件的 `resetQuery()`，会把**所有**搜索条件（含表单字段）一并清空，导致：

1. 树状选中子节点后切到平铺，列表仍可能带着 `parentDeptId` 过滤，或查询条件被误重置  
2. 平铺切回树状时，树选中状态与列表数据不一致  
3. 表单查询条件在切换视图时被清掉，不符合「列表始终跟随查询条件」

## 修复方案

1. **切到平铺**：只清除 `parentDeptId`，保留表单查询条件，并重新请求列表（展示全部数据）  
2. **切到树状**：用 `pendingTreeDefaultReset` 强制树恢复默认（顶级选中、展开二级），树初始化后会触发 `nodeClick` 设置根节点并刷新列表  
3. **查询条件**：不再调用 `resetQuery()`，表单条件在两种视图间保持不变

核心逻辑：

```javascript
// 切平铺：仅清除部门树筛选
if (isFlat) {
  parent.queryParams.parentDeptId = undefined
  parent.queryParams.pageNum = 1
  parent.getList?.()
}

// 切树状：重置树为默认状态
if (!val) {
  this.pendingTreeDefaultReset = true
  this.treeRenderKey += 1
}
```

## 预期行为

| 操作 | 部门树 | 列表数据 |
|------|--------|----------|
| 树状选中子节点 | 选中对应节点 | 按该节点 + 表单条件过滤 |
| 切到平铺 | 隐藏 | 全部数据 + 保留表单条件 |
| 切回树状 | 顶级选中，展开二级 | 根节点范围 + 保留表单条件 |
| 表单查询/重置 | 不变 | 始终按当前表单条件查询 |

该组件被备案相关多个列表页共用（如 `complex`、`assetLeaseApply`、`assetsLeaseContractFiling` 等），上述修改会一并生效。可在物业管理区域备案页验证：树状选子节点 → 切平铺 → 切回树状，确认列表与树状态是否符合预期。
