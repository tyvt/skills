## 原因说明

Element UI 里 **`ElInput` 会在 `value`（v-model）变化时用 `dispatch` 触发 `el.form.change`**，这样带 `trigger: 'change'` 的表单项能在每次绑定值更新后重新校验。

`AmountInput` 之前**只在原生 `change`（以及清空）里** `dispatchToFormItem('el.form.change', …)`，和 `ElInput` 不一致；若规则是 **`change`**，或依赖“值已写回 form.model 再校验”，就容易出现**界面已填、校验仍认为必填**的情况。

另外 **`blur` 若与父组件更新同一帧内执行**，理论上也可能出现校验读到旧 model 的竞态，因此把 **`el.form.blur` 放到 `nextTick`** 里更稳妥。

## 修改说明

1. 在 **`numberValue` 的 watch** 里，在 `emit('input')` 之后 **`nextTick` 中 `dispatchToFormItem('el.form.change', value)`**，对齐 `ElInput` 在绑定值变化时通知 `ElFormItem` 的行为。  
2. **`handleBlur`**：先 `emit('blur')`，再在 **`nextTick` 里** `dispatchToFormItem('el.form.blur')` 并调用 `listeners.blur`。  
3. **`handleChange`**：去掉重复的 `el.form.change`（已由上面 `numberValue` 监听覆盖）。  
4. **`listeners`**：改为先判断存在再调用，避免在 **Vue 2.7** 等环境下 `listeners` 为 `undefined` 时报错。

若你那边仍有异常，请说明 **`el-form-item` 的 `rules`（含 `trigger`）** 和 **`v-model` 绑定的字段类型**（例如是否嵌套在 `el-table` 里），可以再针对性查一层。
