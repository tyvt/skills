### 无法 100% 一样的部分及原因

1. **原生控件由平台渲染**：参考站是 React 项目，使用原生 `input`/`textarea`；uni-app 会把它们渲染成 `uni-input`/`uni-number-box`，日期控件的原生日历图标、文本框缩放把手、占位符字色由浏览器与 uni-app 基础库决定，CSS 无法完全覆盖。
2. **演示数据不同**：参考站预置了 14 条静态工单，本应用从真实空态起步（数据来自 store 与本机存储），因此列表与计数不会逐字相同。
3. **参考站无对应页面**：记录详情页为本应用新增，视觉沿用同一套设计 token 延伸。
4. **微信小程序端不可能与 H5 逐像素一致**：小程序渲染层不是浏览器，字体回退、`svg` 支持（需转 base64）、滚动条与安全区处理都不同。两端共用同一份 `theme.css`，结构与样式同源，但必须单独在开发者工具与真机验收。

### 本轮修掉的两个真实缺陷

- **刷新后返回按钮失效**：页面栈被重建后浅层为 1，`navigateBack` 静默失败，导致历史入口不可达。改为栈深 >1 走 `navigateBack`，否则 `reLaunch` 到兜底页（见 [useBack.ts](<src/composables/useBack.ts>)）。
- **历史上拉加载不追加**：z-paging 页面滚动模式必须显式注册钩子，否则首屏 10 条后不再加载。已注册 `useZPaging`（注意它是**默认导出**，命名导入会导致 H5 构建失败）。
