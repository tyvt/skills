## 原因分析

你这条 URL 同时带了两个参数：

```
?requestCode=AR1842164271190656&wxOpenid=...  ← search 区（灵锡登录凭证）
#/pages/index/newHome?authCode=0               ← hash 区（绑房结果）
```

截图里绑房失败报 **401「无效的Token」**，根因是上一轮加的 **requestCode-token 缓存逻辑有 bug**：

```
onLaunch
  → userStore.clear()
  → 从 localStorage 恢复旧 token（requestCode 相同就认为有效）
  → ensureLingxiLogin 发现已有 token，跳过 lingXiLogin 接口
  → bindHouseByLingXi 带着过期/失效的旧 token 请求
  → 401 无效的Token
```

**`requestCode` 是一次性登录凭证**，每次从灵锡进入都应该用它换 **新 token**。URL 里已经有 `requestCode` 时，不能复用缓存里的旧 token。

---

## 关于 authCode=0

`authCode=0` 表示**第三方判定「未选择房屋」**，不是有效绑房码，不会走绑房接口，只会弹「您没有选择房屋」。

你另一张截图里 `authCode=169b4bad...` 是有效值，那次才会调 `bindHouseByLingXi`，然后因旧 token 报了 401。

---

## 已修复

调整了缓存使用策略：

| 场景 | 行为 |
|------|------|
| URL **有** `requestCode` | 强制调 `lingXiLogin` 换新 token（与 V1 一致） |
| URL **无** `requestCode`（纯绑房回跳） | 才用 localStorage 里的 requestCode-token 配对缓存 |
| 绑房 401 | 清除配对缓存，避免下次继续用坏 token |

请重新部署后再测一遍。正常流程应是：

1. 有 `requestCode` → 先登录拿到新 token
2. `authCode` 有效 → 再绑房
3. `authCode=0` → 只提示未选房屋，不绑房

如果还有问题，看 vConsole 里是否出现 `[灵锡登录]` 调用了 `lingXiLogin` 接口（而不是「跳过重新登录」）。
