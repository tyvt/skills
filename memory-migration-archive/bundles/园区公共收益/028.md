## 问题原因

编辑态详情页依赖 `detailMixins` 的 **sessionStorage 表单缓存**：

1. 进入编辑模式时，若 `sessionStorage` 中有该路由的缓存，会**直接恢复表单并跳过** `getDetail()` 接口调用。
2. `form` 的 deep watch 会在 `form !== originForm` 时写入缓存。
3. 详情接口返回后，**程序化赋值**（如 `getArea()` 计算使用权面积、子组件格式化金额等）会改变 `form`，但 `originForm` 已在 `detailCallback` 里提前同步，导致被误判为「用户已编辑」，写入 `sessionStorage`。
4. 刷新页面后读到这份「假缓存」，就不再请求详情接口。

## 修复方案

**1. `detailMixins.js`（根因修复）**
- 增加 `skipFormCache` 标志，详情加载期间不写入缓存。
- 重写 `getDetail()`，在 `detailCallback` 完成后通过 `syncOriginFormAfterLoad()` 在 `$nextTick` 中再同步 `originForm`，等子组件渲染完成后再解除缓存保护。
- 编辑模式从缓存恢复时，同步设置 `originForm`，并校验缓存中的主键 ID 与当前路由 ID 是否一致。

**2. `plot/detail.vue`**
- 在 `detailCallback` 中调用 `getArea()`，在同步 `originForm` 前完成面积计算。
- 移除手动的 `originForm` 赋值，改由 mixin 统一处理。
