### 行为说明

| 场景 | `menu-name` / `menu-path` | `data-id` |
|------|---------------------------|-----------|
| OperationBtnGroup 点「保存」（`formMode=edit`）触发的编辑接口 | ✅ | ✅ |
| 列表页 `handleDelete` 触发的删除接口 | ✅ | ❌ |
| 其他接口（查询、新增、详情等） | ❌ | ❌ |

### 实现方式

1. **`pageRequestContext.js`**  
   用 `pendingOperHeaders` 标记下一次请求类型（`edit` / `delete`），仅在匹配的 PUT / DELETE 请求上消费并附加对应请求头。

2. **`OperationBtnGroup/index.vue`**  
   点击保存且为编辑模式时，调用 `enableDetailSaveHeaders(primaryKey, form)` 打标。

3. **`mixins/table.js`**  
   `deleteRequest` 发起删除前调用 `enableListDeleteHeaders()` 打标。

4. **`mixins/form.js`**  
   - `editRequest` 仍会在提交前刷新 `form[primaryKey]`，保证 `data-id` 最新  
   - 校验失败时调用 `clearPendingOperHeaders()`，避免标记残留

5. **`request.js`**  
   拦截器改为只通过 `getOperRequestHeaders(config)` 附加请求头，不再对所有请求统一加。

6. **移除** `main.js` 里对 `form` 的全局 watch，以及 `zipdownload` 中的菜单请求头。

### 注意

- 新增保存（`formMode=add`）不会带这些请求头。  
- 删除只走 `table.js` 的 `deleteRequest` 才会带 `menu-name` / `menu-path`；若某列表页完全自定义删除逻辑且未走该路径，需要自行调用 `enableListDeleteHeaders()`。
