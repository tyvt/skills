## 排查结论

问题不是「项目里没有自动加载逻辑」，而是 **懒挂载（`v-if`）与 `@open` 生命周期不匹配**，导致 `getList()` 在首次打开时从未被调用。

## 问题根因（代码层面）

### 1. 父页面普遍使用 `v-if` + `:visible.sync` 懒创建弹窗

典型写法（缴款通知书、其他缴款等详情页）：

```362:364:d:\repository\苏州市房地产监测V3\zhi2-web-admin\src\views\supervision\deposit\other_record\detail.vue
    <ProjectDialog v-if="isProjectDialogVisible"
                   :visible.sync="isProjectDialogVisible"
                   @setData="setProject"/>
```

点击时 `isProjectDialogVisible = true` → 组件 **首次挂载时 `visible` 已是 `true`**。

### 2. 弹窗组件只在 `@open` 里调列表接口

`ProjectDialog`（`views/components` 与 `components/ProjectDialog` 两套实现逻辑一致）：

```71:73:d:\repository\苏州市房地产监测V3\zhi2-web-admin\src\views\components\ProjectDialog.vue
    onOpen() {
      this.getList()
    },
```

`RegulatoryAccountDialog`、`BuildingDialog`、`SelectDialog` 等同理，均 `@open="onOpen"` → `getList()`，**没有 `mounted` / `watch visible` 兜底**。

### 3. Element UI / `zs-dialog` 的行为

`zs-dialog` 只是把 `open` 事件转发给外层 handler：

```47:58:d:\repository\苏州市房地产监测V3\zhi2-web-admin\src\components\zs-dialog\zs-dialog.vue

      const listeners = { ...this.$listeners }
      const externalOpenHandler = listeners.open
      ...
      listeners.open = (...args) => {
        this.startAutoHeight()
        if (typeof externalOpenHandler === 'function') {
          externalOpenHandler.apply(this, args)
        }
      }
```

Element UI 的 `el-dialog` **`open` 仅在 `visible: false → true` 时触发**。  
`v-if` 首次挂载时已是 `visible=true`，**不会触发 `open`**，列表为空，只能点「搜索」手动调 `handleQuery()` → `getList()`。
