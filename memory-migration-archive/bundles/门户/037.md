## 原因

### 1. 「主题」未写 `width` / `min-width`

```14:14:d:\repository\门户\zhi2-web-admin\src\views\home\components\HomeTodoTable.vue
        <zs-table-column label="主题" prop="subject" show-overflow-tooltip />
```

会走 `zs-table-column` 的**按内容测宽**逻辑。

### 2. 用 `subject` 全文测算，上限 500px

组件会遍历当前页每一行的 `subject`，用 canvas 量最长一行的像素宽度，再加表头与内边距（`COLUMN_PADDING = 48`），得到 `min-width`，并限制在 **80～500** 之间：

```60:64:d:\repository\门户\zhi2-web-admin\src\components\zs-table-column\zs-table-column.vue
const MAX_COLUMN_WIDTH = 500
const MIN_COLUMN_WIDTH = 80
const COLUMN_PADDING = 48
/** 测算 min-width 低于此值时输出固定 width，避免短列参与弹性放大留白 */
const SHORT_COLUMN_FIX_THRESHOLD = 280
```

待办里的主题类似「监管项目编号：…，监管项目名称：…」，整段很长，测算结果很容易顶到 **500px** 的 `min-width`。

### 3. 短列被固定宽度，剩余空间更容易落在「主题」上

测算宽度 **&lt; 280px** 的列会改成固定 `width`，不再参与弹性分配；例如「任务名称」「状态」「发起人」等往往偏短。  
「主题」作为**弹性列**且 `min-width` 最大（常是 500），在 `el-table` 里就会显得特别宽，占掉中间大块区域。

### 4. 「序号」并不宽

`type="index"` 会固定 **80px**，不是截图里那列：

```65:68:d:\repository\门户\zhi2-web-admin\src\components\zs-table-column\zs-table-column.vue
const FIXED_TYPE_WIDTH = {
  index: 80,
  switch: 60,
  img: 80
}
```

## 若希望收窄「主题」

在不动全局组件的前提下，可在该列上任选一种方式：

1. **显式宽度**：例如 `min-width="200"` 或 `width="240"`（会覆盖自动测算）。
2. **限制测算上限**（组件已支持）：例如 `measure-max-width="240"`，长文案仍靠 `show-overflow-tooltip` 悬停查看。
3. **全局调小上限**：改 `MAX_COLUMN_WIDTH`（影响所有未指定宽度的 `zs-table-column`，需谨慎）。
