## 原因

报错 `Incompatible merge dtype, dtype('O') and dtype('O'), both sides must have numeric dtype` 来自 **pandas 的 `merge_asof`**，不是网络或 akshare 本身的问题。

在 `data_cache.py` 的 `merge_dataframes_by_date` 里，合并后把日期转成了 Python 的 `date` 对象：

```140:141:d:\repository\投资推送\data_cache.py
    combined[date_col] = combined["_merge_dt"].dt.date  # 旧代码
```

这样 `date` 列是 **object dtype**。当缓存过期、需要重新拉取并合并（创业板 PE/PB、美股价格等）时，内存里的数据仍是 object，而 `cyb_data.py` / `us_index_data.py` 里的 `merge_asof` 要求 **datetime64**，就会报错。

你日志里的 tqdm 进度条（19 步）是 akshare 在刷新缓存；当时 NDX/SPX/399006 尚未显示「就绪」，说明正是在并发刷新数据时触发了这个问题。若缓存已是当天数据，从 CSV 读入的日期是 datetime64，就不会出错——所以这个问题具有间歇性。

## 修复

已将 `merge_dataframes_by_date` 改为保留 **datetime64[ns]**，不再转成 `python date`：

```python
combined[date_col] = combined["_merge_dt"]
```

本地已验证：`merge_asof` 正常，`python report.py` 可完整跑通。

请重新运行 `python report.py` 确认。若仍失败，可先删除对应模块的缓存目录再试（例如 `data/cache/cyb/`、`data/cache/us/`）。
