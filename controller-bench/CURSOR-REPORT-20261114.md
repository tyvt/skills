- 原始数据：`results/bench-cursor-full.json`（350 行）。
- 评分：四维加权 tool .35 / comp .25 / route .25 / eff .15；format_error/网络错 记 0 分（有效口径）。

## 一、结论先行

1. **cursor 这批整体质量高于 codex/gpt（有效 0.637–0.820 vs 0.769–0.779 中上段）**，头部（grok-4.7@500k 0.820 / gpt-5.4-mini 0.809 / claude-opus-4-7 0.803）接近 workbuddy/kimi-k3.1-pro（0.849）。
2. **名目分骗人再次验证**：`gemini-4-hydrogen`（名目 0.820→有效 0.656）、`gpt-5.3-codex`（0.797→0.637）、`gpt-5.4-nano`（0.786→0.674）都是 5–7 题 JSON 污染（markdown 代码块包裹）被拉低。
3. **推荐组合**：`grok-4.7@500k`（综合最强）、`gpt-5.4-mini`（效率/扇出/对抗最强）、`claude-opus-4-7`（工具选择/路由最强）、`deepseek-v41-flash-1017`（最快、坏工具改道强）。
4. **明确不推荐**：`gpt-5.3-codex`（M1 0.48 最差 + 5 题 JSON 污染）、`gpt-5.4-nano`（T 对抗 0.42 极差 + 5 题污染）。

## 五、口径与局限

- 单轮计划产出评测，非端到端真实执行；M9 只测"是否规划用图像通道"，非真看图。
- 本批为**去重后** 10 个（同模型 @1m/@272k/@300k 变体只留一个：claude-opus-4-7 留 @1m、gpt-5.6-sol/terra 留 @272k）；初筛 66 个全量清单见 `results/screen-cursor.json`。
- cursor 为计费模型（per-token，多数 in=2e-6/out=6e-6，claude/gpt 更高），本记录仅作质量侧结论，成本需按 token 另算。
- 进池建议：grok-4.7@500k 作综合主力、gpt-5.4-mini 作效率档、claude-opus-4-7 作工具选择档、dsv41-flash-1017 作低延迟档；先影子对照再定。
