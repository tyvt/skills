# Summary
在苏住房G项目 zhi2-web-admin 中，首页「检查数据导航」点击「正常/逾期 N 份」本应进入整改通知列表，却跳到错误页或详情页。根因为后端下发的菜单里同一 meta.filePath 注册了多条路由（列表入口为静态 path，详情入口带 :tableid 动态段），ruoyi.js 的 find 只取第一条常命中详情入口。做法是将 filePath 反查统一改为 score-and-pick：filter 出所有同 filePath 路由，多于一条时优先选 path 中不含数字 (/\d/) 的那条，排序为静态优先→无动态段→路径更短，都相同才退回取第一条。该规则被 getCurrentRouterByFilePath、getRouterPathByFilePath、getRouterPathByFilePathNew、resolveRegisteredRoute 四处共用。来源会话 35ea5c25，基线 15e201a。

**user**: 【记忆类型】bug
【标题】同一 meta.filePath 命中多条菜单路由时，find 会挑中带 :tableid 动态段的详情入口，跳转落到详情而非列表
【内容】现象：首页「检查数据导航」点「正常：N 份 / 逾期：N 份」本该进整改通知列表，却跳到错误页（或侧栏异常/无数据），排查后确认跳转代码本身没问题。根因：后端下发的菜单里，同一个 `meta.filePath` 被注册了不止一条路由——列表入口 path 是静态串，详情入口则带数字动态段（如 `.../:tableid`）。`ruoyi.js` 里 `routes.find(r => r.meta?.filePath === filePath)` 只取第一条命中，顺序上常先命中详情入口，于是拿到一条带参数占位符的 path 直接 push。做法：把 filePath 反查统一改造成「score-and-pick」——先 `filter` 出所有 filePath 相同的路由；多于一条时优先选 path 中**不含数字**（`/\d/`）的那条；排序为 pareto（静态优先 → 无动态段 → 路径更短），都相同时才退回原来的「取第一条」以保证零行为变化。该规则被 `getCurrentRouterByFilePath`、`getRouterPathByFilePath`、`getRouterPathByFilePathNew`、`resolveRegisteredRoute` 四处共用，改一处即全站收敛。差异点：已知 #504 的根因是「flattenTree 后 filePath 变成 Layout/ParentView」，#703 是「动态段拼写错」，本条是第三个独立根因——filePath 本身合法但一 filePath 多路由，必须靠「静态优先」消歧。
【验证证据】会话 35ea5c25（基线 15e201a）：用户两轮反馈首页「检查数据导航」链接落错页，最终在 @/utils/ruoyi.js 里统一处理「同一 meta.filePath 对应多条路由」，规则为优先选 path 中不含数字(/\d/)的那条，都不含或都含时取第一条；影响 getCurrentRouterByFilePath / getRouterPathByFilePath / getRouterPathByFilePathNew / resolveRegisteredRoute。
