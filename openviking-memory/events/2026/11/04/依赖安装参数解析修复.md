**user**: 【记忆类型】bug
【标题】CI 报 404 '--no-fund@*' is not in this registry：install.mjs 把 npm 配置参数当包名，vite 找不到是它的连带现象
【内容】【什么情况】GitLab CI 里 `scripts/vite-build.mjs` 抛 `Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'vite' imported from .../zhi2-web-admin/scripts/vite-build.mjs`；改用仓库自己的安装脚本后仍报 `npm error code E404 404 Not Found - GET https://registry.npmjs.org/--no-fund`、`'--no-fund@*' is not in this registry`。
【为什么】门户是 **npm workspaces 单仓**（父仓 `zhi2-web-admin-h5-g-unlimited` + 子模块 `zhi2-web-admin`），依赖会被提升到仓库根目录的 `node_modules`；而父仓 `scripts/install.mjs` 在转发参数时把 `--no-audit`、`--no-fund` 这类 **npm 配置参数当成包名**拼进了 install 命令，npm 就去 registry 找名为 `--no-fund` 的包 → E404 → 安装失败 → 子模块目录里没有 `node_modules/vite` → 构建脚本 import 失败。两条报错是同一条因果链，不是两个独立问题。
【怎么做】① 先修参数解析：`install.mjs` 把 `--` 开头的配置参数与包名分开，只把包名传给 npm（父仓提交 `23a20f3`）；② 依赖必须在**仓库根目录**安装（`node scripts/install.mjs` 或 `PM=npm node scripts/install.mjs`），子模块目录里不会有完整 node_modules；③ vite 属 devDependencies，禁止 `npm install --omit=dev` / `--production`，否则 vite 必缺；④ 构建脚本改成「先在项目内找 vite，找不到再自动安装」（子模块提交 `e7df5c80e`），并用 `node scripts/ci-doctor.mjs` 做依赖就绪自检；⑤ 复现验证要在**干净工作区**（无 node_modules）里按 CI 的真实顺序跑三步：`npm run install-dependencies --no-audit --no-fund` → `npm run test` → `node scripts/ci-doctor.mjs`，全部 EXIT=0 才算修好（本批 added 841 packages，关键版本 vite 5.4.11 / @vitejs/plugin-vue2 2.3.1 / sass 1.96.0 / unocss 66.5.10 / rollup 4.46.2）。
【验证证据】会话 session-caa8ca81-1878-4f17-b818-2b2fb0210af9（基线 b6165db）用户诉求 1 贴出 CI 原文 `Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'vite'`；诉求 6 贴出 `npm error code E404 / 404 Not Found - GET https://registry.npmjs.org/--no-fund / '--no-fund@*' is not in this registry`；最终结论给出验证表（install-dependencies EXIT=0 added 841 packages、npm run test EXIT=0、ci-doctor EXIT=0）与两条修复提交（install.mjs 参数解析 23a20f3、子模块 vite 自动安装 e7df5c80e）。
