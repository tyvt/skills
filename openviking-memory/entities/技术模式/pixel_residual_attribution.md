# 像素级还原验收残差三档归因
逐像素还原后差异比对非零时，按亚像素抗锯齿、平台原生控件、演示数据差异三档归因；小程序端不可能与 H5 逐像素一致。

## 现象
- 按参考站做逐像素还原后差异仍非零：工作台 0/329160（一致），汛中巡检 101 像素（0.031%），汛前检查 1158 像素（0.352%）。
- 用户要求「UI 需要和这个100%一样，如果不行告诉我原因」。

## 根因
- 非零残差非布局偏差：4 倍放大核对差异全在输入框文字与步进器数字亚像素抗锯齿（字形字号字重位置一致，栅格化取整不同）。
- 结构性不可消除：原生控件由平台渲染（uni-input/uni-number-box 与参考站 React 原生控件不同）；演示数据不同（参考站预置 14 条静态工单，本应用空态起步）；参考站无对应页面（记录详情页为本应用新增）。

## 解决方案
- 差异归因按固定三档输出并给量化占比（差异像素÷总像素），不笼统说「基本一致」。
- 逐像素比对用固定视口 390×844 + 阈值 delta>24，差异蒙层图落 artifacts/diff/。
- 字体必须与参考站同源（同一份 Figma 托管 woff2：Noto Sans SC / Plus Jakarta Sans），不做本地替换。
- 微信小程序端与 H5 不可能逐像素一致，两端共用 theme.css 保证同源，但须分别开发者工具与真机验收。
- 交付时把「无法 100% 一致的部分及原因」单独成节并附量化证据。
