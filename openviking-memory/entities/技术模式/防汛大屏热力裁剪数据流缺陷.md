# 防汛大屏热力裁剪数据流缺陷
苏住房G 防汛大屏热力图按预警范围裁剪在验收场景下不生效的根因、白盒验证与实机结论。

## 问题根因
- `areaOptions` 用 `value: it.whole ? '' : String(it.code)`，本级汇总项「姑苏区（全区）」`it.whole` 为真，`value=''`。
- 父组件 `active-district="areaKey"`，`areaKey=''` 传给热力组件使 `activeDistrict=''`，裁剪逻辑走清空分支，热力外溢。
- 下拉中的街道 code（如 320508017）匹配不到 suzhou.json 的区级 feature（姑苏区 adcode 320508），选街道也不触发裁剪。
- 未发现市级预警事项（如「2026111001预警苏州」）的范围下拉含区级 code（320508）的可裁剪场景。

## 白盒验证
- 2026-11-27 浏览器白盒探针：把 `activeDistrict` 设为 `320508` 后手动调 `applyDistrictClip`，clipPath 正确生成，证明裁剪算法本身正确。
- 根因是数据流传值不匹配而非裁剪算法缺陷；返工应聚焦让汇总项携带区级 adcode。

## 环境与验证结论
- 2026-11-27 实机验证 localhost:8165（前端静态站，dist_root=`D:/repository/苏住房G/dist`），选「姑苏区（全区）」热力仍外溢，验收不通过、本跳不能提交/回写。
- dist 产物 `HeatMapPanel-C_qb1xHH.js`（11:58）晚于源码改动（11:56）且含 SVG path 生成代码；强刷禁缓存后 canvas 的 clipPath 仍全空，排除构建滞后与浏览器缓存。
- 浏览器会话名 `bug7043-e91695ee90b8` 固定，可跨会话接续操作。
- 验证码识别：captcha-recognizer 默认模型已下线，改用 magpie-vision 视觉网关；算术验证码如 `4*4=?` 填 16。

## 坐标空间错位（2026-11-27 hop9 新增根因）
- 白盒 clipPath 正确但实机仍外溢的根因之一：`chart.convertToPixel` 返回 canvas buffer 像素（913×716），而 `dom.style.clipPath` 作用于 CSS 元素按 CSS 像素（488×383）解释，坐标被放大约 1.871 倍，裁剪区完全错位到画布外。
- 实证：path 坐标 ÷1.871（起点 `M418.14 370.66…` → `M223.44 198.07`）后红色热力严格裁在姑苏区内、无径向溢出；只裁 heatmap 层（zlevel=2）即可，涟漪层 zlevel=3/4 无需单独裁。
- 复用教训：ECharts convertToPixel 结果与 CSS clip-path 之间必须做 buffer→CSS 尺寸换算；「多裁几层」无法解决坐标空间错位。
