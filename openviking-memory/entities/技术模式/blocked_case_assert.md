# 后端缺陷阻塞用例的受阻断言法
当 E2E 用例被后端缺陷阻塞时，改用「不写库的负向断言」记录真实行为与无副作用，而非造数据硬闯。

## 适用场景
- 报告编制 generate 步骤因后端缺陷 D7（企业列表恒空）走不通，报「尚未关联参与评价企业」
- 造数据绕过后端缺陷会掩盖真缺陷，直接跳过又丢失信息

## 受阻断言三件套
- 错误码不等 200 + 错误文案包含关键短语（如 msg 含「尚未关联参与评价企业」）
- 副作用指标前后不变（本次用「报告总数前后不变」），全程不写库、不造数据
- 用例分段：可跑通段写 A 段（全绿断言），受阻段写 B 段（受阻断言）

## 交付纪律
- 缺陷用编号（D7/R-01~R-04）写进 docs/std-evaluation/api-map-report.md，并说明「当前环境无法验证修复」
- 用例整体仍 exit 0（受阻断言预期内通过），但报告必须列出受阻段与缺陷编号，不能只报「全绿」
- 阻塞期间不发起会写库的用例（后端重启窗口 20–40s 请求会失败），等明确通知再继续
