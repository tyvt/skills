# 骨架屏仅覆盖动态区域改造（门户H5）
项目内的骨架屏统一改为只在图片与接口返回数据的动态区域显示，静态结构在加载期间保持可见。

## 改造范围与审计结论
- 2026-11-15 用户要求：项目里所有骨架屏改为只有图片或接口返回的数据部分才需要骨架屏，静态部分都不需要，缺失的动态区域要补齐。
- 改造前只有首页与“我的”页使用骨架屏，且这两页把静态分区标题、tab、菜单也一起隐藏；其他页面暂未使用骨架屏。
- 存在接口动态区但只做文字加载或直接留白的页面：门户列表、详情、个人资料、project-check 详情/记录页、查询分析页（多处动态图表与列表）。

## 实现约定
- 图片不新增通用组件 API，按图片原尺寸显示占位，在 load/error 时退出占位。
- 请求竞态由当前有效请求控制 loading：每页使用局部请求序号，开始新请求时递增，组件卸载时作废旧序号。
- 导航、表单结构、固定菜单标题、tab 等静态区域在 loading 期间必须保持可见。

## 验证与流程
- 计划经两轮修改后通过最终审核，审核 SHA-256 为 038a5722…dbba0e；若目标文件与现有脏文件重合，改动须限定到本计划的改动 hunk。
- E2E 预检（仓库已有 Playwright 测试脚本）条件未满足时不运行 Playwright，改用窄构建、类型检查、逐页人工审阅与 diff 核对作为替代验收，并在结果中明示。
- 审核附加要求：E2E 预检未通过时人工逐页点检后默认仍不合并。
