# 腾讯地图区划接入
园区物管2.0 台账地图按行政区划代码画区域边界并支持下钻时，接入腾讯位置服务行政区划接口及坐标字段语义陷阱。
## 问题背景
- 本地静态轮廓（YUANQU_AREA 常量）维护成本高且覆盖不了下钻层级。
- 后端下发 mapXCoordinate/mapYCoordinate 直接喂腾讯地图报「LatLng.lat 取值应在 [-90,90]」——后端 x 实为纬度（31.49）、y 为经度（120.31），与前端惯性相反。
## 解决方案
- 行政区划轮廓统一用腾讯 WebService「行政区划」接口（apis.map.qq.com/ws/district/v1/search），keyword 传 6 位 adcode，get_polygon=2 + max_offset=3000 取市/区县三级轮廓（乡镇级 get_polygon=3 需单独申请）。
- 浏览器直连跨域用 output=jsonp + callback 的 JSONP 拉取，key 与现有 GL 地图共用（需开通 WebServiceAPI）。
- polygon 返回一维 [lng,lat,...] 数组，转成 'lng,lat;...' 再画 MultiPolygon；坐标字段不能按 x/y 名义当经纬度，需按取值范围判别或与后端确认语义。
- 图层实例维护 districtLayers，重绘、boundaryAdcode 变化、beforeDestroy 时销毁防泄漏。
