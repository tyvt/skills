# 子模块多分支修复分发
在父仓库+子模块结构中，同一 bug 修复需分发到多条发布分支时，采用子模块 cherry-pick 单提交加父仓库逐个更新指针的模式。
## 适用场景
- 仓库为「父仓库 + zhi2-web-admin 子模块」结构
- 需同步修复到 develop/v2.6.1、develop/v2.6.2、develop/v2.6.2-yulin 等差异较大的发布分支
- 直接 merge 会带入大量不相干改动与冲突
## 做法
- 子模块源分支做一次修复提交，其余分支 cherry-pick 该单条提交各得新 SHA
- 父仓库每条分支做一次仅更新子模块指针的提交，指向对应子模块 SHA
- yulin 等业务分支需显式核对指针，若误指主干 SHA 须补提交修正
- 收尾报告三张表：子模块三分支提交号、父仓库三分支提交号与指针
## 注意事项
- env/.env 本地代理配置不应提交
- 避免全量合并，使用 cherry-pick 单条修复提交
