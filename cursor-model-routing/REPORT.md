## 一、结论先行（v3：三件收尾已完成，T1/T2/T3 可作正式输入）

0. **方法论收窄（重要）**：本报告为**单轮裸测**，不等于 agentic 多轮真实会话。下文任何"改判/分工"结论都标注了**复现次数**；未做 3 次复现的单次结果仅作方向参考，不足以直接进规则。
1. **Composer 2.5 有一个真实的间歇性失败模式（关键新发现）**：在部分 prompt 上会**坍缩成训练数据里的无关模板**（T3 复现 3 次中 1 次输出"前端面试题/React 全栈"模板；T7b 复杂文档题则整个跑成"第18/19/20轮"多轮对话自评）。**约 1/3 概率**，prompt 敏感、非确定性。而 **T1/T2 这类有界代码任务 3/3 稳定正确**。
2. **因此 T3 归 Grok 成立，但要写成"抗间歇幻觉"而不是"Composer 不会 T3"**：composer T3 复现 3 次 = 成功(correct)/成功(correct)/**跑题**；grok-4.7@256k T3 = 3/3 全部正确。→ 终审工作、需一次做对的调试类任务给 Grok，或对 composer 输出强制人工抽检。
3. **缓存行为实锤第0步**：grok-4.7@256k/500k 每轮注入 ~1300 token 系统前缀并 **85%+ 缓存命中**（cached_tokens 真实上报）；composer-2.5 多数 **0% 命中**。**注意**：grok-4.6/4.5 **未注入大前缀**（pt 仅 ~100），0% 命中是"无前缀可命中"，**不可与 4.7 系列并列比较缓存策略**（见第四节代际说明）。
4. **成本口径**：composer-2.5 的 **cost=0 是「Pro 池额度前提」**（走 Cursor 套餐额度，网关无 per-token 定价），**不是免费**；一旦超池或按 API 计则需重新核算。grok 全系按 API 真实计费（$2/百万 in、$6/百万 out）。35 格主矩阵里 4 款 grok 合计约 **$0.38**；赠额 6 模型整轮 **$0.065**。
5. **可落地修正**：T1/T2/T6（有界、可验证）→ Composer（便宜快、3/3 稳）；**T3 终端调试 + 需一次做对的高风险任务 → Grok**（抗间歇幻觉）；T5/T7 文档/设计 → **二者都不能免检**，Composer 覆盖度可能更高但**取舍不稳定 + 偶泄技术词**，Grok 更稳但更简（详见 4.2 双维度评分）。
6. **v3 三件收尾（见 §6bis）**：① grok T5/T7b 各 3 次复现——T5 稳定坐实"成品用 grok"、T7b 稳但 ~1/3 数值漂移须复核数字；② 跑题正则离线验证（**修正后：4 正类，旧正则漏检 composer T5rep3 → Recall 75%，补 runaway 模式后 100%/100%**；但只覆盖模板坍缩+文件转储两类，未穷尽串题，未命中≠on-task）；③ composer 池额度悬崖已量化：30d 白吃 95.5M tok/$0，同量走 grok 约 $462/月，悬崖=Cursor Pro 外部周额度墙（网关无读数，靠 unpriced/错误率监控）。**据此，T1/T2/T3 结论可先行；T5/T7b 与正则需按上述边界使用。**

## 四、主矩阵（主池 5 模型 × T1–T7 = 35 格）

### 4.0 代际不可混列（重要）
主池实为**两代模型**，不能当成同一档并列比较：
- **4.7 代**（`grok-4.7@256k`、`grok-4.7@500k`）：注入 ~1300 token 系统前缀、**83%+ 缓存命中**、context 256k/500k。这是当前主力。
- **4.5/4.6 代**：**未注入大前缀**（pt 仅 ~100）、**0% 缓存命中**（无前缀可命中，不代表缓存坏）、生成 token 明显更多（4.6 平均 20774 ct vs 4.7 的 ~12k），更慢更话痨。定位为**上一代对照/兜底**，不与 4.7 同档。

据此，**主选应在 composer-2.5 与 grok-4.7 之间决策**；4.5/4.6 仅作"4.7 不可用时"的兜底，且需注意成本更高。

#### 4.2.1 T5（设计/评审）质量拆两个维度
把"质量"拆成 **覆盖度**（边界/失败模式/回滚/隐私/隐藏风险是否齐全）与 **取舍质量**（篇幅是否克制、是否给出明确推荐、是否区分主次），各 1–5：

| 维度 | composer-2.5（3 次） | grok-4.7@256k |
|---|---|---|
| 覆盖度 | **高**：rep1/2/3 均覆盖全部五点 + 隐藏风险（"成功响应与真实副作用不一致"），5/5 | 高：五点齐全、隐藏风险到位，5/5 |
| 取舍质量 | **不稳定**：同一 prompt 三次产出 3.6k / 4.9k / **31.5k** 字符（rep3 膨胀成"2小时设计说明"），无明确主次 → 2–3/5 | **好**：凝练、主次分明、单一推荐 → 5/5 |
| 关键差异 | 覆盖有余、**克制不足**，越长越可能掺水/跑偏 | 覆盖够、克制好，适合直接交付 |

> 结论修正：T5 不能用"composer 质量更高"一句话概括——**composer 覆盖度高但取舍失控**（尤其长 prompt 会无限膨胀）；grok 覆盖与取舍都稳。**设计/评审要"成品"用 grok，要"素材穷举"用 composer**。

### 4.3 T3 / T7b 间歇性幻觉复现证据（题面要求）
对 T3 就 composer-2.5 与 grok-4.7@256k 各跑 **3 次**（同一 prompt、temperature=0.2），原始数据 `results/t3-repro.json`、`results/composer-repro.json`、`results/t7b.json`：

| 轮次 | composer-2.5 T3 | grok-4.7@256k T3 |
|---|---|---|
| rep1 | ✅ 正确（NODE_ENV/文件缺失/大小写，表格） | ✅ 正确 |
| rep2 | ✅ 正确 | ✅ 正确 |
| rep3 | ❌ **跑题**：输出"前端面试题 React+Node 全栈"模板 | ✅ 正确 |

- 同类坍缩在 **T7b（复杂高管简报）** 单次即出现：composer 先给了合格的简报，随后坍缩成"第 18 轮 / 第 19 轮 / 第 20 轮"的多轮对话自评模板；grok-4.7@256k 单次即正确且全约束达标。

1. 本测**单轮裸能力**，未覆盖多轮 agentic（工具反复调用、跨轮记忆、DSH 大 system prompt）——真实会话成本与表现可能不同。
