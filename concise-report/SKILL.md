# 收尾精简（要点式汇报）

目标：**只说要点，不丢信息，注意力负担最小。** 结论前置，过程压掉，证据留可追溯的一句话。

## 默认格式（极简，除非用户要求“展开”）

回答用 3 段，总量尽量 ≤10 行：

1. **结论**：一句话说清做成了什么 / 根因是什么 / 方案定了什么。
2. **关键改动或证据**：只列真正改动的文件:行号、关键命令、或一条决定性数据。不贴大段代码/日志/JSON。
3. **待定项**：需要用户拍板的用 `ask_user_question`（规则见 `decision-options`），正文不重复问；无待定项就不写这段。

## 硬约束

- **结论第一行给**，不要先铺垫“我做了什么、经过如何”。
- **禁止过程复述**：不复述“先读了 X 又改了 Y 再跑了 Z”的流水账，除非某步是结论依据，用一句话带过。
- **禁止客套与自我评价**：删“太好了/已为您/希望对你有帮助/如有问题随时说/以上是全部内容”这类空话。
- **不丢信息**：凡影响结论或后续动作的事实（改的文件、跑没跑测试、遗留风险、未执行项）必须留，只是压成一行。
- **未执行必写**：没跑的构建/测试要一行注明“未执行+原因”，不藏。
- **标题与列表按需**：多要点用小标题或 `- ` 列表；单点直接一句话，不要为了排版加标题。
- **用户说“展开/详细讲”**：再补过程、取舍、原理，此时不受极简约束。

## 反例 → 正例

反例（啰嗦）：

> 我已经仔细分析了这个问题，首先我查看了相关文件，然后定位到问题所在，接着进行了修改，修改完之后又跑了一遍验证，最后确认没问题。总的来说这次改动比较顺利，主要修改了 xxx 文件，希望这个结果对你有帮助，如果还有别的问题随时告诉我～

正例（精简）：

> **结论**：登录闪退已修复，根因是 token 为空时未判空。
> **改动**：`auth/login.ts:42` 加空值守卫；`npm test` 全绿（12 passed）。
> **待定**：是否一并提交？→ 已在选项框里问。

## 边界

- 纯分析/纯汇报无待定项时，正文写完即结束，不必强行弹选项。
- 精简≠省略风险提示：不可逆操作、遗留问题必须留一行。
- 与 `decision-options` 配合：决定走选项框，正文只解释不追问。
