- 改线上 H5 前，必须先用「线上构建产物 ↔ 本地构建产物」逐文件（文件名+字节内容）比对，确认线上源是哪个仓库+哪个分支+是否逐字节一致，不能靠目录名、README 或 CI 配置推测。
- 比对结论写成可交接溯源文档，结论必须落到「哪个仓库 + 哪个分支 + 是否逐字节一致」三件事上（含判错原因与线上权威还原命令）。
- 确认源头后再改代码并跑验证（bun run test / bun run typecheck / bun run test:e2e / bun run build:h5 与 build:mp-weixin），产物基址（如 /kpzxt/h5/）可整包覆盖线上目录。
- 改错仓库的提交要立刻 reset 掉，不让错误提交留在历史里。
- 交付汇报时明确写「改的是哪个仓库、线上产物路径与基址」，避免下一棒又去猜。
- 本轮核心价值不是改了几行代码，而是把「线上到底是哪份代码」钉死：以后任何差异一比对就知道，别再靠猜目录。
