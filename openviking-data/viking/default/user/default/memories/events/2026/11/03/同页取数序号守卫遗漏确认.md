【标题】同页多个独立取数只给「按区域的主数据」加 fetchSeq 防竞态是半边工程：Tab 切换类列表同样要序号守卫
【内容】什么情况：index-v2.vue 里 loadKeyData / loadCheckData 已有 fetchSeq 丢弃过期响应的模式，但 loadBenefitData / loadRepairData / loadStudyList 没有。用户在「不要区域参数」的改造里指出这一点后，review 结论是合格但留了一条 MEDIUM：快速切学习园地 Tab 时，慢的旧请求可能覆盖新 Tab 结果。

为什么：Vue2 页面里多个并发请求共用一个列表 state，响应到达顺序不等于发出顺序。区域切换类请求有人管（seq 递增 + 比对后丢弃），Tab 切换类请求同样存在「旧响应后到」的可能，尤其是首屏 loadAll() 与用户手动切 Tab 同时发生时。

怎么做：凡是「同一 state + 用户可快速切换的筛选条件（Tab / 区域 / 搜索词）」产生的请求，都要走同一个 seq 守卫：发请求前 const seq = ++this.xxxSeq，回调里 if (seq !== this.xxxSeq) return; 再写 state。首屏只加载一次、之后不随交互重拉的（benefit / repair）可以放宽，但要在代码注释里写明「只在 created 加载一次，故不加 seq」，避免下一个人误判成漏写。

已知清单 #450 讲的是「按字段值触发远端校验」的单字段场景，本条补充的是「同一页面多模块取数时 seq 守卫的覆盖边界与注释约定」，两者互补不重复。
【验证证据】会话 09f68d49 的 review 明确指出 loadBenefitData / loadRepairData / loadStudyList（index-v2.vue:266-327）缺少与 loadKeyData/loadCheckData 一致的 fetchSeq，建议至少给 loadStudyList 补 seq 模式；用户侧需求本身也强调「切换区域时不要调这些接口」。
