**user**: 【记忆类型】bug
【标题】字典配置不可靠的「启用状态/单据状态」列：字典列 + 遗留自定义插槽会静默覆盖字典渲染
【内容】场景：`views/system/regionBankAuth/index.vue` 要求把「启用状态」列改成字典 `is_enable`（与下方「单据状态」列的 `biz_state` 写法一致）。改法是把列配置改成 `{ type: 'dict', label: '启用状态', prop: 'enableStatus', dictUrl: 'is_enable' }`——这是版本基线 864b409 时代的成功路径，不适用 later 版本（那版字典列还要求显式 `:options` 与 dict-url 三件套；但本机苏住房G 后端字典只下发 `is_enable`/`biz_state`，前端拿不到 options 时，不要按 later 版本的口径强加 options，改为先在页面把真实值映射好再交给列）。

真正容易被漏掉的是覆盖：模板里原有的 `prop="enableStatus"` 自定义插槽（区级显示开关、其他层级显示「可用/不可用」）优先级高于字典默认渲染，只改列配置界面上看起来毫无变化。所以要改字典化时必须同步决定插槽去留：要么删掉/收窄插槽，要么只在插槽内部用 `dictUrl` 的 `getDictLabel` 兜底，不能两套渲染并存。

验收：改完后检查每一层级（区/街道）的值是否都由字典渲染，出现「部分行是中文、部分行是开关」即为插槽残留。
【验证证据】会话 14522f3a（baseline 864b409）：用户「@regionBankAuth/index.vue:139 改为字典,is_enable」；结论改为 `{ type:'dict', dictUrl:'is_enable' }` 并明确提示「模板第 34–43 行仍有 enableStatus 的自定义插槽，会覆盖字典默认渲染」。
