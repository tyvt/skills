# 多分支并行合并丢代码的定位与恢复流程
develop/v2.6.2 等目标分支上工单、知识库代码整块消失时，需按目录比对差异文件数，再单提交恢复。

## 定位方法
- 先确认子模块 zhi2-web-admin 在目标分支是否检出完整，避免稀疏检出误判文件不存在
- 按业务目录（src/views 下 workOrder、知识库对应目录）统计两分支文件数差集，差集非空即确认丢失
- 在功能分支上 git log -- <目录> 找到引入功能的提交，确认被哪次合并丢掉

## 恢复方法
- 在目标分支单独做「恢复合并时丢失的 X 相关代码」提交，只包含差集文件，不混其它改动
- 恢复体量常见 20+ 文件、数千行，提交前让 pre-commit 的 eslint 跑通

## 父仓与协作注意
- 产品2.0 是父仓、zhi2-web-admin 是子模块，切错分支时子模块指针挂未提交变更
- 同步修复须切到同一分支再更新子模块引用并提交，否则父仓记另一条分支 SHA
- 并行多 AI 会话共用工作区时，提交前 git status 核对自己的文件，别提交别人改动
- 参考会话 03553771：子模块提交 5af48d12b，23 文件 +5119 行，代码基线 57109f9
