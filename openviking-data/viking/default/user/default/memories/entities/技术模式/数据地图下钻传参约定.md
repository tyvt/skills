# 数据地图下钻传参约定
园区物管2.0 的 benefit/statisticsMap 数据地图页按行政区划/街道下钻查数据时，接口传参的约定规则。
## 问题背景
- 多种交互路径（默认进入、点击区县、滚轮放大到街道层级、点击街道）导致参数规则不明确，容易漏传或多传导致查全量/查空。
- 原有控制「是否传 regionCode」的 usePlatformRegionScope 开关逻辑易混乱。
## 传参规则
- regionCode 始终传递：未点击区县时传 store 的 platformRegionCode，点击区县后传该区县编码，下钻后覆盖并删除 usePlatformRegionScope 开关。
- subDistrictCode 仅在点击某个街道时才传，滚轮放大到物业管理区域层级只传 regionCode。
- 区县/街道聚合接口 selectAreaComplexNumList 始终带 regionCode，用 dimension 参数区分层级（1=区县，2=街道），不额外传街道编码。
## 工程约束
- 新增地图类下钻页面时按此约定组织参数。
- 涉及文件：src/views/benefit/statisticsMap/index.vue、src/views/benefit/statisticsMap/components/map.vue。
- 所属项目：园区物管2.0；来源会话：3b8b0061-bdbb-4225-9dd0-39f6ec21e376；代码基线：6a4835a08。
