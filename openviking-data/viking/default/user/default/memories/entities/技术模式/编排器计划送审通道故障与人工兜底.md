# 编排器计划送审通道故障与人工兜底
bug6909 链路上编排器 plan_review / plan_path 通道持续失败（invalid review state），四种形态全试无效后改由用户人工确认计划。

## 故障表现
- hop1 对同一计划文件已送审 6 次失败；2026-11-24 本会话再试 3 次仍失败，累计 9 次
- 四种换形态均无效：plan_path 通道、plan 正文直送、frontmatter 引号规范化（session_id 补引号）、复制为 v2 新文件名换取全新 review state
- frontmatter 字段检查无异常，判断为编排器残留损坏的 review state，通道确认故障

## 兜底做法
- 按交接文档预案「>2 次失败停下记录原因，征询用户后继续」，停止重试并向用户征询裁决
- 用户确认以人工确认代替模型审核，回填 frontmatter 后直接开工实施
- 同类失败可优先走人工确认通道，避免反复消耗在送审重试上
