# 顶栏返回首页：始终回门户，按门户登录态分流（禅道 5983 最终口径）
顶栏 Navbar「返回首页」的落点由门户侧决定，9002 管理端只负责整页跳门户，不猜登录态、也不留在管理端。2026-11-09 用户澄清后的口径。

## 最终口径
- 始终整页回到门户 9001：读参数配置 sys.portal.index.url（指向门户 /#/index），window.location.replace 过去
- 门户有登录记录（sessionStorage Admin-Token）→ 门户路由放行 /index，落到「对内首页」
- 门户无登录记录 → 门户路由把 /index 导向「对外首页」/UnifiedLogin，且不带 redirect、不强制登录
- 两端 token 各自存在 sessionStorage，9002 读不到 9001；同标签页 replace 后门户自己那份记录仍在，因此由门户判断

## 涉及代码
- 9002：src/layout/components/Navbar.vue 的 goHome() / redirectToPortal() / pushDefaultIndex()；配置缺失时兜底回管理端落地页，NavigationDuplicated 时 reload 给可见反馈（真实落地页是 /todo，不能只判断 hash 含 /index）
- 门户：src/router/index.js 的 handleUnauthenticatedRoutes；对 /index 与 / 走 /UnifiedLogin 不拼 ?redirect=，其它受保护路由仍保留 redirect 以免深链登录丢失目标页
- 注册单页「原路返回门户」是另一套约定（禅道 5995，src/utils/portalBack.js），不要混用

## 变更与教训
- 2026-11-02 6cc5eba2c 误改成站内回管理端首页（需求理解错误）；2026-11-03 01861fe87 恢复跳门户但未登录仍被带进 ?redirect= 登录流程
- 2026-11-09 一度按「留在管理端」修复并回写禅道，用户澄清后作废、重新激活；最终两端同时修改并推送
- 教训：不要按 bug 标题里的「不应该直接退出系统」推断成「留在管理端」，正确诉求是「回门户但别被登出」；跨端口登录态不能靠管理端猜
