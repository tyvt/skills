# 投资推送：实盘报告与推送信号职责分叉
`report.py` 为本地统一报告入口（全指数/全模块查看，不推送）；`push.py` 经 Server酱等只推送当日有买卖信号的指数，两者职责刻意分叉。

## 职责分工
- `report.py`：本地统一报告入口，展示全指数/全模块，不做推送
- `push.py`：经 Server酱等渠道，仅推送当日有买卖信号的指数
- `push.py` 生成报告后经 `signal_format.filter_trade_signal_sections` 过滤，仅当某指数 `signal_short` 为「买入」或「波段卖出」（`section_has_trade_signal`）才走微信推送
- 全部为「观望」时日志为「今日无买卖信号，跳过推送」并正常退出，不会打完整报告、也不会调微信接口

## 阈值与信号来源
- 阈值与指数列表以 `config.py` 为准，运行时可由 `push.env` 覆盖
- 各指数信号在 `*_signal.py` + `price_position.py` 等模块实现，勿在回测脚本里硬编码阈值

## 推送跳过与排障
- 排查「推送没成功」应先读 `logs/push.log` 该行，再用 `python report.py` 看当日全量估值与达标项
- 价格上涨突破价格位置买入上限后信号会从买入变观望（例：中证1000 由 7065 涨至约 7475，突破 120 日低点上限与 1 年区间上限）
- 验证证据：8/4–8/5 日志均为跳过推送；8/3 中证1000 买入时推送成功
