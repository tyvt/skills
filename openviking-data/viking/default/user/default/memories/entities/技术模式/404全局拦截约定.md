# 404全局拦截约定
产品2.0 后台路由在 beforeEach 中拦截 to.path==='/404'，改为统一消息提醒，不再渲染 404 页。

## 问题现象
- 原通配路由 { path: '*', redirect: '/404' } 处理未匹配地址，用户要求不进 404 页。
- 显式 push('/404') 场景在守卫里只判断通配会漏掉。
- 直接渲染 404 页体验差且丢失来源上下文。

## 根因
- 通配重定向发生在 beforeEach 之后，仅在守卫判断通配会漏掉显式跳转。
- 渲染 404 页丢失来源上下文。

## 解决方案
- 在 router.beforeEach 开头（handleExternalToken 之后）统一拦截 to.path === '/404'。
- 有上一跳有效匹配时 next({ path: from.fullPath, replace: true }) 留原页并抹掉无效历史。
- 首次打开即非法地址时 next({ path: '/index', replace: true }) 回首页并 Message.warning 提示。
- /404 路由配置保留不删，实际不再渲染；拦截需放在登录态处理之后。
