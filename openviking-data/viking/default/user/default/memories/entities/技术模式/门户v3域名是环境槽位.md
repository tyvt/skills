# 门户v3域名是环境槽位
用户贴出的 unlimited.g.h5...v3 域名里的 v3 是部署环境槽位/网关版本，并非独立代码分支。
## 根因与对应关系
- 域名 http://unlimited.g.h5.admin.web.v3.fangdichan.shiqu.suzhou.dev.zhi.com 对应父仓远程 zhi2-web-admin-h5-g-unlimited
- 父仓仅有 develop/v2.6.2-portal 一个远端分支，v3 是部署环境槽位/网关版本（.env 中 API 前缀为 /api/v3.0）
- 子模块里的 2.6.2-portal-v3（落后 120 提交旧分叉）与 develop/v3.0.0（无对应父仓分支）均非该环境来源
## 排查与处理要点
- 排查环境问题先对齐「域名 → 父仓远程 → 分支」：git remote -v + git branch -r 看清父仓远端分支
- 仅将 develop/v2.6.2-portal 部署到 v3 环境槽位即可生效，远程主机发布走 CI/发布流水线
- 改完对目标环境强制刷新（静态资源带 hash，index 不缓存）
- 同分支可能有别人并发生成提交，本批父仓指针最终指向含自身修复的较新提交 c1791b7ae（含 cf0005ff7）
