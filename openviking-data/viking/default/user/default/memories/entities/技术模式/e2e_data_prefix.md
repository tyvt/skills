# E2E 测试数据统一前缀与清理规范
E2E 造的测试数据统一加业务前缀命名，接口删不掉的已备案数据按主键走 DB 批量清理。

## 问题背景
- 跑完报告编制/区域报告 E2E 后库里留两条接口删不掉的已备案数据（业务状态已备案不允许删）
- 本次残留：报告编制E2E1031104628改（主键 2116361154115497985）、区域报告E2E1031104816（主键 2116361603476451330）
- 已备案单据业务上不可删除，接口层清理路径无效；随机名/真实业务名既认不出又不敢删

## 命名与清理做法
- 造数据强制加统一前缀（如 E2E + 时间戳 + 模块名），一眼可辨、可按前缀批量筛
- 等级与变更用例优先复用已备案样本，使 DB 残留恒为 1 条已备案样本 + 1 条终审变更日志，不随跑次增长（会话 00e04b09）
- 交付时列出残留数据名称 + 主键 + 原因，不能只说「有残留」
- 清理走 DB 直删（mcp_gateway 的 dbx 工具），因为接口删不掉
- 用例结束前把可删的待提交数据在用例里删干净，只留业务不可删的待 DB 清理
- 临时探针脚本（如 tools/probe-local-backend.cjs）用完即删，不留仓库当噪声
