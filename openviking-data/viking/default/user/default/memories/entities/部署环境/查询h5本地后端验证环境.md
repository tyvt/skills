# 查询H5本地后端验证环境
在 Windows 本机启动 evaluation 后端服务、改 nginx 路由直连本地，用来实机验证后端改动的临时验证环境。

## 拓扑与路由
- 前端 API 常量 `/v2.0/evaluation/h5`，startCheck 实际请求 `/api/v2.0/evaluation/h5/check/start`；本地后端 controller 无 context-path。
- nginx 8095 的 `location /api/` 原样转发远程测试服网关；本地验证时把 `/api/v2.0/evaluation/` 精确转到 `localhost:9608`，其余接口仍走远程网关以保留登录。
- 后端自身无 JWT 鉴权 filter，鉴权在网关层，故直连 evaluation 服务不校验 token（curl 免 token 返回 200）。
- 打包产物落 `$env:TEMP`；后端服务端口 9608。

## 启动要点
- `bootstrap.yml` 写死 `spring.profiles.active=dev`；可用 JVM 参数覆盖 profile，并加 `--spring.cloud.nacos.discovery.enabled=false` 避免注册污染测试服。
- nacos：dev `192.168.1.71:8848`（namespace `suzhou-shiqu-suzhufang-v2`）、test `192.168.1.72`，二者均可达；nacos 配置 API 直连返回 403（需鉴权，无法直接探测）。
- 必须加 `-Dfile.encoding=UTF-8`：nacos 配置含中文，Windows 默认 GBK 解析报 `MalformedInputException: Input length = 1`，datasource 配置全部拉取失败（`dynamic-datasource can not find primary datasource`）。
- dev 库无「已备案物业服务等级」数据（`serviceGrade/finishedComplexPage` 无论有无关键词恒 total=0），需 test profile 才与测试服数据同源。
- 2026-11-24：后台 `mvn` 打包 EXIT=0，新 jar 15:36 生成（含 grade 透传改动）；dev profile 首次成功启动 PID 9884，切换 test profile 后 PID 6508 启动成功、9608 LISTEN。
- 改 nginx 配置须在 `D:\nginx` 下执行 `nginx -t` 与 reload；用 `[System.IO.File]::WriteAllText` 加 UTF8 会写入 BOM 导致 nginx 解析失败，须写无 BOM UTF-8。

## 验证结论
- 2026-11-24 用 curl 直连本地后端验证 `/check/start` 等级透传生效：改 `gradeComprehensiveLevel` 后返回的 `evalLevel` 与综合能力题目 contentId 均随等级变化（细节见事件「改等级重载题目后端验证通过」）。
- 收尾未完成：恢复 nginx 原配置并 reload、停本地后端进程、删除临时产物。
