# 多模块弹窗业务类型推断缺陷
多模块共用同一弹窗组件时，若从路由名或目录名推断业务类型，会因前后端命名不一致导致接口查空。
## 影响模块
- 资金补交(supplement)、电梯缴存(elevator)、公共收益缴存(benefit)、续筹缴存(renewal)
- 共用 maintenance/depositNotice/components/ 下弹窗与缴存清册组件
## 根因
- 组件自身不知所处业务，原实现用路由/目录名反推 depositType
- 后端枚举为 publicincome / continuouspayment，与前端目录名 benefit / renewal 不同源
- 推断错误导致查询参数不对，右侧表格空白
## 修复做法
- 共享组件仅声明 props（depositType），父页 PaymentRangeTable 从模块常量显式下传
- 组件内去除任何路由/路径/目录名推断分支
- 顺带修正大小写判断与枚举完全一致
## 验收要求
- 四个模块入口各跑一遍，选幢后均需看到数据
