# 业主决策确认后无反应与打开失败
苏服办 C 端业主决策确认后表决页打不开、加载关闭却无反应或仅一闪而过 toast 的问题排查与弹窗修复。

## 问题与反馈
- 用户反馈少数业主点确认后加载结束无反应、不跳转，多数用户正常；录屏中加载已关、地址未变、页面完全没离开、无任何提示。
- 线上部署地址 `https://wygl.wxwgzx.com:8989/szh5/sfb/`；2026-11-27 按该线上包核对脚本为 `usePortal.ee8685ea.js`，不再以本地 dist 判断。
- 线上 `usePortal.ee8685ea.js` 已有 300ms 后失败提示（一闪而过 toast，容器内不易看见），并非旧包。

## 排查结论
- 用户不认可早前「苏服办拦外链」「表决页跳回首页致页面刷新」两条结论——表决链接域名相同仅参数不同、录屏里什么反应都没有、真机跳转不可能看不出来；助手复核确认这两条不成立。
- 唯一吻合路径：投票地址已拿到、`window.location.replace` 被调用且未报错，代码当成跳转成功不再提示，但执行后页面仍停在原地；尚不能断定 `replace` 为何没带走页面、失败用户参数现有代码未保留。
- 域名拦截或外链打不开会弹「业主决策页面无法打开」、接口失败会弹「业主决策页面打开失败」、跳走再跳回真机可见页面切换，录屏中均无此表现；链接域名相同只能排除按域名拦截。

## 修复方案
- 用户明确要求给出修复方案、强调没有任何提示且不存在一闪而过的提示；苏服办打开外部页面的正式接口是 `lightAppJssdk.navigation.show`，原实现用 `window.location.replace`，调用不报错即当成功，部分手机页面不动也无任何提示，已改为用容器接口打开表决页。
- 打不开时用必须点确定的对话框提示，文案「业主决策页面无法打开，请稍后重试」，点「知道了」关闭且不会自动消失，不再依赖会消失的 toast；普通浏览器没有苏服办接口，仍走原来的整页跳转。
- 模板里原把点击直接写成函数调用、点击处理写成页面一显示就执行，导致页面一渲染就关闭弹窗；已改成点「知道了」时才判断并关闭。
