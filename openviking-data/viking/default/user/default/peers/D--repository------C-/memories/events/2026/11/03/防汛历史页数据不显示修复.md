## 排查结论

**现象**：历史记录页显示「暂无相关记录」，但 Network 里 `/inspection/page` 返回 `total: 170`、10 条 `inspectionStage: "3"` 的数据 —— 有数据没展示。

**根因**（在 [flood.ts](<src/stores/flood.ts>) 的 `fetchHistoryRemote`）：
1. 请求 `/inspection/page?pageNum=1&pageSize=10` **没带 `inspectionStage`**，后端按全局分页返回，第 1 页恰好全是汛中（stage 3）。
2. 前端拿到后按当前页签 `kinds` 做**客户端过滤**（汛前页签 `['pre']`）→ 10 条全是 `mid` → **全被过滤掉** → 空列表。
3. `total` 用的是过滤后 `records.length`（0），不是后端的真实 `total`，导致 z-paging 认为无更多数据、计数也错。

我已经核对了后端 `FloodInspectionController.page` / `FloodRescueController.page`，`FloodInspectionQueryDto` **本身就支持** `inspectionStage`(2/3/4)、`subject`(property…)、`bizState`、`keyWord` 等过滤参数（Service 层 `.eq(getInspectionStage, ...)` 生效）。

## 改动

只改了 [src/stores/flood.ts](<src/stores/flood.ts>) 的 `fetchHistoryRemote` 和 `countHistory`（demo 分支未动）：
- 检查单按阶段分别请求 `inspectionStage=<STAGE[kind]>&subject=property`，让**后端做阶段过滤**，不再「全量拉取后前端过滤空页」；
