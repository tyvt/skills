- OpenViking 记忆审计的 apply 回写阶段逐条执行 ov write + 回读，速度较慢（每条约 12 秒，个别条目 embedding 超时时单条上限可达 120 秒），应预期转入后台执行。
- stdout 重定向后输出文件与 job_output 仅在进程结束时一次性可见；执行期间通过审计日志是否增长来判断进度，不要反复读尚未写入的输出文件。
- 审计日志短暂停滞通常是某条 write 卡在 embedding 超时；先再等一个观察周期确认是否继续推进，不要急于中断任务。
- 进度偏慢但稳定时用 wait 阻塞等待进程结束，避免高频轮询带来的额外开销。
- 全部回写完成后再统一读取 apply 结果与 stats 覆盖率，核对 skipped 数、哈希回读校验与 valid/invalid 分布。
- apply 逐条 write 带 --wait 等 embedding、串行执行；Ollama 断连会显著拖慢写回。长时间无输出疑似卡在 OpenViking API 写回时，先诊断脚本逻辑与进程状态，并抽样读首尾条目的 frontmatter 是否已写入来判断是否真在推进（如首条已写、末条未写即仍在推进），不要急于中断。
- When the apply command produces no output for more than 12 minutes, treat it as abnormal and inspect the exact apply loop, audit log, lock, and process state instead of only re-waiting.
