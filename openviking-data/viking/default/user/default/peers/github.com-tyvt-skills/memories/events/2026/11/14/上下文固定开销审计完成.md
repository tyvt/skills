## 结论先行

**每轮真正"每步固定重发"的是 tools + system ≈ 14k token/步**（inject 是 turn 级、非每步）。有明确优化空间，主要在两处：

**1. tools 中位 12.7k，其中 69%（≈6k/步）是几乎没人用的重型工具**

| 组 | token/步 | 真实使用率（729 会话） |
|---|---|---|
| `workflow` | 848 | **0.7%**（只用 5 次）|
| `schedule_*` | 1,495 | 1.4%（10 次）|
| `session_event_*` | ~600 | 1.5% |
| `team_task_*` | 1,512 | 3.8% |
| `session_search/trace` | 994 | 8.8% |
| `goal` | 433 | 5.9% |
| 对比：pwsh/read/edit/grep | — | 90–97% 核心 |

**2. OpenViking 工具"回退膨胀"**：38%（276/731）会话把 24 个 `mcp__openviking__*` 独立工具重新内联，每步 **+4,697 token**（14.1k vs 9.4k），而 `mcp_gateway`（246 token）本已是替代入口——两套并存纯浪费。

**其余（message 占 80%）**是真内容，不能删，只能靠纪律压（少整读、大结果先过滤）。

## 收益与方案
- **P0 消除 OpenViking 内联回退**（纯配置，零风险）≈ 省 **13M 等效成本（1.2%）**
- **P1 重型低频工具改按需装载/裁剪** ≈ 省 **40M（3.8%）**，合计约 **5%**，且几乎零功能损失
- 落点都在 `~/.dsh/profiles/web/cordis.patch.yml`（profile 层，非改核心），git 可回滚，改后需重启 DSH Web 生效
