### 2. §3.4 cd 链跟踪对"相对子目录"处理有漏拦

§3.4 (a) 的 cd 链跟踪逻辑：

```
if head ∈ {cd, Set-Location, pushd}:
    target = 该段 <path> 参数
    inSessions = pathIncludes(target, ".sessions")
    continue
```

`inSessions` 被**无条件重算**为"target 是否含 `.sessions`"。于是：

```
cd .sessions && cd sub && cat bill.json
  seg1: cd .sessions → inSessions=true
  seg2: cd sub        → target="sub" 不含 .sessions → inSessions=false   ❌
  seg3: cat bill.json → inSessions=false 且 arg 不含 .sessions → 不拦   ❌ 漏拦
```

`cd sub` 是进入 `.sessions` 的子目录，语义上仍在 `.sessions` 下，但布尔状态被错误重置。这是 v5 🟡4 修复时**只考虑了单层 cd**、没考虑 cd 链相对路径的连带问题。

**建议**：cd 链跟踪不能只看 target 字符串是否含 `.sessions`，需维护"当前目录"或至少区分：

- target 为绝对路径 → 按是否指向 `.sessions` 重算；
- target 为相对路径且不以 `..` 开头 → **保持当前 inSessions 不变**（进入子目录不离开）；
- target 为 `..` 或含 `..` 的相对路径 → 重新计算（可能离开）。

文档应把这条写进 §3.4 (a) 的伪代码，并补 selftest 用例：`cd .sessions && cd sub && cat bill.json`（应拦）、`cd .sessions && cd .. && cat bill.json`（应放行，已离开）。

## 🟡 建议级

### 3. §4.2 文案"临时关闭对应规则"与 §7.5 方案 B 矛盾

§4.2：

> 用户若确需临时直跑，**只能由用户本人修改 config**（`enabled:false` **或临时关闭对应规则**）后执行。

但 §7.5 方案 B 明确"把规则开关硬编码进插件（**不进 config，模型不可关**）"。若采用方案 B，用户**无法"临时关闭对应规则"**——只能 `enabled:false` 全关或删 patch insert。§4.2 的"临时关闭对应规则"在方案 B 下不可执行。

**建议**：§4.2 改为条件表述或通用表述：

> 只能由用户本人修改 config（`enabled:false`；若规则开关未硬编码，也可临时关闭对应规则）或卸载 patch 后执行。

### 4. §3.4 (c) `find ... -exec` 会漏拦

(c) 的"仅查找不拦"条件：

> `head ∈ {find, ls, dir, Get-ChildItem}` 且 `cost_bill.py` 仅出现在 `-name/-Filter/-Include/--name` 的值里 → pass

但：

```
find . -name "cost_bill.py" -exec python {} \;
```

`cost_bill.py` 确实只出现在 `-name` 值里，满足 pass 条件 → 放行；但 `-exec python {}` 实际执行了脚本 → **漏拦**。

**建议**：在 pass 条件上加反向约束——"若该段含 `-exec / -execdir / -ok / -okdir`，则不适用仅查找豁免，按执行拦"。

### 5. §3.4 管道过滤段 `Where-Object` 含 `cost_bill.py` 可能误拦

```
Get-ChildItem -Recurse | Where-Object Name -eq "cost_bill.py"
```

切段后 `Where-Object` 段 head=`Where-Object`，不在 `buildLintNonExecHeads`，进入 (c)：argv 含 `cost_bill.py`，head 不在 `{find,ls,dir,Get-ChildItem}` → **拦**。但这是查找过滤，不是执行/读取账单。

**建议**：把 `Where-Object / Select-Object / ForEach-Object` 视为"过滤/查找类"头，或对 `cost_bill.py` 仅作为 `-eq / -match / -like` 比较值时放行。属边缘场景，可在 selftest 里标为已知样本，不阻塞落地。

### 6. §3.1 "公共前置"的 bin 集合未列举

> 任何**构建/检查类 bin**（eslint/tsc/vue-tsc/npm 等）若选项仅含 `--version/--help`… → 放行

"构建/检查类"是模糊集合，实现时需明确白名单（`npm/pnpm/yarn/npx/eslint/tsc/vue-tsc/vite` 等）。建议在 §3.1 列出 bin 集合，或注明"以 §3.1 各子规则里出现的 bin 为限"。

### 7. 文档末尾重复标题

§9 标题"9. 待用户确认后执行"出现**两次**（标题一次、正文前又一次）。属格式笔误，删除重复即可。
