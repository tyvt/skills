## 二、具体改法

**O1（最高优先）**：在 zentao-analyzer 主 SKILL.md 顶部（定位章节之前）插入一段硬流程：

```
## 定位三步曲（硬顺序，禁止跳步）
1. 查菜单/路由表（zt_menu 或前端 router 配置），用 bug 标题/截图菜单名匹配 → 拿 path
2. 进 src/views/<path>/，只在该目录内 read/grep
3. 仅当 1、2 都无命中，才允许扩大到模块级检索
禁止：按 bug 标题字面量在源码里 grep 猜页面（标题≠路由名，例：用款通知书→划拨通知书 unblock/notice）
```

**O2**：同文件加熔断规则：

```
## 截图/标题冲突熔断
vision 结论与 bug 标题/描述矛盾时，立即停止按标题推演，二选一：
- 查 zt_file 条数与文件名，确认是否传错附件
- ask_user_question 直接问报告人
禁止「maybe vision misread」式假设继续推演。
```

**O3**：AGENTS.md 编排器选型段补一行触发词表，把判断从「理解规则」变成「词面匹配」：

```
意图含以下任一词 → 第一次就 orchestrate {op:"full"}，不等 gate：
跑/执行/构建/build/lint/测试/全仓/大目录/检索/grep 多文件/部署
例外：单文件窄 read（带 offset/limit）、grep 已缩到具体模块目录，可直跑。
```

**O4**：dbx.md 第 99 行附近改为操作清单（消除「量了总长还是续读」的歧义）：

```
长文本（steps/desc 等 TEXT 字段）读取固定动作：
1. SELECT LENGTH(col) → 得 N
2. 直接在思维里算段数 ceil(N/500)
3. 一条 SQL：SELECT seq, SUBSTRING(col, (seq-1)*500+1, 500) FROM (SELECT 1 seq UNION ALL ...) 分段别名表
4. 一次 UNION ALL 全取，禁止先取一段看截断提示再续
```

**O5**：submodule-commit 第 4 条改为带校验的顺序：

```
需要构建产物哈希：commit → build → 核对 version.json.gitHash == git rev-parse HEAD
不一致 = 顺序反了，必须重 build，禁止写「acceptable」。
```

**O6**：AGENTS.md 计划审批段加前置事实清单：

```
计划涉及修改某个 data/computed/props/字段 → 动笔前必须先 grep <字段名> 拿到定义行号，
并把「定义方式（data/computed/接口返回）」写进「现状与证据」。缺定义行的计划不得送审。
```
