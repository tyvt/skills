## 一、真重复（建议处理）

**1. `agent-cost-hygiene`（未加载）与现有 skill 大面积重叠**
它的描述——读文件策略、截断即换、构建顺序、收口时机、vision 去重、环境预检——已被 `token-frugal`（工作流归因）+ `tool-call-hygiene`（错误自愈）+ `dsh-token-policy`（构建/收尾时机）+ `token-guard`（结果裁剪）完整覆盖。且它**未链接到 `~/.dsh/skills`，实际不生效**，是被拆分后遗留的旧壳。这是最干净可清理的一个。

**2. 工具失败自愈三处并存**
- `agent-guard`（插件）：自动修参数形状 + 供应商失败恢复
- `tool-call-hygiene`（skill）：同一批错误码的人工自愈手册
- `orchestrator`（插件）：自动故障转移

`agent-guard` 的参数修复与 `tool-call-hygiene` 的 `INVALID_ARGS` 处理是同一问题的「自动版 vs 文档版」；故障转移与供应商恢复也交叠。建议明确：插件管自动兜底，skill 只留插件覆盖不到的错误码。

## 二、设计分工，但交界模糊（可接受，需画清边界）

**3. token/成本域最拥挤（6 个组件）**

| 组件 | 定位 |
|---|---|
| `token-frugal` | 单会话工作流归因（为什么贵）|
| `token-optimizer` | 跨会话成本排序（哪个最费）|
| `dsh-token-policy` | 常驻规则/路由阈值 |
| `cost-meter`（插件）| 运行时超阈提醒 |
| `token-guard`（插件）| 工具结果源头裁剪 |
| `token-models`（插件）| GUI 每模型 token 面板 |

分层其实是清楚的（规则/归因/排序/提醒/裁剪/展示），但 6 个同域组件对用户感知重复度最高。

**4. Git 三件套**：`repo-safety` 描述已含「一任务一 worktree、子模块自底向上提交」，与 `submodule-commit`、`worktree-snapshot` 内容部分重叠。拆开有利于按需加载省 token，但三处维护同一套规则，易漂移。

**5. 规则文档 vs 强制门**：`dsh-token-policy` ↔ `orchestrator-gate`、AGENTS.md 计划审批 ↔ `plan-gate`，都是同一规则写两份（文档版 + 强制版）。`dsh-token-policy` 自称「常驻禁止项在 AGENTS.md 不重复」，但 gate 的拦截集与它仍高度重合。...
