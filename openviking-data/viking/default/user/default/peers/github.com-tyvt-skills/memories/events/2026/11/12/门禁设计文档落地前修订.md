### 3. §3.4 cd 链的 `cd ..` 保守方向反了 —— 实现会漏放

§3.4 (a)：

```
elif startsWithDotDot(target):      # 以 .. 开头 → 可能离开
    inSessions = false              # 保守：离开 sessions（宁可不漏）
```

**语义与实现矛盾**：

- 文档写"**宁可不漏**"——在硬强制场景，应理解为"宁可误拦也不漏放"，即 `inSessions` 应**保持 true**。
- 实现设 `false`——读取类不再拦 → **漏放**。

且设 false 在相对子目录场景下是实打实的漏放：

```
cd .sessions/sub && cd .. && cat bill.json
  seg1: cd .sessions/sub → 相对子目录 → inSessions 保持初始 false   ❌
```

等等，这里初始 inSessions=false，`cd .sessions/sub` 是相对子目录 → 保持 false，就已经漏了。问题不在 cd ..，而在"初始路径未纳入判断"。更典型的：

```
cd .sessions && cd sub && cd .. && cat bill.json
  seg1: cd .sessions → inSessions=true
  seg2: cd sub       → 相对子目录 → inSessions 保持 true
  seg3: cd ..        → 以 .. 开头 → inSessions=false
  seg4: cat bill.json → inSessions=false 且 arg 不含 .sessions → 不拦 ❌
```

但 seg3 后实际在 `.sessions` 下（sub 的父目录），**仍在 sessions 内**，却被判为离开。这是实际漏放。

**建议**：`cd ..` 不能简单设 false，需维护"当前路径深度"或"当前路径字符串"：

- 维护 `currentPath`（初始为仓库根/exec cwd），每次 cd 做路径拼接/规范化，再判断 `currentPath` 是否含 `.sessions`；
- 或简化：`cd ..` 时**保持 inSessions 不变**（因为无法确定是否离开，按"宁可误拦"应保持 true），只有 `cd <明确不含 .sessions 的绝对路径>` 才设 false。

后者更简单，且符合"硬强制宁可误拦"的原则。当前"设 false 且称宁可不漏"是方向反了。

## 🟡 建议级

### 4. 公共前置对 `npm run <script> --version` 误放行

§3.1 公共前置："任一此类 bin 若**选项仅含** `--version/--help` … 放行"。

但 `npm run build --version` 中 `--version` 是传给 build 脚本的参数，npm 不会因此打印版本——命令**实际执行了 build**，却因"含 --version 且无其他执行性参数"被放行。同理 `pnpm run lint --help`。

**建议**：公共前置限定为"bin 直接跟 --version/--help"（`eslint --version`、`tsc --help`），对 `npm/pnpm/yarn run <script>` 形式**不适用**——即 `run` 子命令后出现 `--version` 视为脚本参数，不触发放行。

### 5. Where-Object 脚本块形式可能漏过"仅查找"判定

§3.4 (c)：

```
isSearchOnly = head ∈ {..., Where-Object, ...}
               and cost_bill.py 仅出现在 -name/-Filter/-Include/--name/-eq/-match/-like 的值里
```

但 PowerShell 更常见的写法是脚本块：

```
Get-ChildItem -Recurse | Where-Object { $_.Name -eq "cost_bill.py" }
```

`cost_bill.py` 在脚本块 `{ ... }` 里，不是 `-eq` 的直接值 → 不满足"仅出现在 -eq 值里" → isSearchOnly=false → **误拦**。虽属查找而非执行，但会误伤。

**建议**：把 `Where-Object`/`Select-Object`/`ForEach-Object` 的豁免条件放宽为"该段不含 `-exec`/`-Command`/`Invoke-*`/`Start-Process` 等执行性 token"，而不要求精确匹配 `-eq/-match/-like` 的值位置。或标注为已知边缘，selftest 里作样本记录，不阻塞落地。

### 6. `cd` 执行失败的固有限制未注明

guard 是**预执行**检查，无法知道 `cd .sessions` 是否成功（目录不存在则 cd 失败，后续命令实际在旧目录执行）。§3.4 的 cd 链跟踪假设 cd 一定成功。

**建议**：在 §3.4 或 §6 注明"cd 链跟踪假设 cd 成功；cd 失败时后续命令在旧目录执行，本规则可能误判——属预执行固有限制，接受"。属边界说明，不阻塞落地。

### 7. `isAbsolute(target)` 的平台判定未注明

Windows 下 `D:\repo\.sessions` 绝对、`\repo\.sessions` 盘根相对、`.sessions` 相对；Unix 下 `/x` 绝对。文档用 `isAbsolute(target)` 未说明实现（`path.isAbsolute` 还是自实现）。建议注明"用 `node:path` 的 `isAbsolute`，按运行平台判定"——属实现细节，提一下即可。
