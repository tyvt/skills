## 工单 A（P0，硬约束）：防汛改动的 pre-commit 门禁

**目标**：暂存了 `src/views/flood/**` 或 `src/api/flood/**` 却没有 `docs/flood/common-errors.md` 时，commit 直接失败。

**落点**：子模块 `zhi2-web-admin` 的 husky 钩子（本会话 commit 输出显示已启用 lint-staged，说明 husky 在位）。worktree 共享同一 `.husky/`，无需每个 worktree 单独装。

**做法**：把 `.husky/pre-commit` 改成先跑门禁、再跑 lint-staged。

```sh
#!/usr/bin/env sh
# 防汛改动必须同提交更新错误台账（AGENTS.md 交付要求）
staged="$(git diff --cached --name-only --diff-filter=ACMR)"
if printf '%s\n' "$staged" | grep -qE '^(src/views/flood/|src/api/flood/)'; then
  if ! printf '%s\n' "$staged" | grep -qx 'docs/flood/common-errors.md'; then
    echo "❌ 防汛页面/接口改动必须同一提交更新 docs/flood/common-errors.md"
    echo "   规则来源：AGENTS.md 交付要求 / flood-page-guard"
    echo "   本次暂存的防汛文件："
    printf '%s\n' "$staged" | grep -E '^(src/views/flood/|src/api/flood/)' | sed 's/^/     /'
    exit 1
  fi
fi
npx lint-staged
```

**注意**：
- 若 husky 是 v9，删掉 `_/husky.sh` 那行；若 v8 保留。
- 只看**子模块内** commit，父仓 `chore(submodule)` 提交不受影响（hook 在子模块里）。
- 纯 docs 提交、非 flood 提交不受影响。

**验收**：
1. 只 `git add src/views/flood/x.vue` 后 commit → 失败并打印提示。
2. 再 `git add docs/flood/common-errors.md` 后 commit → 通过，且 lint-staged 仍执行。
3. `git add src/views/evaluation/x.vue` → 不受影响。

> 这条能直接消灭本会话最贵的一次返工：代码 `1e4f697cd` 先提交推送、父仓 `9737184` 同步，之后才发现漏台账，又补 `4d0aa574a` + 父仓 `84bebc1`，多一轮 commit/push/父仓同步。

**判断标准**：跑一个同类防汛 bug，看是否满足——
1. 只有 **1 次**子模块提交（代码+台账同 commit）；
2. 只有 **1 次**父仓指针提交；
3. 没有单步 output > 3000 tokens 的纯推理；
4. 收尾前有 token-optimizer 输出；
5. 禅道回写走脚本，无手拼 SQL。
