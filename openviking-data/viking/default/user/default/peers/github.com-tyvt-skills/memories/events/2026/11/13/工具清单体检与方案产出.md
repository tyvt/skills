## 核心结论

**当前 `standard` preset 每步固定下发约 67 个工具**，按来源分 13 组。历次 token 审计已经把 dbx/context-mode 的 36 个 MCP 工具收编进 `mcp_gateway` 单入口了，**但漏了一个最大的同类项**：

### 🔴 P0：OpenViking 的 24 个工具绕过 gateway 直连常驻
- 证据：`@openviking/dsh-memory-plugin` 的 `index.mjs:113` 无条件 `mountOpenVikingMcp()`，把 24 个 `mcp__openviking__*` 工具全挂进目录（本会话实物可数：add_resource…write 共 24 个）。
- 成本：每步约 **1.5k–2.5k tokens 固定重发**，且其中 `privacy_*`、`*_acl`、`list_users/groups`、`cancel_watch`、`download` 等低频维护工具长会话里几乎不调。
- 这正是 gateway 当初为 dbx/context-mode 解决的问题的复现，只是换成了 openviking。

### 🟡 P1：agent-team(9) + session-query(5) 平台型大块
对多 agent / 跨会话回忆必要，但普通单线程编码任务是 1k tokens/步 的纯开销。

### 🟢 其余都很精简
host 的 14 个核心工具 bundle 描述合计仅 ≈3.1k tokens，没有值得砍的。

## 方案（关键：B 走不通）
- **方案 A（推荐）**：把 openviking 也纳入 mcp-gateway（1 个入口 + 按需 list）。语义可行——记忆的 capture/recall/commit 走 HTTP 端点，与工具面独立。**但已查证：插件没有任何配置开关能关/过滤工具面，必须 `pnpm patch` 改插件，或上游加开关。不是改一行 yml 能完成的。**
- **方案 B（已排除）**：config 里白名单收窄——插件不提供该字段，走不通。
- **方案 C（P1 可选）**：agent-team/session-query 场景化，需新会话切 preset，不建议默认做。
