**这两个工具是干什么的**
- `spawn_teammate`：在会话内拉起 teammate 子代理并行处理多个对象，是 AGENTS.md「并行扇出」规则的“多对象并行首选”（成员继承 Lead 模型，不支持 per-spawn 换模型）。
- `workflow`：大规模编排工具，支持 `agent(prompt,{provider,model})` 派异构模型子代理。

**为什么没有**
- DSH 按会话 preset 裁剪工具、省每步 toolsTokens。2026-11-14 的批 2 裁剪在 `~/.dsh/profiles/web/cordis.patch.yml` 的 `preset-standard` 里给 `tool-workflow` 加了 `disabled: true`，standard 会话从此没有 workflow（每步省 848 token，已实测验证；full-tools 预设 46 工具仍保留）。
- 11-14 验证时 standard 会话还保留 spawn_teammate；若现在连它也没有，说明要么之后又做过裁剪，要么本会话跑在更精简的 preset 上。

**实际影响**
- 「并行扇出」规则要求同类批量对象 ≥3 时优先扇出到 spawn_teammate / workflow；这两个工具不在会话里时，agent 只能声明这一点然后改道——首选 `orchestrate {op:"full"}`（编排器内部并行，本会话仍在），或退回窄命令分批处理。
- 所以这句话本质是“别试这个工具、换路走”的提示，不代表系统故障。

**要恢复的话**：把会话切到 full-tools/cordis 预设，或在 cordis.patch.yml 里去掉 tool-workflow 的 `disabled`（11-14 改动有备份 `.bak-p1b-20261114152151` 可参照）。
