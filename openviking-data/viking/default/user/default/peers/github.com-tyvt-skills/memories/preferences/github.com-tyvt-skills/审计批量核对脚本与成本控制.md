- Check orchestrator capability first and use it for parallel verification batches, while keeping result writing and application under direct control.
- 并行核对编排器失败时不按同一形态重试，直接切换为脚本化批量核对（逐条提取高辨识度符号、在命中文件内核对、输出紧凑证据表供二态判定）。
- When verification cost becomes high, stop expanding checks: run one final parallel batch covering the remaining critical items, resolve all verdicts, write back, and finish directly.
- For many candidates, write one batch verification script that greps decisive symbols per candidate and emits a compact report; read the report in slices and run a focused second pass only for missing or contradictory symbols.
- Prefer compact judgment sheets with file matches and symbol hits only over reading long raw dumps.
- 仅向审计缓存目录写入临时导出或核对脚本、不涉及项目代码改动时，无需构建代码基线即可继续运行。
