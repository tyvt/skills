- 记忆抽查逐条核对：用特征字符串在 D:\repository 对应项目内 grep 精确定位并读指定行段，按实机代码证据判 VALID/INVALID，不凭记忆描述本身下结论；输出被截断时收窄到具体文件与行段。
- 审计只回写 verdict/note 等判定字段并 apply，不改记忆正文语义、不删除记忆、不提交 git；中间文件只写 ~/.dsh/cache/memory-audit/，不写入项目目录。
- 写 result.json 后、apply 前自检 verdict 与 note 结论一致（曾出现 note 写改判有效而 verdict 仍 invalid），纠正后再 apply。
- 统计以逐条判定与 apply 结果为口径；简报汇总数与逐条结论冲突时按逐条为准并显式更正口误。
- build-gate 不适用于纯审计任务：未改项目源码、只写缓存中间文件时无需构建基线。
- 候选清单 select.json 用文本 read 工具读取，不要误用图片读取工具；终端输出截断（picked 数多于显示条数）时读完整文件并补读中间省略段。
- 全仓 glob 会超文件预算失败，改用已知项目目录的窄命令批量核对；记忆路径省略子目录前缀时在项目目录内窄定位；精确 symbol 核对并行但控制批量避开门禁。
- 后台全仓 grep 大目录会卡住，kill 后改用 ops_grep（有扫描预算、更快）做最后核对；成本升高时用 offset/limit 局部行读收窄范围。
- 审计时宽泛的仓库级 glob 会撞上 dist/ 压缩产物与 file-limit 并污染结果；收窄到 src/ 子路径，按具体文件与行段精读核对。
