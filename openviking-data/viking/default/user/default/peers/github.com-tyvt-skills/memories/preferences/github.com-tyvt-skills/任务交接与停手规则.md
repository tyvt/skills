- 存在未完成项（如 git 提交、临时产物与后台任务清理）时必须先写交接文档再停手，不能直接结束任务。
- 交接文档按 9 节格式撰写，存放在 D:\plan\skills\，文件名含链路主题、hop 序号与时间戳。
- 排下一跳时 DTSTART 按当前时间现算（约 +15 秒），交接 prompt 只保留四项内容。
- 收到 P0 硬交接指令时，完成交接文档与下一跳排程后立即停手。
- skill 加载失败（报 unknown 或不再可用）时也不阻塞：按记忆中做法手工执行，注入指令为权威，仍按 9 节格式写交接文档，并找已有 9 节交接文档作格式模板。
- 等效成本超过 150k 阈值时在步骤边界启动 hop 交接（2026-11-25 实测 156k 触发 hop2、162k 触发 hop3），不在本会话触顶后硬撑。
- 触顶交接时若旁边存在半成品状态（半迁移的 DB、运行中的服务），本跳只做只读核对、不改生产代码/DB，把现状与待决项写进交接文档再排下一跳。
- P0 分档硬控：累计等效成本达 1.00M（mid 档）即在步骤边界强制交接并停手（2026-11-25 实测 1.08M 触发 hop4→hop5）。
- 接续指令以交接文档正文为准（文末「新会话第一步」与「第 4 节 未完成（按优先级）」）；排程所写节号若在文档中无对应标题（如「第 9 节」），按正文接续、不阻塞。
- 收尾跳对第 4 节每项待办逐条给出结论（含无法闭环项及原因、不重跑已完成项）后即终止链路、不排下一跳，并列出唯一可选的人工后续。
