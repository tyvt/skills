当前 6 步并列，实施时精力会分散。真实收益排序：

- **P0（先做，占 80% 收益）**：E1 绝对路径只读放行、E2 hash 复用 + 轮次上限
- **P1（随后）**：E3 plan 重写提示、E7 基线口径文案
- **P2（可延到下一轮）**：E4/E5 合并提示、E8 单步短路、E6 vision 评分表

E6 是纯规则层、无自动单测、靠人评，性价比最低，放在代码方案里占一节反而稀释重点，建议直接降为 policy 一段话。

**commit 边界也要写死**：`graph.py` 的 E1 独立 commit（唯一高风险、必须可单独 revert）；E2/E3 一个 commit；E4/E5/E7 一个 commit；E8 一个 commit 且默认关。现在只有 E1 提了"独立 commit 易 revert"，其余没定。

## 二、三个硬缺口（实施前必须补）

**1. E2 的数据流没闭环。** plan_review 是 `orchestrate{op:"plan_review"}` 在编排器子进程里跑的；plan-gate 拦截的是宿主 `edit/write`。**轮次计数和 hash 复用放在 plan-gate，但它感知不到 plan_review 发生了**。方案写"plan-gate 轮次事件计数"，实际没有事件来源。需要补一个桥接：plan_review 每次返回后写 `.plan/<sessionId>.review.json`（hash、轮次、verdict、mtime），plan-gate 读它判断。不补这条，步骤 3 的 2/3/4 三个子功能全都落不了地。

**2. E1 过度设计，第一版会做不完。** 本会话三次 escalate 全是**绝对路径 `Select-String`**，不是 `rg --pre` 或 `git -c`。参数级白名单 + realpath + symlink + 8.3 + 敏感名 + glob 排除 + which 校验 + 管道重定向，这是安全敏感代码，任何一处漏就是逃逸，而且单测要写 8 个负例——这是两三个小时的活，不是"扩白名单"。建议**拆两步**：
- P0 最小版：`Get-Content/Select-String` 绝对路径 realpath 归 repoRoots + 拒绝 symlink + `_DANGEROUS_CHARS` 最前——覆盖 80% 场景，负例 3 个
- P1 完整版：参数级白名单、`git log -p` 强制带路径、敏感名排除、which 校验

**3. 缺"增量送审"。** E3 只做"重写提示"，但真正该做的是**plan_review 只发变更段落**。本会话 plan 4 次全量送审，每次都把整篇 3-4k 喂给 reviewer，既抬 E2 的 input 又抬 E3 的 output。加一条：送审时若已有上轮 hash 的 plan，只发 `diff` 段 + 新增证据，reviewer 基于上轮结论续审。这条能同时降 E2 和 E3，比 E3 的"提示"有用得多。

## 三、需要收紧的口径

- **量化验收太松**：现在写"单任务首次达标即视为通过"。改成 **3 个任务全部达标才算通过**；均值达标但单任务不达标，写明原因并复测一次。否则 1M→0.9M 也能"达标"。
- **编排器调用计数口径不清**："按 execute 条数"会低估——本会话有一次 orchestrate 内部 5 步，按 execute 算是 5 次，按 orchestrate 调用算是 1 次。而 guard 链开销来自 orchestrate 调用。建议**主指标按 orchestrate 调用次数**，报告里附底层执行数。
- **生效时机没写死**：风险表说"下次会话/profile 重载生效"。这意味着本轮改完**不能当场验证 A/B**。§五 必须明确"baseline 与 A/B 均在下个会话执行，本轮只交付代码 + 单测/selftest"。不写这句，实施完会误判"已生效"。
- **模板缺失**：E2 证据章节硬拒，但没给模板。直接改 `.plan/TEMPLATE.md`，给 frontmatter + `## 已核验事实` 骨架（每条 `\S+:\d+` 一行），一填就过；只写 policy 文字规则 agent 会漏，模板是结构约束更硬。
- **告警响应**：本会话 150k、1.01M 两次告警后仍全量重写。方案只加了提示，没约束。跨插件通信成本高，建议不新增机制，只在 **cost-meter 告警文案里直接写"下一步禁止全量 write/全量 read"**，低成本覆盖。
- **§七 的 5 条待确认**：给默认值，别全抛回用户。建议默认：E1 开（env 可关）、E2 硬拒接受（override 需二次确认）、E8 关、E6 自评即可、本轮不实施。
