## P0-1 排查结论：**确认成立，但仅限 magpie-responses 路径**

### 证据链（本机 DSH 安装实测）

**1. `magpie-responses`（openai-responses API）每步全量重发历史 reasoning —— 实锤**

- `~/.dsh/profiles/web/cordis.patch.yml:1029`：`magpie-responses` provider，`api: openai-responses`，挂 `codex/gpt-6.1-sol` 等模型
- `pi-ai/dist/api/openai-responses.js:264`：`store: false` —— 无状态模式，服务端不存历史，全靠客户端每步重放
- `openai-responses.js:295`：请求带 `include: ["reasoning.encrypted_content"]`，每步产出加密 reasoning
- **关键点** `openai-responses-shared.js:234-240`：历史 assistant 消息序列化时，每个 thinking 块只要带 `thinkingSignature`（存的就是含 `encrypted_content` 的完整 reasoning item JSON），就**无条件** `JSON.parse` 后 push 回 input——没有“只保留最近 N 步”的任何条件或配置项

**2. 主模型走的 `magpie`（openai-completions）路径：历史 reasoning 不回传，无此问题**

- `openai-completions.js:993-999`：只有 thinkingSignature 非空（magpie 网关模型流式时置 `""`，仅 opencode-go 例外）才写 `reasoning_content` 字段；`requiresThinkingAsText` compat 默认 false（:1267）→ **主模型（hy3 / zai_glm-5.3-flash 等）的历史 thinking 在序列化时被丢弃**
- 意外收获：这意味着 62% 的二次累积集中发生在用 `codex/gpt-6.1-sol`（magpie-responses）的长会话里

**3. 平台无现成开关**：`dsh-agent-loop`、`dsh-compaction*`、pi-ai transform 全部只有 `reasoningEffort` 旋钮，无历史 reasoning 裁剪配置 → **配置丢弃做不到，只能 patch**
