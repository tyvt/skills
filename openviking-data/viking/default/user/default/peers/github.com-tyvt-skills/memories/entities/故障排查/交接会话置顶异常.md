# 交接会话置顶异常
DSH Web 自动交接下一跳会话在 composer2.5 下沉底、hy4 flash 正常置顶，2026-11-25 排查确认 skills 仓代码层无法可靠修复。

## 现象
- composer2.5 下交接新会话沉底、hy4 flash 下置顶；判据为交接后会话列表第一条即新会话
- 交接用 target=new_once 创建新会话（session-handoff/SKILL.md:48）

## 根因排查硬事实
- 会话列表排序在 DSH Web 闭源前端包 @deepseek-ai/dsh-web-frontend@0.2.1-rc.2 + @deepseek-ai/dsh@0.2.2-rc.5，本机无源码、patch 全局包重启即被覆盖
- 服务端存储 ~/.dsh/storages 不暴露排序配置；前端 bundle 未命中会话排序字段，"原会话继续活动致新会话沉底"因果未验证
- skills 仓三处交接点均不能根治：dsh/AGENTS.md:79 规则与 dsh/cost-meter/lib/index.js:322 handoff 指令均为 prompt 级（composer2.5 不遵守约束）；dsh/agent-guard/lib/index.js:272 tools/pre-execute 只拦工具调用，拦工具≠结束 agent loop
- agent-guard/cost-meter 只有 pre-step notice 注入与工具调用软拦截，无强制停手/结束 turn hook；guard 返回字符串即拒绝工具调用，可读 exec.arguments、按 session 维护 state

## 可选路径与结论
- A 换模型：不让 composer2.5 执行交接、切回 hy4 flash，用户已明确否决
- B patch agent-loop：用 dsh/patches/tool-call-fix 先例的 cordis patch 改 DSH 核心 agent-loop，检测交接排程后强制结束 loop；属改全局 npm 包高风险越权且依赖未验证因果
- 上一轮"修 composer2.5 交接行为"推荐已被证伪，为判断失误；最终待用户在 A/B 或补充置顶表现间定夺
