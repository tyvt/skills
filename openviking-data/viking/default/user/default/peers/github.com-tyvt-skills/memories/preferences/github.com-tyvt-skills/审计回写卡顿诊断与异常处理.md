- 后台 apply 长时间无输出时不要过早判定卡住：先查进程状态与脚本逻辑，判断是否卡在某个 OpenViking HTTP 调用，而不是反复轮询 stdout；每条需多次 ov CLI 读写，45 条约 135 次调用、约 12 秒/条。
- 审计日志短暂停滞通常是某条 write 卡在 embedding 超时；先再等一个观察周期确认是否继续推进，不要急于中断任务。
- apply 逐条 write 带 --wait 等 embedding、串行执行；Ollama 断连会显著拖慢写回。长时间无输出疑似卡在 OpenViking API 写回时，先诊断脚本逻辑与进程状态，并抽样读首尾条目的 frontmatter 是否已写入来判断是否真在推进（如首条已写、末条未写即仍在推进），不要急于中断。
- apply 因 embedding 服务断连报错时，先确认后台任务状态与 embedding 服务健康，再决定继续等待或处理异常。
- apply 命令超过 12 分钟没有输出时视为异常，应检查具体 apply 循环、审计日志、锁和进程状态，而不是只继续等待。
- 进程不可见但 job 仍在运行时，不用总体 audit_status 计数判断进度（多为历史轮次）；改读当前轮首尾 URI 的 last_checked 时间戳确认落盘，并抽查中间条目估计剩余时间。
