## 第一批：规则层（改 AGENTS.md / skill，当天可完成）

**R1 直跑豁免清单（对应 P0-1、P0-2）** — 落点：`~/.dsh/AGENTS.md` 编排器选型节

在现有「单文件窄 read、已缩模块 grep」例外基础上，扩充为明确的豁免白名单：

> 以下情况直跑宿主工具，不进编排器：
> 1. 已知具体路径的单文件窄 read（带 offset/limit）；
> 2. 已缩到具体模块/文件目录且关键词已知的 grep（含 `grep -n "类名"` 拿行号）；
> 3. 单目录 + 关键词已知的 grep（与「单文件窄 read」同级）。
>
> 样式类/局部行改动固定路径：**grep 类名拿行号 → read offset/limit ±30 行**，禁止对 >300 行文件整读。

**R2 CSS-only build 豁免（对应 P0-3）** — 落点：build-gate 配置 / AGENTS.md

> 改动仅含 scoped CSS、注释、文案时，构建 gate 直接放行并记录「CSS-only，build 豁免」，不再要求见基线。

**R3 stall 熔断（对应 P0-3、P0-1）** — 落点：AGENTS.md 长任务节 + 编排器

> 同一会话内 orchestrate 对同一命令 stall 一次后打标记；再次调用前必须换形态（查 `.task-state/*.state.json` / stderr 尾部）或直接写明「未执行 + 原因」，禁止同形态重试。
> 编排器侧：planner 加硬约束——任务含明确本地路径时直接 `generate_command` 调 `rg -n`，禁止输出「无法访问磁盘」类模板；对返回"无实际执行”的响应打熔断标记，同类请求本会话不再投 `op:"full"`。

**R4 一次问清窗口扩到 turn（对应 P0-4）** — 落点：ask-gate hook

> 判定窗口从「同一 step」扩到「同一 turn」：含 edit/write 的 turn，首个 ask 未覆盖「提交方式/推送」时拦截并给合并模板；兜底用 warning 级提示（问题数 <2 且未含提交选项）。

**R5 git 输出瘦身（对应 P0-5）** — 落点：`submodule-commit` skill 命令模板

- rebase/pull 统一加 `-q`，或 `| Select-Object -Last 15` 截尾；
- 父仓状态只查 `git status --short <submodule>`；
- 把 status/pull 封进已有的 `git-ab.mjs`，固化模板。

## 第二批：机制层（改 hook/编排器代码，需计划送审）

**M1 cost-meter 刹车（对应 P0-6）** — 落点：dsh-context / cost-meter hook
- 连续 2 步未命中 >10k → 下一步工具白名单强制为 `{read(offset/limit), grep(path+include)}`，其余调用返回 `cost gate: 请先用窄读`；
- 会话等效成本 >150k → 拒绝 `orchestrate op:"full"`，只允许直跑窄命令。

**M2 build-gate 代码化** — 豁免白名单从规则文字落成 hook 判定（diff 仅 CSS/注释/文案 → 自动放行）。

**M3 编排器 stall 摘要** — 编排器自己解析 stderr 尾部，输出一句话结论（如「仅 LangChain 弃用警告，无实质错误」），替代全量回灌。
