## 一句话
把编排器 `plan_review`（计划审核）改成**分级制：只有 P0（阻断落地）才 reject，P1/P2 仅提示不阻断**；并且只动 `plan_review`，`security_guard` 等审查节点保持原样。

## 现状问题
- `src/api.py` `_PLAN_REVIEW_SYSTEM`：无分级，任一瑕疵即 reject，还叠加 `score<70 也 reject`。
- `_normalize_review`：`pass 且 score<70 → 强制 reject` 硬规则。
- 后果：措辞/次要建议也打回，多轮送审、烧 token（历史有 5 轮 reject）。

## 改法（3 处，均为纯文本逻辑）
1. **提示词** `_PLAN_REVIEW_SYSTEM`：输出 `issues:[{level:P0|P1|P2,text}]`，明说「仅 P0 才 reject」，删掉 score<70 措辞。
2. **归一化** `_normalize_review`：兼容新旧 issue 格式；**删掉** score<70 硬规则；**新增**「有 P0→reject、无 P0→pass」一致性纠偏；返回 `p0_count`。
3. **渲染** `index.js renderPlanReview`：issues 按 `[P0]/[P1]/[P2]` 前缀显示，P0 置顶，追加「P0 阻断项：N 个」。
- `config.yaml` 的 `plan_reviewer` 模型池/超时不动；`security_guard` 不动。

## P0 定义（关键）
缺关键前置事实致必然失败、有不可逆破坏且无回滚、高危写操作无防护、方案自相矛盾/缺关键步骤、违反仓库/安全硬规则。
