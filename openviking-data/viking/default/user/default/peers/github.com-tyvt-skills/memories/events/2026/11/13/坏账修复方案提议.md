# 2026-11-13 (Friday) ChatLog:
**user [peer=github.com-tyvt-skills]**: 架构级 Fix 建议（让模型更聪明、更省钱）
针对上述坏账模式，具体落点如下：

🛠️ Fix 1：改造 Guard 报错文案（直接改代码，零成本起飞）
现状：拦截时返回“拒绝递归列举...改用 glob 或 Get-ChildItem 收窄”。

改造：在 agent-guard 的返回文本中，强制带上可复制的正确示范。

错误返回：“拒绝递归列举，改用 glob 指定 pattern...”

正确返回：“[agent-guard] 拒绝递归列举。请直接复制执行：Get-ChildItem -Path <具体目录> -Filter *.ext 或 glob {path: '<具体目录>', pattern: '**/*.ext'}。”

效果：模型看到提示会瞬间零延迟纠正，不用再试探。

🛠️ Fix 2：强制长任务外包（Hook / Gate 拦截）
现状：模型直接在主模型前台跑 vite build，不仅阻塞，而且回灌了海量日志。

改造：修改 AGENTS.md 里的硬约束，并在 pwsh 工具的封装层或 Hook 处增加校验。

约束规定：“遇到 build, test, install 等预期耗时 > 30s 的命令，禁止直接在 pwsh 前台执行。必须使用 orchestrate {op:"full", execution:{program:"npm", args:[...]}} 或 run_in_background: true。”

提示指引：若主控被强拦，强制其学习使用编排器。

🛠️ Fix 3：注入针对一次性脚本的“防御性 Prompt”
现状：模型直接上手写 mjs 或复杂 pwsh，导致环境不兼容和语法错误。

改造：在 PLANNER_SYSTEM 或工具描述中，加入写代码前的“三秒自检”：

"在编写 Node 脚本时，先确认项目是 type: module；在写复杂 pwsh 管道前，先跑一句简单的 echo 验证解析器行为。"

"禁止在测试脚本中并发启动多个耗时任务（如并发 build），必须串行测试以保证基准准确。"

🛠️ Fix 4：沉淀构建性能排查的专属 Skill
现状：模型用“手动消融（Ablation）”跑了四五次全量构建才找到真凶（1.85MB 的 SVG 内联）。

改造：将 vite-bundle-analyzer 或 rollup-plugin-visualizer 封装成一个可直接调用的 Skill（比如 vite-build-profiler）。

下次遇到“排查打包慢”，Prompt 直接引导模型："请先加载 vite-build-profiler skill 并生成报告，不要在盲猜中耗时间。"
