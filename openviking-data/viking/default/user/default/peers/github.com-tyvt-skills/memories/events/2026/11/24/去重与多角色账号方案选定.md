## 现状诊断（根因）

| 现象 | 根因（证据） |
|---|---|
| 项目重复 | 分组键用 `it.project`（index.html:55），卡片标题用运行时从 dist 父目录推导的 `display_name`（api.py:111-129）。`fdc-v3`（5 env，显示"苏州市房地产监测V3"）与 `苏州市房地产监测V3`（id=24, 8098，同一 dist）是同一项目登记两次 → 看板出现两组同名。"portal→门户"、"2334-registration→太仓G" 也存在 key/显示名分裂。 |
| Bug 命名 | 显示名取自 `dist_root` 目录名，`榆林G-bug6220-dist` → `榆林G bug6220`（id=19，conf 也带 bug6220）。名称没有独立、可治理的字段。 |
| 账号密码 | `login_user` 全空、`login_selector={}`、`secret_ref` 只是 `{{ov_privacy:deploy_env/<p>/<e>/password}}` 占位；隐私库里**没有任何 deploy_env 条目**（只有 nacos-taicang-dev）。每 env 只有一个密码槽，无法承载多角色，看板也完全不展示。 |

## 设计方案

### 1. 数据库（三表，密码绝不入库）

**新增 `projects`（项目身份唯一来源）**
```sql
key TEXT PRIMARY KEY,          -- 稳定键: fdc-v3 / portal / yulin-g
display_name TEXT NOT NULL,    -- 治理后的干净名: 苏州市房地产监测V3 / 榆林G
aliases TEXT DEFAULT '[]',     -- 旧 key/旧名 JSON，用于归并去重
dist_root TEXT, status TEXT DEFAULT 'enabled', updated_at TEXT
```

**改造 `env_registry`**：加 `project_key`(→projects.key)、`sort_order`；`project`→`project_key` 迁移；唯一键改 `UNIQUE(project_key, env)`；保留 `dist_root` 仅用于算 `built_at`。**废弃**运行时的 `display_and_built()` 名称推导（built_at 仍可由 dist 算）。

**新增 `env_accounts`（一 env 多角色）**
```sql
project_key TEXT, env TEXT,
role TEXT,                     -- admin / operator / viewer
role_label TEXT,               -- 超级管理员 / 操作员 / 只读
username TEXT,
secret_ref TEXT,               -- {{ov_privacy:deploy_env/<key>/<env>/<role>/password}}
login_selector TEXT DEFAULT '{}', sort_order INT, updated_at TEXT,
UNIQUE(project_key, env, role)
```

### 2. 去重与改名（迁移脚本，幂等 + 备份 + 写 events）

- 归并 `fdc-v3` ↔ `苏州市房地产监测V3`：保留 5-env 的 `fdc-v3` 作为 `project_key`，旧名进 `aliases`，删除 id=24 冗余行；显示名统一为干净的"苏州市房地产监测V3"。
- 清洗 `榆林G bug6220` → `榆林G`（`key=yulin-g`），用正则剥 `bug\d+`、`-dist` 后缀；**dist_root / nginx_conf 不动**（nginx 实际路由依赖它们）。
- 建表、加列、回填 `project_key`、写 `deploy_events`，模式照搬现有 `migrate_dashboard.py`。

### 3. API 与展示

- `/api/state` 每项返回 `project_key` + `project_display` + `accounts:[{role,role_label,username,has_password,password_masked,secret_ref_path}]`；密码只给掩码（`****` 或尾 2 位）。
- 新增 `/api/account/password`（POST，复用 `.token` 鉴权）：点击"显示"才 `privacy_resolve` 返回明文，避免明文进快照 JSON。
- 前端 `render()` 改按 `project_display` 分组、标题取干净名；每个 env 卡片加一块账号表：`角色 | 用户名 | 密码(**** + 显示/隐藏切换)`。

**前置条件**：真实账号密码目前隐私库里没有，需要你按 `deploy_env/<key>/<env>/<role>/password` 逐条补录后才会显示（角色用通用 `admin/operator/viewer`，具体清单可后续给）。
