- 强烈反感任务没完成就停下、还要用户输入「继续」才推进的交互，认为这种体验十分糟糕，希望任务在当前轮次内自行走完。
- 对 verify-loop 这类按会话累计计数的门禁，倾向保留提醒与 ledger 记账但降级为 warn，不要用 block 硬拦截拒绝工具调用。
- 期望 agent 被门禁拦截后改变形态继续本 turn（换工具、合并断言、新开会话），而不是把「等用户回复继续」当成应对手段。
- 门禁改动后接受「重启 DSH Web 的新会话才生效」这一前提，无需额外确认。
