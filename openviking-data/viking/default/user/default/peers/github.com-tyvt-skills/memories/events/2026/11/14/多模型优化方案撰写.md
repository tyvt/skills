## 优化方案（三层，按你的优先级：效率>质量>成本）

| 层 | 做法 | 模型分工 | 收益/成本 |
|---|---|---|---|
| **层一 探索外包**（零配置，立刻见效） | 探索动作强制派 `dsh-explore` 只读子代理，主控只收 ≤30 行结论 | 探索子代理用**廉价快速模型**（glm-5.3-flash/deepseek-flash）扛高频读盘；主控空出来做决策 | 效率↑成本↓，质量不掉（只回定位结论）|
| **层二 角色化模型路由**（需改配置，正式落地） | 给 teammate/子代理打通 per-spawn 模型覆盖 → 建 `explore-fast`(廉价只读) / `code-strong`(composer-2.5/gpt-6.1-sol) / `plan-deep`(gpt-6-luna) 三类 | 按任务类型派到对应模型的子代理 | 这才是"探索阶段多模型"的结构性落点 |
| **层三 编排器兜底** | 混合批量任务直接投 `orchestrate op:"full"`，复用其内建工具级池路由 | planner 用 gpt-6，检索用廉价池 | 已验证可用 |

**不建议**：把主控静态换成强模型（高频读盘会拉到贵模型，成本爆、效率反降）；所有子代理都用强模型（探索用强模型纯浪费）。

**推荐落地顺序**：先层一（改 AGENTS.md 探索纪律强化 + 使用习惯，零风险立刻见效）→ 再层二（需计划审批改插件）→ 层三按需。
