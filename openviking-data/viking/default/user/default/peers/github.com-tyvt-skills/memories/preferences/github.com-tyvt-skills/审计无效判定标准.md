- 按真实代码证据判定 `suspect` 记忆；`suspect` 标记本身不代表记忆无效。
- 决定性符号只出现在 memory-migration 归档 dump 而非项目源码中时，标记为 INVALID（不可核验），但先区分“实现后回滚或改名”与“幻觉”。
- 纯流程记录且无代码锚点的记忆在审计中判为无效。
- 无法用真实代码证明或与当前代码矛盾时，归类为 INVALID。
- 决定性被引用的文件或修复在源码中无法确认、且唯一支撑只是记忆本身时，判定为不可核验。
- 记忆描述“删除了某符号、字段或调用的修复”时，通过确认当前源码中该符号的缺失来核验修复后状态（例如 LAST_HANDLE_COLUMNS 已不在 finished/process.vue 中）；缺失可以是有效修复的正向证据，不只是新代码的存在。
- 对 commit-SHA 主张，检查所有相关的本地父仓库和子模块 checkout；若各处的 SHA 都不存在，标记为不可核验的无效。
- 反复出现的 INVALID 原因归为三类：修复未真正落地到当前代码、描述与当前代码矛盾、引用的文件或路径已不存在。
