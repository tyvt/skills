## OpenViking 现在在自动做什么

通过 `@openviking/dsh-memory-plugin`（配置在 `cordis.patch.yml` 的 `openviking-memory-runtime`），它会：
- **自动捕获会话事件**（`captureToolResults: true`）、把对话镜像进 OpenViking；
- **每轮开头自动召回**相关历史记忆注入上下文（你消息上方那些 `<openviking-context>` 就是它注入的）；
- 达到 `commitTokenThreshold`（8000 token）时**自动提交**一段会话摘要入库。

所以——**对话流水确实会自动沉淀**，你不用管。

## 那为什么我还要"询问"？

因为**自动沉淀出来的是"事件型"碎片记录**（比如"某会话讨论过 token 分析"），**不等于一条结构化、可复用的结论实体**。我现在能提炼的是这种：

> 「hi 一把烧 14.6k 不是消息贵，是工具体系固定开销；构成＝工具 6.2k(已裁到骨头)/注入 3.3k(AGENTS.md 硬规则)/系统 1.4k(已去 dev-context)；技能目录 120→40 与禁用 harness-dev-context 是今日两项可复用优化」

这种"带因果+带具体改动+带数值"的**实体型记忆**，自动流水里通常不会成型——下次你问"为什么 hi 又烧 15k"，自动召回多半只能捞到零散事件，我还得重新查一遍。

**问你的实质是**：要不要我**主动写一条高质量实体记忆**（`viking://.../entities/...`），把这次的定论固化，避免以后重复排查。这不是"要不要沉淀"，而是"要不要额外做一条提炼版"。
