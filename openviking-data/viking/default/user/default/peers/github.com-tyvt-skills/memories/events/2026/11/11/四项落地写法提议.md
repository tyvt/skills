## 四件事的落地写法

**1. AGENTS.md（地图）只加四句，不再多**

```text
- 开工：读 worktree-snapshot skill 的输出，禁止现场拼 git status / git worktree list。
- 提交：按 submodule-commit skill 的清单执行，不临场推演提交顺序。
- 纯文案/显隐/单字段：只加载 zentao-analyzer，不加载 flood-page-guard；
  涉及表单/子表/加密接口才加载后者。
- 出现 Option 1/2/3 并列推演 = 缺事实，立刻查一条命令。
```

现有 6KB 里与流程/命令相关的段落删掉，只留指针。这是“现在就停”的那一步。

**2. cost-meter 插件只加两条规则，notice 文案照上面 A/B**

额外一个点：turn 正常结束时，“本轮有 `git commit` 但未跑 token-optimizer”这条要能判定。cost-meter 拿得到本轮工具调用序列，这个条件可实现；但**不要在 notice 里写“必须跑”**，写“收尾自查未做：本轮有提交，未见 token-optimizer 记录”，保留模型判断。

**3. 两个 skill，脚本收命令**

`worktree-snapshot/SKILL.md` 骨架：

```markdown
---
name: worktree-snapshot
description: 开工前一次拉全父仓/子模块/各 worktree 的分支、detached、脏净、HEAD。
---
运行 scripts/snapshot.ps1 <parent-repo>，输出每行：
  <worktree> | <branch|DETACHED> | <dirty count> | <HEAD>
判读规则（写进 SKILL）：
  - 方括号分支 = 该分支实际检出位置；主检出显示 DETACHED 时，改动必须落在分支所在 worktree。
  - 输出作为整轮开工快照，后续只查增量，不重复跑 git status。
```

`submodule-commit/SKILL.md` 只放清单，不放解释：

```markdown
1. 在分支所在 worktree 编辑
2. node ../node_modules/eslint/bin/eslint.js <file> --ext .vue
3. git add <file>; git commit -m "<type>(scope): <desc> (bug <id>)"
4. git push origin <branch>
5. git -C <主检出> checkout <new-sha>
6. git -C <父仓> add <submodule>; git commit; git push
7. git -C <两端> ls-remote origin <branch> 复核
```

脚本里处理 `@{u}`、`head/tail`、编码，Agent 不自己拼。PowerShell 语法错误这类不再靠 lint hook，靠“命令进脚本”消失。

**4. 硬门禁与 Plugin 不动**

- 防汛台账继续只放子模块 `pre-commit`——它是唯一“提交时可判定”的硬约束。
- “禁止在 detached 主检出上改文件”现在只能靠快照 skill + AGENTS 指针，**不做 shell 守卫**；等 DSH 插件 API 能 deny 工具再升级为硬门禁。
- Plugin 等第二个仓库要同一套再打包。
