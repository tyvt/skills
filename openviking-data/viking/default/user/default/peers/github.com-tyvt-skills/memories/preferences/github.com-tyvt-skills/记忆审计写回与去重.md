- 常规审计只回写 verdict/note 等判定字段并 apply，不改记忆正文语义、不提交 git；中间文件只写 ~/.dsh/cache/memory-audit/，不写入项目目录。
- 仅 OpenViking URI 归一化造成重复时清理未审计副本。
- apply 回写后还要确认标题空格未被归一化成下划线并造成重复；若出现未审计副本，先核对 frontmatter 与正文，再保留唯一审计文件。
- apply 偶发 post_persist_embedding_err（Ollama 断连）时，若写入与回读均成功且 verify ok，按成功处理，无需重跑。
- apply 因空格标题 URI 被归一化成下划线、而 verify 用原空格 URI 回读导致误报 skipped 时，先核对两个变体的 frontmatter：若下划线版已有 audit_status、note 与本轮 result.json 一致且 last_checked 为本轮时间，则判定 verdict 已实际落盘，无需重跑 apply（重跑会制造重复写入）。
- stats 的 checked 若已包含该条，可进一步印证 skipped 项 verdict 已生效；判定已落盘后应在简报中标注该条生效，而不是当作仍待审。
- When an apply gets stuck retrying embeddings after an Ollama disconnect, load the OpenViking autostart skill to recover services, stop the stuck background job, wait until both Ollama and OpenViking report healthy, confirm the apply script is idempotent (it checks current status and verifies after writing), then re-run apply instead of assuming partial writes are corrupt.
- After a write or edit times out, verify the node's state with a read rather than retrying the same form; if a write is still needed, switch to a different tool form (for example, from MCP edit to CLI `ov write`).
- Space-named URIs cannot be addressed directly: OpenViking normalizes the space to an underscore even through CLI `ov write` with extended timeout, and MCP edits time out. Treat the resulting skip as benign when the verdict landed on the canonical node and is counted in stats.
