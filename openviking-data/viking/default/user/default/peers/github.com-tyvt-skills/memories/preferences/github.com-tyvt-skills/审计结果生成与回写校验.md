- 回写判定结果时用脚本从 select.json 读取原始 uri/sha、按序号映射判定并生成 result.json，避免中文 URI 编码错误和手工转录全部条目，再执行 apply 回写。
- result.json 是数组；每条判定记录包含 uri、verdict、note、body_sha256_16 字段；apply 按这些字段映射并逐条回写。
- 脚本用 1-based 位置索引判定 note 时，不要在字典中间补缺失键；这会让后续键错位，应调整读取下标（如 base[i+1]）并撤销插入。
- 本地重算哈希与脚本输出不一致时，使用给定的 body_sha256_16，不要用自算约定替换。
- apply 后必须回读校验；URI 含空格会被 OpenViking 规范化为下划线导致回读失败并被跳过，此时判定结论仍应保留；随后核实是否产生重复文件，ov ls 可能分页不列出，直接读原空格 URI 与规范化下划线 URI 判定实际落盘状态。
- 全部回写完成后再统一读取 apply 结果与 stats 覆盖率，核对 skipped 数、哈希回读校验与有效/无效分布。
- apply 汇总 JSON 可能混入 ERROR 行而无法直接解析，可从输出尾部的 applied/skipped/invalid 汇总确认结果；JSON 为多行缩进格式时用 raw_decode 从首个 `{` 开始解析；JSON 前若有 cmd 回显行，直接对输出 grep 目标文件名定位即可。
