## 🟠 重要级

### 1. `ForEach-Object` 被列入查找豁免 → `ForEach-Object { python cost_bill.py }` 可绕过

§3.4 (c)：

```
isSearchHead = head ∈ {find, ls, dir, Get-ChildItem, Where-Object, Select-Object, ForEach-Object}
hasExecToken = 该段含 {--exec, -exec, ..., -Command, Invoke-*, Start-Process}
if isSearchHead and not hasExecToken: pass
```

`ForEach-Object` 的脚本块可以执行任意命令：

```
Get-ChildItem | ForEach-Object { python cost_bill.py }
```

- head = `ForEach-Object` ∈ isSearchHead；
- 段内不含 `-exec/-Command/Invoke-*/Start-Process`；
- 满足 isSearchOnly → **放行**，但脚本块实际执行了 `python cost_bill.py`。

这是 §3.4 硬拦的直接绕过。`ForEach-Object` 本质是 pipeline 执行器，不是"查找/过滤"。

**建议**：把 `ForEach-Object` 从 isSearchHead 移除；或规定"段内含 `{ ... }` 脚本块且块内含 `cost_bill.py` 或执行类 token → 按执行拦"，仅对 `Where-Object`/`Select-Object` 的简单属性比较保留豁免。

### 2. `cost_bill.py` 的查找豁免未覆盖 `grep/rg/Select-String` → `grep "cost_bill.py" logs/` 被误拦

§3.4 (c) 的 isSearchHead 不含 `grep/rg/Select-String`，于是：

```
grep "cost_bill.py" logs/          → head=grep，argv 含 cost_bill.py，isSearchHead=false → 拦 ❌
Select-String cost_bill.py logs/   → 同上 → 拦 ❌
```

这些是**搜索日志里的字符串**，不是执行/读取账单。而真正的账单读取 `grep "bill" .sessions/` 已由 (d) 拦截。当前 (c) 会把"在日志里搜关键词"误拦，与 §3.6 误伤控制目标不一致。

**建议**：isSearchHead 扩为 `dataReadHeads` 中的搜索类（`grep, rg, Select-String, find, Get-ChildItem, Where-Object, Select-Object`），但 `cat/Get-Content` 不算；或把 (c) 的 `cost_bill.py` 拦截限定为"执行/读取脚本"，搜索字符串不拦。同时补 selftest：`grep "cost_bill.py" logs/` 应放行、`grep "cost_bill.py" .sessions` 应被 (d) 拦。

## 🟡 建议级

### 3. currentPath 初始化顺序应 `exec.cwd` 优先，`repoRoot` 仅 fallback

§3.4 写：

```
currentPath = repoRoot or exec.cwd          # 初始工作目录
```

命令实际在 `exec.cwd` 下执行，若两者都存在却取 `repoRoot`，相对 `cd` 会解析错。例：`exec.cwd = repo/sub`，命令 `cd .sessions && cat bill.json`：

- 正确：`repo/sub/.sessions` → inSessions=true → 拦；
- 按 `repoRoot=repo` 解析：`repo/.sessions` → 仍含 `.sessions`，碰巧对；但 `cd ../.sessions` 等会错。

更典型的 `cd sub` 从 `repo/sub` 出发，正确是 `repo/sub/sub`，按 repoRoot 是 `repo/sub`，可能误判。

**建议**：`currentPath = exec.cwd ?? repoRoot ?? undefined`；两者都无时，cd 相对路径不可靠，保守置 `inSessions=true` 或禁用 cd 跟踪并拦读取类，不要 undefined。并处理 `cd` 无参数、`Set-Location -Path .sessions` 的 path 提取（当前"该段 `<path>` 参数"未说明 `-Path` 前缀）。

### 4. §3.4 bash/terminal "按 command 兜底"在字段名不同时不会生效

§3.4 标题写"bash/terminal 的命令字段名以 M3 确认后对齐，**未确认前按 command 兜底并对此类工具同样生效**"。但若 bash/terminal 实际字段是 `script`/`cmd`，guard 取 `arguments.command` 就是 `undefined`，规则**不会生效**，"兜底"无从谈起。

**建议**：改为"未确认前按多字段探测（`command`/`script`/`cmd`）兜底；若均取不到，则 bash/terminal 的 §3.4 为已知未覆盖，待 M3 确认后生效"，把边界讲清楚，避免误以为已覆盖。

### 5. `pathIncludes` 用路径段匹配而非子串

`pathIncludes(currentPath, ".sessions")` 与 §3.4 (d) "任一 arg 含 `.sessions`" 都是子串匹配，`D:\repo\.sessions_backup` 会被误判为在 `.sessions` 下。硬强制下误拦可接受，但建议在文档注明"按路径段匹配（`/\.sessions(\/|$)/`）"或声明"子串匹配，`.sessions*` 一并拦"作为已知行为。

### 6. §3.1 公共前置对 `npx eslint --version` 的"bin 直接跟"需明确

`npx eslint --version` 的 bin 是 `eslint`，`--version` 跟在 eslint 后，应放行；但"任一此类 bin 直接跟 --version"对 `npx` 而言 `npx --version` 是 npx 版本，`npx eslint --version` 是 eslint 版本，两者都应豁免。建议注明"对 `npx/pnpm exec` 先剥前置再取 bin，再判 `--version/--help`"。
