# zhi1 注册成功分支验证码刷新导致凭据弹窗
太仓物管前端 zhi1-web-admin 企业注册成功后会额外刷新一次验证码，此时页面已进入凭据弹窗，该刷新被视为弹窗最可能的触发点。

## 现象
- 只读探测未发现注册页初始请求返回 401，排除初始请求鉴权失败触发弹窗。
- 2026-11-15 用正常鼠标式点击复测：账号未创建成功，提交被凭据弹窗拦住；响应监视器显示真正的 401 来源是 `/company/base/add`，并非验证码刷新，原先「验证码刷新触发弹窗」的假设被推翻。
- 正在追查是哪个界面处理器发出了 `/company/base/add` 请求，定位后再据此修正。
- 源码显示注册成功后会额外刷新一次验证码，而此时页面已经进入凭据弹窗。
- 该刷新没有后续用途，曾被列为最可能的弹窗触发点。

## 处理方案
- 只移除注册成功分支中的验证码刷新，保留失败分支的重试逻辑。
- 修改后改用正常鼠标式点击进行验证，不使用脚本化点击。

## 归属
- 所属项目：太仓物管前端 zhi1-web-admin，禅道任务 2334 企业注册流程原型还原范围。
- 与「验证码默认隐藏」模式相互独立：本模式只涉及成功分支的多余刷新。
