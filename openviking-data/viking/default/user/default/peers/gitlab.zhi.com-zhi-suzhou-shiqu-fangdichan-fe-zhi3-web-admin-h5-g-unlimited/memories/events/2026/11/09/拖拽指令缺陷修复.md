# Summary
修复共享指令 v-dialogDrag 将 onmousedown 挂在 .el-dialog__header 导致关闭按钮 mousedown 冒泡重定位弹窗、浏览器取消 click 使 X 无法关闭的缺陷。改动 src/directives/dialog/drag.js，在 onmousedown 内对 .el-dialog__headerbtn 直接 return，保留关闭按钮 click。该缺陷影响所有 el-dialog/zs-dialog 调用方。
# 2026-11-09 (Monday) ChatLog:
**assistant [peer=gitlab.zhi.com-zhi-suzhou-shiqu-fangdichan-fe-zhi3-web-admin-h5-g-unlimited]**: ...**解决备注（落于 zt_action.comment，HTML）**要点：
- **根因**：共享指令 `v-dialogDrag` 把 `onmousedown` 挂在 `.el-dialog__header`，关闭按钮 `.el-dialog__headerbtn` 位于 header 内，其 `mousedown` 冒泡到拖拽处理器，导致 `.el-dialog` 被重定位，浏览器随后取消后续 `click`，`handleClose`/`closePreview` 不触发，X 无法关闭；该缺陷影响所有 `el-dialog`/`zs-dialog` 调用方。
- **修复**：指令头部 `onmousedown` 内对 `.el-dialog__headerbtn` 直接 `return`，不再重定位弹窗，保留关闭按钮 `click`；头部拖拽与 resize 手柄不受影响（改动 `src/directives/dialog/drag.js`）。
- **验证**：worktree 构建后部署临时 nginx 站点，Playwright 复现脚本确认关闭按钮 `click` 已触发、预览关闭（修复前 `click:0`/`closed:false`）。...
