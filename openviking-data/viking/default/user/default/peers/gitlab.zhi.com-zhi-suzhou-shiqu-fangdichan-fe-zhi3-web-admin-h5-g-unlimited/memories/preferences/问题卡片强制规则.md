# 交互偏好：待定事项必须用问题卡片

> 用户明确要求（2026-11-02）：「需要我定的和确认的、问题的，一定要有问题卡片，不要直接纯文本返回给我」。

## 规则

凡属以下三类内容，**必须调 `ask_user_question` 弹卡片**，禁止在正文用纯文本问句：

| 类型 | 具体场景 |
|---|---|
| 需要用户**定** | 方案取舍、技术选型、优先级、范围确认 |
| 需要用户**确认** | 删数据、强推、回写禅道、合并分支、部署、改公共组件 |
| 向用户**提问** | 环境确认、复现路径、账号凭证、字段含义、缺接口文档 |
| 收尾**待定事项** | 是否提交/推送、是否清理临时文件、是否继续下一项 |

## 不适用（可以纯文本）

已完成的结论、已执行命令与结果、未验证项说明、风险提醒、进度汇报。**汇报不是提问。**

## 写法

- 一次可多题，但**每题只一个决策点**；风险确认单独成题
- 2–4 个真实可执行选项，推荐项放首位并标「（推荐）」，写清影响
- 题面写清背景 + 为什么要你定 + 各选项后果
- 禁止：正文末尾写“要吗？”了事；先纯文本问一遍再补卡片

## 反例（2026-11-02 bug 6023 收尾）

把「是否提交推送 / 是否清理临时文件 / 是否回写禅道」三个待定事项写成正文问句，用户只能逐条打字回复。正确做法是一张卡片三题。
