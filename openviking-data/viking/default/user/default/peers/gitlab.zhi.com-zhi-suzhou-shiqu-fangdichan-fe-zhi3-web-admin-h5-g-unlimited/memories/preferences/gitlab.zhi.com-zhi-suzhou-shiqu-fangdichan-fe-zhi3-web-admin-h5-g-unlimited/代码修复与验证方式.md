- 修复问题时倾向最小改动，并主动回退可能引入回归的中间改动（如会让兜底路由指向错误菜单的注册表改动）。
- 校验改动优先用单文件 eslint 加构建（exit 0）判断，把全量 lint 的存量红基线视为与本次改动无关。
- 编排器对 npm run lint 反复失败时，改用窄形态（只对改动的 .vue 文件跑单文件 eslint）。
- 改动前先核实真实数据与解析链路（业务库变更单、菜单表 busCode、待办跳转 query 参数），再做实机验证。
