# 禅道备注优先于代码排查（bug 6023 教训）

> 类型：可复用经验🔵｜来源：2026-11-02 bug 6023 楼幢同步缺陷｜适用：所有禅道 bug 处理

## 一句话教训

**拿到禅道链接后，第一个查询必须是 `zt_action` 的评论，而不是 `zt_bug` 的 steps，更不是直接翻代码。**

后端、测试、产品对需求/接口的变更全都写在备注里，`zt_bug.steps` 只保存提单时的原始描述。只看 steps 就去分析根因，会对着**已经作废的接口**死磕。

## 标准动作（开工第一步）

```sql
-- 连接：新禅道（4027e274-2f63-49e6-8a8d-5f25eb1e6c5e）
SELECT id, actor, action, date, LEFT(comment,1000) cmt
FROM zt_action WHERE objectType='bug' AND objectID=<id> ORDER BY id;

-- 命中接口/入参说明时，分段读全（comment 按 200 字截断）
SELECT SUBSTRING(comment,1,300) c1, SUBSTRING(comment,301,300) c2, CHAR_LENGTH(comment) len
FROM zt_action WHERE id=<actionId>;
```

判断规则：

1. `action='commented'` = 需求/接口变更，**必须逐条读完再动手**。
2. `action='assigned'` 记录当前该谁处理；`extra` 字段常是被指派人。
3. **评论时间晚于 opening 的，优先级高于 steps**。
4. 接口路径与入参**原文抄录**，不要转写、不要凭记忆。
5. 评论带 `{fileID}.png` 时用 REST API 取图（Token 鉴权绕过强制改密）。

## 附带教训：不要基于猜测的方法/环境下结论

- 新接口在网关层统一返 **401**（认证先于路由），无法用 HTTP 探测确认 GET/POST——只能依据**仓库内同名接口的现有调用**判定（本例 `ExtractDialog.vue` 用 `$post`）。
- 这类「无法验证」的推断必须在交付时如实标注为未验证项，不要写成已确认。
- 截图里的业务数据（楼幢 `B3205060000000016`）可能**不在当前连接的库**（客户测试环境 vs dev），不能因为查不到就判定数据缺失。

## 附带教训二：按截图定位页面，别按方法名猜（2026-11-03 二次返工）

**事故**：上一轮改了 `building/building/detail.vue` 的 `synchronizeHouse()`，交付后用户问「备注让改成 extractBuildingBySurveying，为什么代码用的是 extractBuilding」——因为 bug 截图对应的其实是**另一个页面** `projectManagement/buildinginfo/detail.vue`，它的 `handleSync()` 还在调旧接口 `extractBuilding`。

**两个页面都有「同步」按钮，极易混淆**：

| 页面 | 按钮 | 方法 | 原接口 |
|---|---|---|---|
| `projectManagement/buildinginfo/detail.vue`（**bug 6023 截图这个**） | 「同步」+ `el-icon-refresh` | `handleSync()` | `POST /building/building/extractBuilding` |
| `building/building/detail.vue` | 「同步房屋信息」 | `synchronizeHouse()` | `GET /building/syncCoManagement/syncHouseAndObligee` |

**正确做法：用截图里的界面元素反查页面，而不是靠 `grep 同步` 命中的方法名猜。**

1. **看左侧菜单名与页签**：截图菜单「楼幢维护 / 项目备案申请 / 单元管理 / 户室查询」、页签「楼幢维护 / 测绘成果变更 / 户室查询」→ 属 `projectManagement` 模块，不是 `building` 模块。
2. **看按钮文案与图标**：「同步」+ 刷新图标 → 与 `icon="el-icon-refresh"` 精确匹配；「同步房屋信息」是另一个页面。
3. **反查路由**：`grep -n '楼幢维护' src/router/` 或查菜单配置，把菜单名映射到具体 vue 文件路径。
4. **`grep` 出多处命中时，必须逐处核对所属页面**，不要取第一个语义相近的就动手。

**另一条**：同一业务动作（楼幢同步）在本项目有多个入口时，后端换接口通常**所有入口都要换**。改完一处应主动全仓 `grep` 旧接口路径，确认没有遗漏的调用方——本次即 `extractBuilding` 在 `api/lpgl/buildinginfo.js`、`projectManagement/buildinginfo/detail.vue` 各有一处。
