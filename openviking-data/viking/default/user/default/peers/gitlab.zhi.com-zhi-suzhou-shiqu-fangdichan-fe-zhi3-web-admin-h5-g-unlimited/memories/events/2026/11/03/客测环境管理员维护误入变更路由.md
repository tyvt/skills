**assistant [peer=gitlab.zhi.com-zhi-suzhou-shiqu-fangdichan-fe-zhi3-web-admin-h5-g-unlimited]**: 这不是保存按钮写死了变更接口。客测打开的页面本身就是「管理员变更」，所以新增走 `/add`、查看走 `/detail`，都落在 `companyAdminChange` 上。

维护和变更共用 [detail.vue](zhi2-web-admin/src/views/company/companyAdmin/detail.vue)。变更入口 [developer/detail.vue](zhi2-web-admin/src/views/company/companyAdminChange/developer/detail.vue) 写死了 `:is-change="true"`。一旦 `changeActive` 为真，`businessName` 就从 `companyAdmin` 换成 `companyAdminChange`，通用保存会拼出 `POST /company/companyAdminChange/add`。变更单本来不走这个新增接口，而是已有管理员点「变更」后由 `getLast` 生成，所以这里返回 400。

截图上侧栏是「管理员维护」，页头却是「管理员变更」，说明路由已经进了变更菜单。开发库菜单是对的：

| 菜单 | 组件 |
| --- | --- |
| 管理员维护详情 | `company/companyAdmin/developer/detail`，路径 `companyAdmin/:tableid` |
| 管理员变更详情 | `company/companyAdminChange/developer/detail`，路径 `companyAdminChange/:tableid` |

客测请对一下地址栏和 `SYS_MENU`：

1. 地址含 `companyAdminChange`，就是进了变更路由。
2. 「管理员维护」详情的组件必须是 `company/companyAdmin/developer/detail`，路径必须是 `companyAdmin/:tableid`。
3. 若维护详情被配成变更组件，或两条详情的 path 都是 `companyAdmin/:tableid`，先注册的变更路由会把维护的新增和查看都吃掉。开发库租赁那条已经有 `companyAdmin:/tableid` 这种错 path，客测开发企业很可能是同一类数据问题。
