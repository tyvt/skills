- 禅道工时日志（`zt_effort.work`）要按任务或缺陷的实际工作内容填写，不接受「[T]提交:仓库/分支·hash·时间」这类提交格式。
- 任务详情描述缺失时，直接用禅道任务标题作为工时日志内容。
- 偏好用定时任务自动处理当天工时记录，而不是事后人工补填。
- 缺失的历史工时日志可以事后批量补录，采用自动模式、内容取禅道任务标题，不必逐条确认。
- 补录时按每天实际处理的任务分配工时；单日总工时 T 按当天最后一次代码提交时间换算：8h 保底，若最后提交晚于 18:00 则 T = 8 + 超出小时数（如最后提交 20:00 → 当天 10h）；周末（无工时动作的日期）不填。
- bug 转成的任务工时不再固定 0.5h，按实际用时和任务复杂度估算。
- 单日总工时 T 确定后，按解决时间顺序在当天各条工时上均分，用 0.1 小时整数倍微调凑整到 T；禁止出现 0.01 精度（如 0.53/0.54/0.55），8h 分 15 条只能是 10 条 0.5 + 5 条 0.6。
- 当天修复的 bug 也要转成禅道任务并在新建任务上记工时，不能只核对或修正已有工时日志的格式。
- 为凑到当天总工时 T 而调整工时时，保留已有工时行并调整其时长，不删除。
- 工时合计要用独立连接复核，条数与总和都对上才算完成。
- 自动化定时任务的执行标准被修改后，要同步更新该定时任务的 prompt，后续同类任务都按新标准执行。
