## 三、最大成本黑洞：Vite build 卡死（step 19–38，20 步 / 约 1/3 步数）

时间线还原：

1. **step 19**：启动 `npm test 2>&1 | Out-String -Width 200 | Select-Object -Last 25`——用了**最糟糕的缓冲管道**。`--logLevel error` 本就静默，再套 `Out-String | Select-Object -Last` 意味着**进程不结束就永远没输出**。
2. **step 22/25/26/27**：`job_output` 分别等 120s / 180s / 240s / 300s，累计空等约 14 分钟，**无任何诊断动作**。
3. **step 28**：kill，读 `package.json` 才发现 `test = node scripts/vite-build.mjs build --mode test --logLevel error`。
4. **step 29**：重新启动，`Out-File` 到 `.tmp-bug6402\build.log`——**目录不存在，`Out-File` 不建目录，build 根本没跑**（这是第二次失败）。
5. **step 31**：第三次启动，改到 worktree 根。
6. **step 33–37**：又一轮 `job_output` 轮询 + 查进程，终于看到 PID 25360 **CPU 0.05s、内存 47MB、日志冻结在 `version.json`** → 确认 hung。
7. **step 38**：kill。

**四个根因：**
- **不知道"缓冲管道 + 静默日志 = 永远无输出"**，第一步就选错命令形态。
- **轮询前不检查进程活性**。`Get-Process` 看 CPU/内存，一眼就能判定 hung，本可以 1 步结束，却等了 4 轮。
- **写日志前不 `Test-Path`/`New-Item`**，第二次启动直接空转。
- **卡死期间反复 `job_output`**，每次都带着已增长到 70k+ 的完整上下文返回，**直接触发了一次 compaction**（seq 258），这是"build 不烧 token 但烧 200k+"的真正机制。

**优化：**
- build 前先 `New-Item -ItemType Directory -Force` 日志目录；用 `Start-Process -PassThru` 拿 PID，启动 30s 后查一次 `CPU`，为 0 直接 kill，**不进入 job_output 长轮询**。
- `--logLevel error` 下**禁止用 `Out-String | Select-Object -Last`**，改 `*>` 流式重定向。
- 更重要：**本机 vite 构建已知会卡死**（本次 + 历史那次共两次），应把这条写进 `AGENTS.md`/`flood-page-guard` 的 known-issues，**默认不在本会话跑 `npm test`，改用 CI 或直接标注"构建未执行"**。这次最后确实标注了，但已经是花了 20 步之后。

- **step 39/40**：`GIT_EDITOR='true' git rebase ...`——**bash 语法**，PowerShell 报 `CommandNotFoundException`，rebase 没跑；step 40 改用 `$env:GIT_EDITOR='true'` 才对。这恰好是 AGENTS.md 第 7 条明写的规则，**模型知道规则但写错了形态**。
