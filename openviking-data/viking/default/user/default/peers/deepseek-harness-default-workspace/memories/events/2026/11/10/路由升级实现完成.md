## 改动

**`config.yaml`** 新增 `scheduling` 段：工作日（ISO 周一=1）的 `09:00-12:00`、`14:00-18:00` 为 DeepSeek 峰时，`planner_use_free_hy3` 与 `peak_use_glm_as_fallback` 两个策略开关默认开启。`planner` 池改为 `openrouter/tencent/hy3-preview:free` 主力、`cursor/grok-4.7@256k` 兜底；`file_reader` 和 `code_editor` 都把 `workbuddy/glm-5.3-flash` 放进池里。

**`src/config.py`** 新增 `DeepSeekPeakHours` 与 `SchedulingConfig` 两个 dataclass，`load_config` 解析 YAML 后挂到 `OrchestratorConfig.scheduling`，缺段时回落默认值。

**`src/router.py`** 新增 `_is_deepseek_peak_time`（按本地时间判断，闭区间起点、开区间终点）和 `_get_effective_models`。峰时且策略开启时，`file_reader` / `code_editor` 跳过所有 `deepseek-v4.1-flash` 并把 `glm-5.3-flash` 提到队首；谷时、周末或策略关闭时保持原序。`run_tool` 增加 `force_model`（只调指定模型，规划兜底用）和 `now`（测试注入时间），冷却排序仍作用于有效池。

**`src/graph.py`** 的 `node_plan` 在 `planner_use_free_hy3` 开启时调用 `plan_needs_fallback`：输出解析不出 JSON、拆出 0 步、或用户需求命中高复杂度关键词（死锁、深度推理、疑难、竞态、内存泄漏、递归爆栈、分布式事务）时，trace 输出 `[WARNING] hy3 规划异常或不够详尽，已自动升级给 grok-4.7 重新规划`，再以 `force_model='cursor/grok-4.7@256k'` 重规划一次。
