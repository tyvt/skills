## 三层配置（优先级从高到低）

| 层 | 位置 | 作用范围 |
|----|------|----------|
| **环境变量** | `OPENVIKING_*` | 本机全局（若你在启动 DSH 时注入） |
| **Profile patch** | `~/.dsh/profiles/web/cordis.patch.yml` → `openviking-memory-runtime` | **所有走 web profile 的会话**（你已配的 commit 8000、score 0.40 等） |
| **工作区文件** | `<cwd>/.openviking/config.json` | **仅当该会话 cwd 落在这个目录（或子目录）时** |

`ovcli.conf` 主要是 **URL/账号**，不是 recall/capture 细项；长期 recall/capture 仍以 **cordis + 工作区文件** 为主。

---

## 全局能做什么（不用 per-project 文件）

在 `cordis.patch.yml` 里已经/可以统一设：

- `commitTokenThreshold`、`captureToolResults`
- `recallMaxTokens`、`scoreThreshold`、`recallDedupTurns`
- **`recallPeerScope: all`**（跨项目召回）或 **`actor`**（只召回当前 peer）

若你希望 **全机默认「改 bug 优先本仓库记忆」**，可以**只改全局**：

```yaml
recallPeerScope: actor   # 全局 actor，所有 git 仓库会话都优先 peer
```

Git 仓库的 **peer 仍由 `origin` 自动推导**，不需要每个项目写 `peer.id`。

---

## 什么时候才需要 per-project `.openviking/config.json`

| 场景 | 是否需要 |
|------|----------|
| 统一写回阈值、统一 score、统一 actor/all | **否**，cordis 即可 |
| **同一台机器、同一 repo 不同目录要不同 peer** | 是 |
| **非 git 目录**（如 `default-workspace`）要固定 peer / 全库召回 | 是（或设 `OPENVIKING_PEER_ID`） |
| 某项目要 **更严 score / 更小 max_items**，其它项目保持默认 | 是（局部覆盖） |
