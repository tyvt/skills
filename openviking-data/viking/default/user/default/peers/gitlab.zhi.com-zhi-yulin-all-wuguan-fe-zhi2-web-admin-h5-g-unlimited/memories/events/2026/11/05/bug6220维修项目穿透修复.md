**assistant [peer=gitlab.zhi.com-zhi-yulin-all-wuguan-fe-zhi2-web-admin-h5-g-unlimited]**: ...**问题**：【榆林本地测试环境】系统监控-综合大屏，维修资金大屏 - 维修项目点击跳转，穿透后的数据与实际不一致（大屏显示 2 条，穿透后列表仅 1 条）。

**根因**：
大屏「维修项目」统计的是**全部已备案(bizState=2)**项目，穿透跳转到【维修资金-维修项目-维修项目立项】时，目标页 [maintenanceProject/index.vue](<zhi2-web-admin/src/views/maintenance/maintenanceProject/index.vue>) 的 `queryParams` 默认 `currentState = '00'`（当前节点=项目立项）。`listMixins` 穿透时只把 URL 上的 `bizState=2` 写进查询参数，**没有清除页面默认的 `currentState`**，导致列表被同时按「当前节点=项目立项」过滤，数量与大屏不一致（正是截图里红箭头指出的「当前节点=项目立项」筛选）。

**修复**：在目标页重写 `applyScreenQuery()`，调用原 mixin 逻辑后再 `this.$set(this.queryParams, 'currentState', undefined)` —— 大屏穿透时不再带「当前节点」默认筛选，只按已备案展示，符合提单期望「不需要带上当前节点的筛选」。

**验证**：ESLint 通过；`npm run build` 成功；本地 nginx 站点 `http://127.0.0.1:8109` 加载新构建，产物 chunk 含 `applyScreenQuery(){…currentState",void 0}` 逻辑。
