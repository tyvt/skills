## 根因定位

目标文件：[detail.vue](zhi2-web-admin/src/views/benefit/pubAllotNotice/detail.vue)

查看态由 `contentInfo` 计算属性渲染（[L683–747](zhi2-web-admin/src/views/benefit/pubAllotNotice/detail.vue#L683-L747)），它的合同分支 `displayAsWithContract` 只 push 了 8 项：

```
支出合同编号 / 支出合同名称 / 支出合同金额 / 累计支取合同金额 / 剩余可用合同金额 / 收款人 / 收款账号 / 收款开户行
```

**`noticeAmount`（本次支取合同金额）在这个分支里根本没有被 push** —— 编辑态的模板 [L75–79](zhi2-web-admin/src/views/benefit/pubAllotNotice/detail.vue#L75-L79) 有这个字段（`v-model="form.noticeAmount"`），但查看态的 `contentInfo` 漏掉了它。同时 `haveWithdrawAmount` / `remainWithdrawAmount` 恒为 `-`，是因为合同选定时 [openExpenditureContractDialog L1106–1107](zhi2-web-admin/src/views/benefit/pubAllotNotice/detail.vue#L1106-L1107) 才赋值，`getDetail()` 拉回的详情里这两个字段没有值，也没有任何兜底赋值。

### 已确认（有证据）

1. **直接原因** — [detail.vue](zhi2-web-admin/src/views/benefit/pubAllotNotice/detail.vue) 的 `contentInfo` 计算属性（L705–737）在 `displayAsWithContract` 分支中 push 了 8 项，但**唯独漏掉 `noticeAmount`**。而编辑态模板（L75–79）里确实有这个字段。因此保存后，页面从编辑态切换到查看态时，该行就消失了。

2. **累计/剩余可用合同金额显示 `-`** — `haveWithdrawAmount` / `remainWithdrawAmount` 只在 `openExpenditureContractDialog` 选中合同时赋值（L1106–1107）；`getDetail()`（L888–905）用 `response.data` 整体覆盖 `this.form`，对这两个字段没有兜底。

3. **苏住房同源实现存在同一缺陷** — 已逐行比对确认，它是 task 2393 的移植来源。

4. **更关键的发现（数据库证据）**：
