## 所以真正的报错定性

- 这是个 **`Error` 对象被反复抛出**：每次都是 vue-router `replace` 里 `console.error(l)` 后走 `replace/assign` 那套——截图里 `i / replace / s / [native code]` 的循环，是 **vue-router 在重试/递归导航**。
- 也就是说：**中转页在 `main.ts` 里设置 token 后触发了一次路由跳转，而这次导航失败了（或反复失败），每次失败都被 `console.error` 打出来，形成你看到的刷屏红色栈。**
- 这条路**不会**因为 `decodeURIComponent` 报 `URIError`——我核对了线上包，uni 里的 `decode` 都有 `try/catch` 兜底（`function decode(e){try{return decodeURIComponent(""+e)}catch(t){}...}`），**不会抛出来**。我上轮怀疑的 `URIError` 方向，**在线上包里被排除**。

## 那“token 脏值”影响什么

`main.ts` 拿到的 `token` 不会在解码时炸，但会：
1. 存进 `userStore.token`
2. 触发首次导航/接口（interceptor 带 `Authorization: Bearer <脏token>`）
3. 后端 401/403 → 前端路由守卫/请求失败回调里调 `router.replace(...)` 回登录页
4. 兜底页又判断无有效登录态 → **再跳一次** → 循环 replace

**这正好解释了你截图里大量重复的路由 `replace` 栈帧**，而不是白屏死循环代码 bug。
