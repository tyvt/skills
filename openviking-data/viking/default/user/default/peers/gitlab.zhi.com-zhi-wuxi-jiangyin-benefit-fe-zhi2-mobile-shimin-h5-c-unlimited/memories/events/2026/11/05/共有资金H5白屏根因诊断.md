- 编译源 [src/utils/url.ts](src/utils/url.ts) 里确实存在「字符串 ↔ URL 解码」链：`getQueryParam('token')` → `decodeURIComponent`，被 [src/main.ts](src/main.ts) 的 `createApp()` 开头读取，与栈里的 `i()/s()/replace()` 形态吻合

## 诊断结论（最终）

### 1. vConsole 生产/测试包永久开启（配置缺陷，已确认）
- [vite.config.ts](vite.config.ts) 第 62–69 行：`enabled: VITE_DELETE_CONSOLE == 'false'`
- [env/.env.production](env/.env.production)、[env/.env.test](env/.env.test) 均为 `VITE_DELETE_CONSOLE = false` → 构建进去就必开
- 只有 [env/.env.development](env/.env.development) 也是 false；换句话说**三个环境全开**，没有一处关闭
- 后果：vConsole 面板常驻 + `WEBREVIEW` 角标；控制台盖住登录页

### 2. 红色栈是"假象"，不是死循环
- 栈帧 `i:34:6703 / replace:34:7068 / s:34:5530 / replace@[native code]` 是**同一调用链被快照重复渲染**
- `34:7068` 经换算命中 `vue-router` 的 `encodeParam`：`return null==e?"":encodePath(e).replace(SLASH_RE,"%2F")`
- 即正常的 `encode/decode` + `String.replace` 调用链；没有 `RangeError: Maximum call stack` 之类循环爆栈特征
- 之所以看起来"无限重复"，是因为 bundle 里有 **283 KB / 294 KB 的巨型单行**，vConsole 把长栈拆行输出后，错误正文被顶出首屏

### 3. 真正要排查的报错点（建议自行核对）
按调用顺序，最可能的抛错源头是 **URL 参数解码**：

1. [src/main.ts](src/main.ts) `createApp()` 开头：
   ```ts
   const initToken = getQueryParam('token')
   ```
2. [src/utils/url.ts](src/utils/url.ts) `getQueryParams()` 第 12 行：
   ```ts
   queryParams[decodeURIComponent(key)] = decodeURIComponent(value)
   ```
   —— 若 URL 里 `token`/`option` 含未转义的 `%` 或残缺编码，`decodeURIComponent` 会抛 **`URIError: URI malformed`**，`createApp` 中断 → 登录页白屏
3. 最新提交 `00a1826 feat(login): 写死登录 option 参数值便于 C 端测试` 很可能让 URL 参数带上特殊字符，是本次最可疑的诱因

**建议核对方式**：在被测 URL 上直接把地址栏完整 URL 拷出来，检查 `?` 后是否有孤立 `%`、`%E4` 这类半截编码；或用 `decodeURIComponent` 手动跑一遍整串，能立刻复现 `URIError`。

### 4. 顺带一个体验问题
即使不改代码，登录页一片空白也是异常表现——正常情况下应有表单。若本次预期是"带 token 直接进主页"，那白屏说明**路由/登录态判断在异常参数下没兜底**；这部分定位在 [src/main.ts](src/main.ts) 的 `createApp()` 与登录页组件初始化，未对 `getQueryParam` 失败做降级。
