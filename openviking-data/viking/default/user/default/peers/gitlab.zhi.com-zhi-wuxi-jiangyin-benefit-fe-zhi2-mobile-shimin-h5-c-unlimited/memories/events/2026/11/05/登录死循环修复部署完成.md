## 根因（已实测坐实）

我直接请求线上 `loginByUid` 接口：**用代码里写死的那个 `TEST_LOGIN_OPTION` 请求，后端返回 401**（option 已失效）。由此形成死循环：

```
线上首页 → /pages/login (中转页 login.vue)
  onLoad 永远用写死的失效 option 调 loginByUid
    → 后端 401
      → http.ts 里 401 一律 uni.redirectTo('/pages/login')  ← 跳回自己
        → onLoad 又用同一个死 option 调接口 → 又 401 → 又跳自己 …
```

每轮 vue-router 的 `replace` 都 `console.error`，就是你截图那屏无限红色栈——**是"结果"，不是死循环代码 bug**。

两处缺陷叠加：
1. **[src/pages/login.vue](src/pages/login.vue)**：写死 `TEST_LOGIN_OPTION`、完全不读 URL 里的真实 `option`
2. **[src/http/http.ts](src/http/http.ts)**：401 → `redirectTo('/pages/login')`，而 `/pages/login` 正是中转页本身 → 原地自跳

## 修复内容（3 个文件）

| 文件 | 改动 |
|---|---|
| [src/pages/login.vue](src/pages/login.vue) | 优先 `getQueryParam('option')` 读三方登录真实 option，读不到才回退测试值；登录失败/无 token 统一回落**账号密码登录页** `/pages/login/index`，绝不回流本页 |
| [src/http/http.ts](src/http/http.ts) | 401 重定向目标由 `/pages/login` 改为 `/pages/login/index`；**登录类接口（loginByUid/ctAuth）的 401 不再自动重定向**，交由调用方处理；加 `redirectingLogin` 防重入，`httpFile` 同步修正 |
| [src/utils/url.ts](src/utils/url.ts) | `decodeURIComponent` 用 `safeDecode` 包裹，脏 `%` 参数不再抛 `URIError` 中断 `createApp`（防白屏兜底） |
