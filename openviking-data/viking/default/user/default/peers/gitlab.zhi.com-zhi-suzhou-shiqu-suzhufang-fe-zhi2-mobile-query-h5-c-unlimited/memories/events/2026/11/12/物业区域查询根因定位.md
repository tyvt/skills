**assistant [peer=gitlab.zhi.com-zhi-suzhou-shiqu-suzhufang-fe-zhi2-mobile-query-h5-c-unlimited]**: 查到根因了，是**前端预期和后端接口不匹配 + 测试库没有这个小区**两层原因：

## 1. 不输关键词时必然「暂无可选区域」（接口限制）

C端进入页面聚焦时，前端会调 `loadComplexOptions('')`（`src/pages/inspection/index.vue:75`），期望“默认展示前10条”。但后端接口：

- `FloodCommonController.complexOptions`（`苏住房后端/.../flood/common/controller/FloodCommonController.java:85`）签名是 `@RequestParam String complexName`，**必传**；
- 代码第 86-88 行：`complexName` 为空时直接 `return JsonResult.success(Collections.emptyList())` —— 这是刻意设计（注释写明“G端可看全部；物业侧要按授权过滤走B端接口，不在本接口”）。

所以空关键词永远返回空列表，前端注释里也承认了这一点（`flood.ts:447`“若后端需要关键词则退回空列表”），但页面交互上没提示用户“必须输入名称搜索”，看起来就像“查不到”。

## 2. 输关键词也搜不到「星耀商务中心」（数据不存在）

接口的搜索逻辑（`ComplexServiceImpl`）会：
- 只搜**已备案**小区（`biz_state=2`）；
- 且只搜**有住宅（purpose=1）房屋**的小区（`t_house → t_building → t_complex_range` 链路）；
- 按 `complex_name / record_name / promotion_name / legal_name` 四个名字模糊匹配。

我查了测试库（苏住房测试 / ZHISHU_PROPERTY.T_COMPLEX）：**库里根本没有「星耀商务中心」**，只有「星耀之光大厦」和「星耀君庭」。已备案小区有 5527 个，所以搜其他真实存在的小区名是可以搜到的。

另外前端把接口异常 `catch` 后统一渲染成「无匹配区域」（`inspection/index.vue:68`），真实报错会被掩盖。

## 建议修法（二选一）

1. **改前端**（推荐，改动小）：空关键词聚焦时不发请求，placeholder 改成“请输入小区名称搜索”，避免误导；
2. **改后端**：`complexName` 为空时返回默认前 10 个已备案小区，兑现“默认展示前 10 条”的交互。
