## 一、Bug 本质
标题：**管理APP 街镇/区县/市级检查中，需要能修改评价等级**。
- 结果图（24130）：顶部总评级 `市标二级`，但「01 综合能力」分组标签是 `市标三级`，且标签只读。
- 期望图（24132）：需求文档明确「评价标准（综合能力）」是**下拉单选、必填、按物业区域带出后支持编辑**，枚举 市标一级~五级；评价等级按五类中最低等级生成，检查频次联动。

对应前端就是本项目手持端检查填写页 `src/pages/project-check/form/index.vue`（截图中的路南苑、进度 0/5、好(1)/较好(0.75) 选项与页面完全吻合）。

## 三、实现要点（结合 G端/后端）
1. **打开入口**：恢复 `form/index.vue:410-415` 的 picker，用 `form.levelEditable && currentCategory` 控制（仅街镇及以上可见，后端已给标志），复用 `onLevelChange`。这是本 bug 的直接修复点。
2. **本地草稿模式的坑（关键）**：bug 流程是「发起检查→开始检查」，此时 `isLocalDraft=true`（:364），`changeLevel` 只做 `recalc()+persistDraft()`（:186），**不会重新加载新等级对应的考评题目**——会出现「等级改成三级、题目还是二级」的新不一致。要正确重载，需在改等级后用新 grade 参数重调 `startCheck`。但 `store.startCheck()` 目前不传 grade，而后端 `StdEvalCheckInitDto` 已支持——这是 C端需补的一处入参扩展（后端零改动）。已落库单据走 `save()+load()`（:187）则天然从 `/form` 重取，无此问题。
3. **等级/频次口径**：与 G端 `constants.js:172-188`、后端 `:2251-2264` 一致（1/2→每半年，3/4→每季度，5→每两月），前端不要另算，沿用 `evalLevelOptions` + 后端返回值即可。
4. **回写时机**：后端 `update()` 只允许 `PENDING_SUBMIT`（:621），改等级须在提交前完成，这与「开始检查中修改」的场景吻合。

## 四、结论
**后端能力齐备、零改动；G端有现成交互范式；C端改动集中在 `form/index.vue` 一处**——放开被注释的 picker，并补齐本地草稿下按新等级重载题目（扩展 `startCheck` 传 grade 参数）。
