- 修改持仓面板或组合文件前必须先通过计划审查（审批门），审查未通过就停在审批门前，不直接改文件。
- 计划审查器卡住（如 120 秒无输出）时，先检查审查任务状态，确认无遗留审查任务后再原样重送同一计划一次。
- 若重送后审查仍卡住，则保留已写好的计划文件并暂停执行，说明阻塞点并等待审批，不绕过审批强行推进或直接改代码。
- 送审前会先确认编排器能正常列出审查池，作为审查服务可用的判断依据。
- 再次送审前习惯先把计划精简压缩到必要的少数章节，只保留关键约束条款（如仓位方案比例、集中度上限、数据库回滚要求），再按计划路径重新送审，而不是直接送审冗长版本。
- 计划审查器对最新版完整计划超时且确认无遗留后台任务后，会改用范围更窄的送审请求（例如仅提交相对已通过版本的变更摘要）继续推进，而不是反复重送同一份完整计划。
- 计划审查通过后若确认弹窗超时、未收到明确选择，视同未确认，不据此改代码，先按工具故障规则处理提问工具，再用更短的确认选项重新发起确认。
- 当用户此前已明确授权某批动作（如合并规则、清理冲突文档、重新筛选）时，计划确认工具超时后不再重复询问，直接按既有授权继续收尾并说明依据与保留项。
