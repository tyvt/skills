不过有个关键权衡需要你定，我先说清楚现状和取舍：

**现状**
- `config.js` 由 `final_portfolio_v3.py` 生成（目标权重/风控/单只 dps 等），重跑会整份覆盖。
- 它**不是行情数据**，是「静态策略配置」，量很小（~4KB）。

**并入 sqlite 的技术做法**：面板已内联 SQLite 引擎，可在库里加一张 `config(k,v)` 表（或 `panel_config` 单行 JSON），启动时优先从库读；`config.js` 仅作首次导入来源。

**但这里有一处必须你拍板的取舍**，因为直接影响你的选股工作流：
**assistant [peer=github.com-tyvt-financial-data-lake]**: 明白：**以 sqlite 为准**，`config.js` 仅作首次导入，之后在面板里手动「从 config.js 同步」。

方案：
1. 库加 `config` 存储：用现有 `setting` 表（已有 `k,v`），存 `cfg:json`（整份 PANEL_CONFIG）。
2. 启动时：库里有 `cfg:json` → 用它；没有 → 从 `config.js` 导入一次写库。
3. 设置里加「从 config.js 重新同步」按钮（覆盖库，提示会丢弃库里手改）。
4. `config.js` 缺失时，若库里有配置仍可正常用（真正单 sqlite）。

先看现有 `setting` 表结构和读写逻辑、设置弹窗，确认改动最小。
