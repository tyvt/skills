# 实控人治理抓取机制
`ownership.py` 的 `fetch_many` 串行单线程抓取东财接口，是数据湖选股模块最慢环节。

## Description
- 每只股票一次 `requests.get`（超时 15s），股间强制 `sleep(0.6~1.8s)` 防东财限流
- 失败指数退避重试（最多 3 次，2^k×1.5s + 抖动）
- 无缓存新股实际每只约 1.3–2s
- 属于数据湖选股模块（final_portfolio_v3.py 等）

## Performance
- 246 只全新抓：约 5–8 分钟
- 全市场 2791 只：1 小时以上
- 41 只（先筛后抓）：约 1 分钟

## Cache
- `fetch_many` 第 311–314 行：当日已抓命中缓存跳过不发请求
- 缓存文件 `实控人核查.csv` 共 86 条，2026-11-11 当日有效仅 1 条

## Optimization
- 放宽缓存时效至 N 天（如实控人极少变，30 天最划算）
- 并发抓取（ThreadPool 4–6）+ 调小 sleep，注意东财 403 限流
- 先跑廉价关卡压候选量再抓治理，最省且不改逻辑
