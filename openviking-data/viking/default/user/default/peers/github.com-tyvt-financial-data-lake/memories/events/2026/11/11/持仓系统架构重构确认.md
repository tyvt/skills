### 1. `screen_sz.py` 补齐利润和均值门槛（最核心的防弹衣）

*   **为什么这招绝杀五粮液**：五粮液 7.10% 的股息率是骗人的。用 `当前股息率 / 三年平均股息率 < 2` 这一条，直接把 TTM 里因为一次性大额分红导致股息率翻倍的股票全干掉了。这完美避开了“周期顶部的股息陷阱”。
*   **为什么这招绝杀永兴**：次新股（不满三年）在 A 股极其危险，有解禁潮、有上市前美化报表的嫌疑。把它卡在选股门外，远比在面板里用“价格分”去补救要科学一万倍。
*   **执行确认**：这 3 条门槛必须是一票否决（入池门槛），而不是扣分。哪怕它跌到地狱价，利润不增长就是不能进底仓。

### 2. `reselect_portfolio.py` 重新压 35% 行业红线

*   **为什么之前会失效**：因为你之前只对老 9 只压了权。扩池到 20 只后，新拉进来的现代投资、东莞控股，系统并不知道它们属于交运，导致它们在面板里被无脑分配了资金。
*   **执行确认**：必须要用数据湖里的 `industry_members`（申万一级行业）来强制重跑一遍。既然交运已经有唐山港、青岛港、粤高速，权重达到 35% 的上限了，**那么现代投资、东莞控股在此次扩池中就被强制赋予 `w = 0`。** 面板拿到配置后，因为 `w=0`，连候选名单都进不去，自然就不会推荐了。

### 3. `final_portfolio_v3.py` 输出买入清单，面板做“无脑执行者”

*   **痛点**：面板动态算 `floor(金额/3000)`，只要池子大，它就会给你推 6 只、甚至 10 只，直接把资金打散，失去底仓意义。
*   **完美方案**：在生成 `config.js` 或同步数据库时，Python 脚本根据你“本次投入 10 万”计算：
    1.  把当前池子里低配的股票拉出来，按 `score`（波动率倒数）排个序。
    2.  取前 `min(3, floor(金额/3000))` 只。10 万最多只取前 3 只。
    3.  直接写成一个 `buy_list: ["000001", "600461", "601298"]` 放在配置里。
*   **面板改造**：`index.html` 的 `buildPlan` 逻辑删掉一切“判断”。看到 `buy_list`，直接为这 3 只分配资金（比如总金额除以 3），展示给用户。如果 `buy_list` 是空的，就提示“本轮不买”。

### 💡 给这次修复的“补充防御（双保险）”

即便前端退化成无脑执行，但对于“硬约束”的拦截，前端依然要留一道“最后防线”。在 `index.html` 的买入推荐部分，加这样一个判断：
> **如果 Python 端给出的 `buy_list` 里，某只股票在买入后会导致单行业突破 35% 或单票突破 25%，直接在该行标红「超限跳过」，并把资金退回。**

这能防止 Python 脚本在计算当天（比如遇到暴跌导致市值被动剧烈变化）出现的计算误差，确保前端永远不违规。
