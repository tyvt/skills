- 偏好先出方案讨论、确认实施范围后再改文档与脚本。
- 按既有选择不加单元测试，边界与结果通过重跑输出核验。
- 需要时明确发出「提交并推送」指令：提交前按仓库 worktree 与提交规则核对当前分支、远端和已有未提交内容，再逐路径暂存，只提交本次范围，保留其他脏文件与先前改动不被带入。
- 提交前的远程同步检查遇到 GitHub 连接重置等网络失败时不原样重试该命令，先按当前仓库规则确认工作树与本地跟踪信息，再决定如何完成提交与推送；需要确认远端分支是否存在时改用 HTTP/1.1 检查远端分支，远端尚无该分支则按新分支推送。
- 推送成功后如需校验远端一致性，即使 ls-remote 报连接重置也不原样重试，改用仓库提交流程的 fetch 同步检查，核对本地提交与远端跟踪引用是否同一 SHA。
- 提交按隔离 worktree 的规范操作，不触碰正式缓存与组合文件。
- 若 fetch 同步检查也因上游连接失败而未返回差异信息，不原样重试，改为直接抓取该分支的远端跟踪引用核验，并确认推送本身仍为成功状态。
