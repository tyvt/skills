- 回测首次运行在某个筛选阶段（如沪市筛选）失败时，先单独复现该基准日、该阶段的步骤，再据此修正，避免重跑整组回测。
- 排查时把标准错误合并进诊断日志；若看门狗日志只保留了标准输出导致错误栈缺失，先补齐错误栈再定位问题。
- 失败后的诊断与重跑按当前会话的长任务与编排器规则执行，不随意自行改动流程。
- 代码生成调用超时后不再重复同一调用，先诊断原因再重跑，避免反复超时。
- 隔离回测的重跑以上游修复为前提：等两位筛选脚本负责人各自修好对应的银行门后，才开始重跑隔离回测。
- 读表头/字段解析失败时逐层收窄根因：先修编码问题（如 UTF-8 BOM 改用 utf-8-sig 并清理列名中的 BOM），再改为列名优先、列序兜底读取，修复方式先纳入自检再重跑全组。
- 控制台打印中文（如漏斗统计）触发编码报错导致程序退出时，改用 Python UTF-8 模式重跑，并放到新的隔离目录，确认正式结果与缓存未被触碰。
