## 结论
**「参与决策/修改决策」的切换逻辑完全由后端返回的 `voteState` 决定，跟「点击决策详情」这个动作本身无关；而 iOS 原生仓库里根本没有决策逻辑——它是 WKWebView 壳，「业主决策」只是菜单码 `3_0_0` 加载 H5，所以不存在可对比的原生接口链路。**

## 关键证据

**当前项目（一网通办 H5/小程序）**
- 按钮文案在 `src/pages-decision/components/index.vue:51-53` 计算：`voteState == '未表决' || '未选举'` → 显示「参与」，其余状态 → 显示「修改」，`typeLabel` 拼成「决策/选举」。
- 点击「决策详情」的 `goDetail`（`components/index.vue:202-208`）只做两件事：`decisionStore.setTableId / setOwnerVoteOpinCode`，然后 `navigateTo` 详情页——**不改 voteState，也不改标签**。
- 详情页 `decision/detail.vue` 只调 `SmUserVoteDetail`（`common.ts:162`）渲染字段，没有任何参与/修改按钮。
- 标签会变，是因为列表在 `onShow` 时 `reload()`（`components/index.vue:195`），重新拉 `SmCastVoteListApp`（`/version/1/app/SmCastVoteListApp`）拿到新的 `voteState`。也就是说「点详情再返回后变修改」= 后端把该记录状态更新了，前端只是被动反映。...
