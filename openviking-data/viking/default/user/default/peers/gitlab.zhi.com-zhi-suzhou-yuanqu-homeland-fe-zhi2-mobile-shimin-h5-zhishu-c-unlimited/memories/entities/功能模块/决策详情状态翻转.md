# 决策详情状态翻转
点决策详情后「参与决策」变「修改决策」是新 app 后端 SmUserVoteDetail 打开详情时写库导致，不是前端 bug，前端只是忠实反映后端返回的 voteState。

## 因果链路
- 前端详情页加载调 SmUserVoteDetail（家园区一网通办/src/pages-decision/decision/detail.vue:143,162）→ 后端 Controller /SmUserVoteDetail → detailExecute（SmCastVoteAppController.java:236,249）。
- detailExecute 写库：updateVoteOpin 把 voteopinion 4→3（未表决→已送达未表决）（SmCastVoteAppServiceImpl.java:2181 → SmCommonMessageDtlAppMapper.xml:190-205）。
- 同时把消息 isReader 0→1、busiState 0→1 并 updateById（SmCastVoteAppServiceImpl.java 约 :2203/:2211/2214）。
- 列表接口 SmCastVoteListApp 按 po.getBusiState() 映射 voteState：0→未表决、1→表决中、2→已表决、3→已过期（SmCastVoteAppServiceImpl.java:392-416）。
- 前端按钮文案：未表决/未选举→参与，其余→修改（components/index.vue:51-53）；即打开详情→后端置 busiState=1→列表返回「表决中」→标签变「修改决策」。

## 新老 app 差异
- 老 app（iOS→园区表决H5→V0 后端）用 /estate/AppDecision/selectAppDecisionList、/h5decision/ownerDecision，按 Tab 静态分流，详情只读不写状态，没有这个行为。
- 该行为是新一网通办 /version/1/app/Sm* 接口引入的。

## 结论与待办
- 状态翻转是后端有意设计（打开即标记已读/送达）；把「已读消息」映射成「表决中」并显示「修改决策」是否合理需产品确认。
- 若要改为「未实际投票仍显示参与决策」，得改后端 updateVoteOpin 与 busiState→voteState 字段映射，不在前端范围内。
- 本次为纯静态排查，未跑构建/测试。
