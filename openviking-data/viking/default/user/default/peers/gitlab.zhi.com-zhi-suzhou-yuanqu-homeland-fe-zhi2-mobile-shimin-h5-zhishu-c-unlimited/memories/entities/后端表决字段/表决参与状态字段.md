# 表决参与状态字段
后端表决列表中用于判断用户是否真正提交表决的字段、状态语义与核对方法。

## 核心结论
- 仅查看详情不等于参与：SmUserVoteDetail 会把消息 isReader 置为 1、busiState 从 0 变为 1，并可能把业主 voteopinion 从 4 改为 3。
- busiState→2（已表决）应在 SmCastVoteGoHandleApp / SmCastVoteSubmitApp 链路，更接近真正提交表决。
- 现状列表没有“是否已提交”专用字段，列表未下发业主 voteOpinion。

## 列表字段
- voteState 由消息 busiState 映射：0 未表决、1 表决中、2 已表决、3 已过期。
- isReader 只表示消息已读，包含仅进详情，不能作为已参与依据。
- ownerVoteOpinCode 是查详情/提交用的本户表决权利人编码，不表示是否已投。
- voteBusiState 是业务侧另一套状态位，列表前端基本不用来判断参与。

## 判断与影响
- 真参与核对应优先看 voteState=已表决（busiState=2），再用详情/统计接口的 MtplOwnerVoteObligee.voteOpinion 非空且有效复核。
- 看详情时 mtpl_ownervoteopin.voteopinion 的 4→3 是 updateVoteOpin 副作用（SQL 条件 nvl(voteopinion,'4')='4'），不是用户选择同意/不同意。
- 新 app 用 voteState==未表决 生成“参与”文案，会把仅看详情后变为表决中的情况显示成“修改”；老安卓主按钮不看 voteState。
- 若要在列表严格区分需后端扩展 DTO（如下发 voteOpinion 或 hasSubmitted）；落库核对应结合消息 busiState/isReader 与权利人 voteopinion。
