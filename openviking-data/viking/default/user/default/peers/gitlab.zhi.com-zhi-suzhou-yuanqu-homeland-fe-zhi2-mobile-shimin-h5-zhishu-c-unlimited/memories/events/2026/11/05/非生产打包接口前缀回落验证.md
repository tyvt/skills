## 回答：是的，不用生产环境变量打包，接口一定出问题

我实测了两种打包（只读验证，已清理临时产物）：

| 打包方式 | `VITE_APP_PROXY_PREFIX` 最终值 | 接口实际请求地址 | 结果 |
|---|---|---|---|
| `npm run build`（production） | `/wechatapph5/api` | `sipps.sipac.gov.cn/wechatapph5/api/...` | ✅ 通 |
| `npm run test`（`-m test`） | **`/api`** | `sipps.sipac.gov.cn/api/...` | ❌ **404，接口全挂** |

**根因**：接口前缀 `VITE_APP_PROXY_PREFIX` **只有 `.env.production` 里写成了 `/wechatapph5/api`**；基础 `.env` 是 `/api`，而 `.env.test`、`.env.development` **都没覆盖它**。所以只要打包时没走 production 模式（`-m test`、或构建环境读不到 `.env.production`），前缀就回落成 `/api` → 打到站点根 → 404。

**注意它和静态资源是反过来的**：
- 用 test 打包：**接口坏（`/api`）、静态资源好**（`VITE_APP_PUBLIC_BASE` 基础值为空 → `base` 回落 `./` 相对路径）
- 上次线上白屏：**静态资源坏（`/assets` 404）、接口碰巧对**

所以两者**必须用 production 模式打包**，缺一不可。
