## 问题定位
「刷新页面卡在骨架屏」的根因是**骨架屏的揭开被非关键公告接口"硬绑"住了**：

[index-new.vue](<zhi2-web-admin/src/views/home/UnifiedLogin.vue> 中 `loadNoticeList()` 原逻辑是 `await getPublicNotices(...)` 完成后（无论成功/失败/catch）才把 `pageSkeletonVisible` 置 false。而该请求走 `axios` 默认 **100s 超时**——在 8081 本地 dev 下，如果公告后端（dev 代理指向 `58.210.252.230:9001`）慢、弱网或不可达，请求长时间挂起，整页骨架屏就一直不揭开，表现为"刷新一直卡骨架屏"。

我实测：8081 上公告接口当前能返回 200，所以**干净浏览器里我复现不出卡死**（无痕加载各路由均正常）。真正会卡的是接口挂起/慢的场景——这也解释了为什么之前那次会话在 8081 也没复现到具体页面。

## 修复（[UnifiedLogin.vue](<zhi2-web-admin/src/views/home/UnifiedLogin.vue>)）
把公告请求改成**不阻塞骨架揭开的旁路任务**：
- 用 `Promise.race([noticeTask, sleep(SKELETON_MAX_WAIT)])` 兜一个最长等待 **2500ms**，到点无论接口是否返回都先揭开骨架屏；
- 公告接口真正返回后照常把列表补进页面（`startNewsRotation` 等逻辑不变）；
- 保留原有「最短展示 600ms」防闪屏。

净效果：**公告接口再慢/挂起，用户也不会被卡在骨架屏**，最多等约 2.5s+最短时长。
