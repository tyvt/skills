## 真正的原因找到了 🎯

你说的关键线索「**localStorage 里有 `platform-config-cache` 再刷新就卡**」直接锁定了根因——**平台配置缓存命中时，模块初始化阶段抛异常，整个应用启动失败**，于是页面停在骨架屏（无缓存时不触发，所以之前一直复现不出来）。

我实测复现并抓到了异常栈，其实是**两个 bug 叠加**：

1. **TDZ 报错**：`store/modules/app.js` 里，缓存命中时在模块顶层调用 `normalizePlatformConfig()`，而它内部读取的 `export const DEFAULT_REGISTER_URL` 声明在这段代码**之后** → 抛 `Cannot access 'DEFAULT_REGISTER_URL' before initialization`（暂时性死区）。
2. **算色崩溃**：修掉第 1 个后，紧接着 `changeThemeColor(缓存的主题色)` 在样式还没加载时执行，`getCssVariable('--danger-color')` 返回空串 → `hexToRgb('')` 里 `''.match(/../g)` 得到 `null` → 抛 `Cannot read properties of null (reading '0')`。

两者都会让 `app.js` 模块求值中断 → 应用起不来 → 卡骨架屏。

## 修复
- **[app.js](<zhi2-web-admin/src/store/modules/app.js>)**：把 `DEFAULT_REGISTER_URL` 的声明**移到缓存初始化之前**（消除 TDZ）；并给两处 `changeThemeColor` 调用加 `try/catch`——主题色只是首屏优化，绝不能再让它拖垮整个启动。
- **[utils/index.js](<zhi2-web-admin/src/utils/index.js>)**：`hexToRgb` 增加容错，空/非法色值退化为黑色 `[0,0,0]`，`mix` 不再抛异常（把"硬崩溃"变成"优雅降级"）。
