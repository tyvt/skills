## 根因

「应用管理详情」这条路由在接口里是：

```json
{
  "path": "/",
  "hidden": true,          // 父级 Layout：隐藏
  "children": [{
    "path": "application/:tableid",
    "hidden": false,       // 子路由：未隐藏 ← 与菜单管理「隐藏」不一致
    "meta": { "title": "应用管理详情" }
  }]
}
```

菜单管理里显示「隐藏」，但 **`listRouters` 没有在子节点上体现**（没有 `hidden: true`，也没有 `visible: 1`），反而写了 **`hidden: false`**。

前端 `isRouteHidden()` 只看当前节点，所以会认为这条路由**应当展示**。

另外，门户把大量菜单拆成多个 `path: "/"` 的 Layout；侧栏实际用的是 `buildNavbarChildrenMenus` **扁平化后的 children**。原先只判断子项是否 hidden，**没有看父 Layout 是否 `hidden: true`**，于是父已隐藏、子仍为 `hidden: false` 时，「应用管理详情」仍会被推进侧栏列表（且因排在第一个，常出现在侧栏最上方）。

## 已做前端修复

在 `menuVisibility.js` 的 `buildNavbarChildrenMenus` 中增加：**父级路由 `hidden` 时，不再扁平化其 children**。这样与若依「隐藏目录下菜单不进导航」的行为一致，你这份 JSON 下侧栏不会再出现「应用管理详情」。

## 后端建议（根治）

`listRouters` 构建时应与 `sys_menu.visible` 一致，对 menuId `20023` 应返回 **`hidden: true`**（或带上 `visible: "1"`），避免子节点与父 Layout、与菜单管理界面三者矛盾。否则仅依赖「父 Layout hidden」在别的树形结构下可能仍会有边角问题。

刷新页面或重新登录后看侧栏即可验证；若仍出现，说明还有别的入口在写 `sidebarRouters`，可以再查 Network 是否走了缓存的 `sessionStorage.routers`（iframe 模式）。
