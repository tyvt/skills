## 行为分析（按场景）

### 扁平相对路径（如 `system/user`）

Vue Router 3 的 `router-link` / `router.push` 对不以 `/` 开头的 `to` 会按**当前路由**做相对解析，在 `/system/...` 下会把 `system/user` 解析成 `/system/system/user`。  
`toRouterAbsolutePath` 统一加上前导 `/` 并折叠重复斜杠，得到 `/system/user`，与预期一致。

`getLinkProps` 在拼接后统一调用该函数，即使 `parentPath` 为空、仅得到 `system/user`，也会变成 `/system/user`，这是本次修复的核心。

### 顶栏 `buildNavbarChildrenMenus`

```82:86:d:/repository/门户/zhi2-web-admin/src/utils/menuVisibility.js
        } else if (!isHttpUrl(source.path)) {
          const parent = router.path.startsWith('/') ? router.path : `/${router.path}`
          const segment = String(source.path || '').replace(/^\/+/, '')
          child.path = toRouterAbsolutePath(`${parent}/${segment}`)
```

- 父级无 `/`（如 `system`）时，旧逻辑会得到 `system/user` 这类仍相对路径；新逻辑得到 `/system/user`，与侧栏跳转一致。
- 典型若依子段为 `user`、父为 `/system` → `/system/user`，正确。
- `router.path === '/'` 仍走 `/redirect/` + `source.path`，未改动，合理。

### 嵌套侧栏

子项为相对单段（如 `user`）时，`getLinkProps` 仍先与 `parentPath` / `menuItem.path` 拼接，再 `toRouterAbsolutePath`，嵌套场景与原先拼接逻辑一致，仅最终 `to` 变为绝对路径。

### HTTP / 外链

- `toRouterAbsolutePath`：仅当**整串**以 `http://` / `https://` 开头时原样返回，不会误加 `/`。
- `getLinkProps` 在纯外链分支仍先返回 `href` / `target`，不会走到 `to: toRouterAbsolutePath(...)`。
- `buildNavbarChildrenMenus` 对 `isHttpUrl(source.path)` 为真时不改写 `child.path`。

`isHttpUrl`（任意位置包含 `http://`）与 `toRouterAbsolutePath`（仅开头）判定不一致，属既有风格；正常菜单 path 下不构成实际问题。
