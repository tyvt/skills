## B 端是否会先挂 v2？

**结论：在当前路由 + GetInfo 实现下，不会出现「B 端在 `terminalType` 未写入时因本修复误显 v2」。**

依据：

1. **路由门禁**（`router/index.js`）：`roles.length === 0` 时会 `await store.dispatch('GetInfo')`，之后才 `next()`。首页 wrapper 不会在首次进系统、roles 仍为空时挂载。

2. **GetInfo 提交顺序**（`user.js` 142–149）：同一 `.then` 回调里先 `SET_ROLES`，再 `TERMINAL_TYPE`，中间无 `await`。Vue 2 对同一事件循环内的依赖变更会把组件更新排到 nextTick，不会在两次 `commit` 之间单独渲染 wrapper。

3. **Promise resolve 时机**：`GetInfo` 在 `/system/profile` 之后才 `resolve`，晚于 `TERMINAL_TYPE`。首屏进入首页时，B 端通常已有 `terminalType === 'B'`，`homeVariantReady` 走第一分支 `terminalType != null`，不会依赖 `roles` 兜底。

4. **仅 `roles`、无 `terminalType` 的兜底**：对应 API 明确不返回 `terminalType`（超级管理员等），`useBLegacyHome` 为 false，走 v2 符合注释预期；不是 B 端误分流。

5. **同一次渲染**：`homeVariantReady` 与 `useBLegacyHome` 在同一 tick 读同一 store 快照；`ready === true` 时若 `terminalType === 'B'`，会选 `index-legacy`。
