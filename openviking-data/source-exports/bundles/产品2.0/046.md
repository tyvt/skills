### 最终结论
## 原因（为何写死 `z-index` 仍会翻车）

Element 的 `el-dialog` 会在**第一次打开**时用 `PopupManager` 分配一个 `zIndex` 并**缓存在实例上**。`ImageViewer` 一直挂在 `App` 里、只切换 `visible` 时，**同一个对话框实例**会反复用这个旧值；业务弹窗每开一次都会拿到更大的新值，多轮开关之后预览就会再次被压在下面。

## 做法（不写死、交给 Element 叠层）

1. **`ImageViewer`**：给 `el-dialog` 加 **`v-if="showViewer"`**，关闭时从 DOM 卸掉、再打开时**新建实例**，这样会重新走 PopupManager，和当前其它弹窗自然叠在一起。已去掉 `:z-index` 以及遮罩/对话框上 `::v-deep` 里写死的 `z-index`。外层加了 `image-viewer-host` + `display: contents`，不占布局、又满足 Vue 2 单根。

2. **`App.vue`**：删掉全局的 `.viewer-container { z-index: 9999 }`（只影响预览里的容器，且会干扰正常叠层），并去掉已无内容的 `<style>`。

未在全项目里批量删其它页面上的 `:z-index`（那是另一轮范围）；若你希望**所有**业务 `el-dialog` 都不写死，可以再说一下我按目录扫一遍改。

当前 `App.vue` 里 `localStorage.setItem(..., true)` 的 TS 提示是原有问题，与这次修改无关。

## 问题原因

这是一个**状态不同步**问题，常见触发路径如下：

1. 选中「当日」后 `currentTab = 0`，页面展示当日数据  
2. 进入待办详情再返回首页，`currentTab` 恢复默认 `1`（本周）  
3. 但办件数量区域可能仍显示上一次的当日数据，出现「本周选中、当日数字」的错乱

可能原因包括：
- 切换 tab 时 DOM 复用，数字未及时刷新  
- 多次统计请求并发返回，旧数据覆盖新数据  
- 页面被缓存后再次激活，tab 与数据未一起重置

## 修复内容

1. **`:key="'task-stats-' + currentTab"`** — tab 切换时强制重渲染数量区域  
2. **`currentTaskStats` 计算属性** — 安全读取当前 tab 对应数据  
3. **`refreshStatsData()`** — 刷新前先清空 `todoCount` / `bubbleList` / `lineData`，避免短暂展示旧数据  
4. **`statsFetchSeq` 序号保护** — 忽略过期的统计接口响应，避免竞态  
5. **`activated` 钩子** — 从详情返回时重置为「本周」，并重新拉取统计数据

## 建议验证步骤

1. 首页点击「当日」，确认数量正确  
2. 点击右侧任意待办进入详情  
3. 返回首页  
4. 确认默认停在「本周」，且办件总数 / 已处理 / 待处理均为本周数据（不应再出现当日数字）  
5. 在「当日 / 本周 / 本月 / 本年」间多次切换，确认数字与 tab 始终一致
