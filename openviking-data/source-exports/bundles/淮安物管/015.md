### 最终结论
## 原因说明

`zs-operate-column` 里原先有一段**非 scoped** 样式：

```css
.el-table .zs-operate-column-cell {
  background-color: #ffffff !important;
}
```

表头 `th` 和表体 `td` 都带有 `zs-operate-column-cell`（分别来自 `label-class-name` / `class-name`）。`!important` 会压过 `ZsTable` 里通过 `header-cell-style` 给表头写的 **`#fafafa`**，于是「操作」列表头变成纯白或与灰底表头不一致，在固定右列叠层时容易看起来像**表头背景缺失**。

## 修改方式

把「强制白底」只作用在**表体**（主表 + 右侧固定列的 body），不再作用在表头：

```127:134:d:\repository\淮安物管\zhi2-web-admin\src\components\zs-operate-column\zs-operate-column.vue
<!-- 操作列 td 由表格渲染在组件外，需非 scoped 才能命中固定列单元格；勿作用于 th，否则会覆盖 ZsTable 表头 #fafafa -->
<style>
.el-table__body-wrapper .zs-operate-column-cell,
.el-table__fixed-body-wrapper .zs-operate-column-cell {
  background-color: #ffffff !important;
}
</style>
```

这样「操作」列表头会重新跟随 `ZsTable` 的 `header-cell-style`（`#fafafa`），与其它列表头一致；表体操作列仍为白底，避免固定列透底等问题。若某页不用 `ZsTable` 且未设置表头背景，需要在该页的 `el-table` 上自行配置 `header-cell-style` 或全局表头样式。
