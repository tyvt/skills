## 从苏住房G 迁过来的 4 处改进

**1. `detailId` 作为业务主键兜底**
```js
const { busCode, path: storedPath, dataId, detailId } = row
const id = extractDataIdFromPath(storedPath, dataId ?? detailId)
```
这就是你上一轮问的那个点——G 项目确实认 `detailId`，但它是当作 `dataId` 的兜底来源，而不是跳转参数名。`dataId` 有值时优先用 `dataId`。

**2. 菜单壳路由（Layout / ParentView / InnerLink）不再当作页面**
新增 `SHELL_MENU_COMPONENTS` 集合和 `isMenuShellRoute()`，`getRouteFilePath()` 也会过滤掉这类值。原来如果 busCode 命中一条 `component: 'Layout'` 的目录路由，会拿它当详情页跳，现在会退回后端存的 `storedPath`。

**3. storedPath 匹配不到时按 busCode 兜底详情路由**
`pickRouteByStoredPath` 增加了「有 hints 但全不匹配就返回 null」；`resolveTodoTaskNavigation` 拿到 null 后改为在 busCode 候选里找 `isDetailRoute`，用主键重建路径。原来这种情况会直接跳后端那个已经失效的旧 path。

**4. 通用动态参数段 + 缺主键提示**
G 用通用的 `:xxx` 段处理替代了 V3 里只管 `:tableid` 的写法。我做成混合式：`:tableid` 仍走 V3 原有的 `buildTableIdNavigation` 多级兜底，其他动态段（比如 V3 路由里真实存在的 `register/:applyId`）走 G 的 `name + params` 逻辑。拿不到主键时返回 `{ missingId: true }`，`navigateToTodoTask` 提示「待办任务缺少业务主键，无法打开详情页」并中止跳转。
