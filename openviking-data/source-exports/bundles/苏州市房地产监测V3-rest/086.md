## 问题定位

截图里两个红框正好对上了矛盾点：右边 `meta.submitApi` 已经配成 `/company/companyRecordChange/specialSubmit`，左边点「提交」却没走它。

原因在「企业基本信息」变更详情页的自定义提交按钮（`toB/companyRecord/detail.vue:662` 的 `handleSubmitChange`）。它不使用通用的 `ZsSubmit` 组件，而是自己拼接口，原来那行是：

```js
const submitApi = await resolveFlowSubmitApi(this, this.changeFlowBusCode, COMPANY_RECORD_CHANGE_SUBMIT_API)
```

这条链路有两处断点，任意一处都会让菜单配置失效：

1. **`resolveFlowSubmitApi` 只查流程配置**（`/flowable/flowConfig/list`），从头到尾没读 `route.meta.submitApi`。
2. **`changeFlowBusCode` 在这个页面是 `undefined`**。它定义成 `if (!this.isChange) return undefined`，而这个路由的 `isChange` prop 没传，值是 false，所以连流程配置那次查询也被 `if (!busCode) return fallbackApi` 直接短路了。

两者叠加，最终永远落到硬编码的 `/company/companyRecordChange/submit`，菜单里配的 `specialSubmit` 一次都没被读取——这与你看到的现象完全一致。

## 改动

在 `src/utils/flowApi.js` 新增 `resolveSubmitApi`，明确三级优先级：**菜单 `meta.submitApi` → 流程配置 `submitApi` → 代码默认路径**。它兼容传入路由对象，会沿 `matched` 向上继承父级菜单的 meta，因为详情子路由常把配置挂在列表菜单上。

然后替换了两个调用点：

- `toB/companyRecord/detail.vue` — 截图这个页面。顺带修了第二个断点：`ensureFlowConfigured` 和接口解析现在用同一个 `busCode`（解析值回退 `CHANGE_FLOW_BUS_CODE`），之前前者用常量、后者用可能为 `undefined` 的 computed，两处判断口径不一致。
