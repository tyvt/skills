## 原因说明

`el-form` 校验时，`ElFormItem` 的 `fieldValue` 是直接从 **`form.model` + `prop`** 里取的，不依赖你在输入框里“看起来有没有字”。  
开发能过、**打包后**才像“空值”，常见有两类原因：

1. **同一事件循环里的顺序**：最后一位输入后立刻失焦时，`el.form.blur` 触发的校验若早于父组件把 `v-model` 写进 `model`，读到的仍是旧值（生产用 `vue.min.js`、批处理更紧时更容易暴露）。
2. **自定义组件向上找 `ElFormItem`**：用 `$options.componentName === 'ElFormItem'` 时，若外链/压缩后的 `element-ui` 表现不一致，可能找不到表单项（你原来给 `change` 做的 `dispatch` 会失效；整表 `validate()` 仍主要看 model，但 blur/change 触发会乱）。

## 已做修改（`AmountInput/index.vue`）

1. **显式 `model: { prop: 'value', event: 'input' }`**，避免构建链对 v-model 的歧义。  
2. **`numberValue` 的 watch 增加 `{ flush: 'sync' }`**：先把 `input` 同步派发给父组件，再在同一 tick 里处理 blur，减少“校验读到旧 model”的竞态。  
3. **`input` / `blur` / 清空**：优先用 **`instance.proxy.$emit`**（与 `vue-currency-input` 内部写法一致），减少 setup `emit` 在个别构建下的差异。  
4. **`handleBlur` 使用双 `nextTick` 再 `dispatch` `el.form.blur`**，给父级 model 多留一帧更新时间。  
5. **向上查找表单项时同时认 `componentName` 和 `name` 为 `ElFormItem`**，兼容不同打包方式。

请重新打一次生产包验证。若仍有个别页面异常，说明一下是 **点提交整表校验** 还是 **失焦/change** 时报错，以及该字段的 `rules`（是否 `required`、是否自定义 `validator`），可以再针对性查。
