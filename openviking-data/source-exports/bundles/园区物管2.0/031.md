### 最终结论
## 问题原因

这是典型的**异步竞态 + 在 computed 里做副作用**问题，不是后端配置真的坏了。

1. **平台配置异步加载**  
   `App.vue` 在 `created` 里调用 `getPlatformConfig()`，不等待完成；`platformConfig.region` 初始为 `undefined`。

2. **页面组件先渲染**  
   路由切换时，`zs-search-form`、`zs-region-select` 等会立刻执行 computed。原先在 `!platformConfig.region` 时直接 `msgError(...)`，配置还没回来就被当成失败。

3. **computed 会反复执行**  
   Vue 每次依赖变化、重渲染都会重新算 computed，同一次加载可能连弹多条提示。

4. **刷新后“正常”**  
   整页刷新后，配置往往在子页面渲染前就加载完了，或只触发一次，所以看起来像“刷新就好了”。

## 修复内容

| 文件 | 改动 |
|------|------|
| `zs-region-select.vue` | 去掉 computed/`created` 中的 `msgError`；`region` 未就绪时返回空选项；用 `watch` 在配置到达后同步默认值 |
| `zs-search-form.vue` | `isCityLevel` 在 `region` 未就绪时返回 `false`，不再弹错 |
| `mixins/area.js` | 同样去掉 computed 中的误报 |
| `store/modules/app.js` | 仅在 `getPlatformConfig` 请求结束后、且确实没有 `region` 时提示一次；请求去重 |
| `router/index.js` | 首次鉴权时与区域树等数据一起 `await getPlatformConfig`，避免首屏竞态 |

配置加载期间，行政区域相关控件会暂时为空/隐藏，属于正常等待状态；只有接口返回后仍缺少 `region` 时，才会提示「获取行政区域配置失败，请检查系统配置」。

请重新登录或切换几个带「行政区域」筛选的列表页验证，不应再出现频繁误报。若仍出现单次提示，则需要检查后台 `/system/platformConfig/getInfo` 是否返回了 `region` 字段。
