### 最终结论
你的质疑是对的。说明如下：

## 为什么当时改了模板？

当时做表格样式优化时，参考的是**业主账户开户**（`owner/index.vue`）——它没用 `ListTemplate.js`，而是写了独立 `<template>`，并加了 `bottom-summary-items`（底部合计行）。

我错误地把同样做法套到了另外几个页面上。实际上：

| 页面 | 是否真的需要独立模板 |
|------|---------------------|
| `accountCancel/index.vue` | 否，只需 `border: true` |
| `complex/index.vue` | 否，只需 `border: true` |
| `settlementAccount/index.vue` | 否，只需 `border: true` |
| `accountOpen/components/index.vue` | 否，只需在 script 里重写 `summaryItems`、`showMethod`、`listCallback` |

这三个页面把 `ListTemplate` 的 HTML 复制一遍，**没有新增能力**，反而和项目惯例不一致。

## 和通用模板差在哪？

原来的 `ListTemplate.js` 已包含：

- `list-container` + `list-card` 外框
- `ListOperationButtonContainer` 标题栏
- `:border="border"`、`:show-summary="showSummary"` 等

当时缺的是：

- `:bottom-summary-items`（底部「合计：账户数…」那一行）

## 已做的修正

1. **增强 `ListTemplate.js`**：补上 `bottom-summary-items` / `bottom-summary-variant`
2. **在 `table.js` mixin 中**：增加默认 `summaryItems: []`、`bottomSummaryVariant: 'table'`
3. **上述 4 个页面已改回** `template: template` + 只写 script 的方式

`accountOpen/components/index.vue` 仍用通用模板，只在 script 里重写 `summaryItems` 等合计逻辑。

## 什么时候才该写独立模板？

只有通用模板**覆盖不了**的场景才写，例如业主账户开户：

- 额外的 `OwnerAddDialog` 弹窗
- 额外的「导出」按钮
- 列定义不走 `displayColumns` 配置

其余列表页继续用 `ListTemplate.js` + `listMixins` 即可，这也是项目主流写法。
