### 最终结论
重构完成。请**硬刷新（Ctrl+Shift+R）**后打开 `pubElevMaintenanceNew` 验证：列应根据表头/数据自动撑宽并填满表格，且不再卡死。

## 死循环根因

旧架构有一套自定义列宽分配引擎，致命点在 `distributeColumnWidths` 用**渲染后的 realWidth**（操作列动态宽度、滚动条都会改它）来反推剩余空间分给弹性列。即「分配的输入」依赖「分配的输出」，`lastDistributeKey` 永远稳定不下来 → 与 `el-table` 布局、ResizeObserver、`watch`、`:key` 叠加形成同步死循环。这也是为什么写死宽度（绕开整套机制）就不卡。

## 新方案（核心：测量只算内容，分配交给 el-table 原生 fit）

测量输入是**原始文本**（与渲染布局无关），输出只作为 `min-width` 喂给 el-table，不再回读布局 → 输入与输出彻底解耦，**数学上不可能死循环**。

| 组件 | 改动 |
|------|------|
| **zs-table-column** | 用纯 computed `contentWidth`（canvas 测表头+数据）算内容宽度；弹性列输出 `min-width`，有显式 `width` 原样透传，有显式 `min-width` 取 `max(显式, 内容)` 作下限。删除 `computeColumnWidth`/`applyDistributedWidth`/`setColumnWidth`/`getBaseWidth` 及 `tableData` watch、`nextTick` 调度 |
| **zs-table** | 删除整个分配引擎（`distributeColumnWidths`/`scheduleDistribute`/`autoWidthColumns`/`isDistributing`/`lastDistributeKey`/`distributeTimer` 等约 90 行）；只留 `flexColumnCount` 计数器，`fit = flexColumnCount > 0` |
| **zs-operate-column** | 宽度改为纯 computed，删除 `buttonWidth` 状态、`mounted`/`beforeDestroy`/`watch`/`nextTick` |

## 兼容性（页面零改动）

- 显式 `width` 的列：原样固定（完全尊重页面）。
- 显式 `min-width` 的列：作为下限，内容更宽时撑大（与旧行为一致）。
- 无宽度的列：按内容算 `min-width`，由 el-table 原生 flex 填满（有弹性列时 `fit:true`）。
- 全固定列页面：无弹性列 → `fit:false`，与现状完全一致（不拉伸末列）。

另外清理了 `propertyContractTable.vue` 中一处对已删方法的死调用。Lint 报错均为该项目 `ts-plugin` 对 Vue2 Options API 的既有误报，非本次引入。

如验证后某些列宽度观感需要微调，告诉我，我再调测量的 `COLUMN_PADDING`/`MIN`/`MAX` 常量即可。
