## 原因说明

控制台里形如 `.../assets/%E4%BC%9A%E6%89%80-xxx.js` 的请求，对应的是 **Vite 为每个静态资源模块打出来的小 JS chunk**（再导出图片 URL），chunk 名来自源文件路径。`operatingAssets.vue` 里用中文文件名去 `import` 了 `statisticsMap/images/` 下的 PNG，以及 `assets/images/benefit/` 下三张中文名的车位统计图。生产环境在 **`/sz/` 子路径 + 部分 Nginx/CDN 对 URL 编码中文路径不友好** 时，容易出现 **404**，进而触发顶层的 `Failed to fetch dynamically imported module`。

## 已做修改

1. **`src/views/benefit/statisticsMap/images/`**  
   将所有中文 PNG 文件名改为英文短名（例如 `会所.png` → `club.png`，`帐篷租赁.png` → `tent-lease.png` 等）。

2. **`src/assets/images/benefit/`**  
   将三张车位相关图片改为：  
   `parking-space-total.png`、`parking-space-property.png`、`parking-space-public.png`。

3. **`operatingAssets.vue`**  
   已把上述资源的 `import` 路径全部改为新文件名（业务里 `STAT_ICON_MAP` 等仍用中文 key，无需改动）。

重新构建后，`operatingAssets` 的依赖 chunk 已变为 ASCII 名，例如：`temp-stall-*.js`、`club-*.js` 等，不再出现 `会所-*.js` 这类路径。

## 关于 `index-BJlYXbMW.js` 仍失败

若部署后 **仅** 主入口 chunk 仍报 `Failed to fetch`，常见是：**整包未同步完**、**CDN/浏览器缓存了旧 `index.html` 却指向新 hash 的 chunk**、或 **网关只转发了部分静态文件**。处理办法是 **全量发布 `dist`** 并做一次 **强刷/清 CDN**，保证 `index.html` 与各 `assets/*.js` 为同一次构建。

请重新打包并完整发布 `zhi2-web-admin` 构建产物后再验证该页面。
