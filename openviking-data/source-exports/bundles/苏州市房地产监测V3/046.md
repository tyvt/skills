## 全局排查结论

### 已确认：同类「gap 被盖掉」问题

全库检索 `gap: 0 !important` 后，**只有一处**会影响 Headline 分块间距，就是已修复的：

- 原规则 `.detail-from-container.el-row { gap: 0 }` 特异性高于 `.detail-from-container { gap: var(--detail-block-gap) }`
- **未发现** `.detail-container.el-row`、`.collapse-container.el-row` 等同类写法

### 间距机制（修复后各场景是否覆盖）

| 页面结构 | 间距来源 | 状态 |
|---------|----------|------|
| `<el-row class="detail-from-container">` + 多个 **直接** `Headline` | 容器 `flex gap`（`--detail-block-gap` 12px） | 已修复 |
| `detail-from-container` + **唯一** `zs-form` + 多个 `Headline` | `.detail-from-container > .el-form` 的 `row-gap`（`zs-form` 根节点是 `el-form`） | 正常 |
| `detail-container` + 多个 `Headline`（无 `detail-from-container`，如机构注册审核） | `.detail-container` 的 `gap`（`--detail-section-gap` 16px） | 正常 |
| `AgencyBasicInfoForm` / `DeveloperBasicInfoForm` 内多个 `Headline` | 包装层 `row-gap` | 已统一到全局 |

全局已把 **直接子级** `.collapse-container` 的 `margin` 清零，**不能**再依赖 margin 叠间距，必须靠父级 `gap` / `row-gap`。

### 局部样式（有意为之，不是 bug）

- `basic-appendix-row`：并排网格里对 `collapse-container` 清零 `margin-top`，用 `grid gap` 分列
- 预售类详情（现售/委托/测绘变更等）：`margin-top: 0` 配合自定义纵向 `flex` 布局
- `company-cancel-detail`：`.agency-basic-info-form + .collapse-container` 的 `margin-top: 12px` 会被全局 `margin-top: 0` 覆盖，实际靠 **`zs-form` 的 `row-gap`** 分块

### 后续注意（防再犯）

1. **不要**再把 `.detail-from-container.el-row` 加回「内层 `el-row` gap 归零」那条规则里。
2. 多个 `Headline` 若包在**普通 `div`** 里，且该层没有 `flex` + `gap`/`row-gap`，仍可能贴在一起——当前业务里常见包装（`detail-from-container`、`detail-container`、`*-basic-info-form`）已覆盖。
3. `zs-form` 在 DOM 上是 `el-form`，全局选择器 `.detail-from-container > .zs-form` 几乎不起作用，实际生效的是 `> .el-form`。

### 本次顺带加固

1. 在 `.detail-from-container.el-row` 上显式写上 `gap: var(--detail-block-gap) !important`，降低以后误改导致回归的概率。  
2. 将 `agency-basic-info-form` / `developer-basic-info-form` 的 `row-gap` 抽到 [`detail-form.scss`](zhi2-web-admin/src/styles/detail-form.scss)，与 token 对齐（原组件内写死 16px）。
