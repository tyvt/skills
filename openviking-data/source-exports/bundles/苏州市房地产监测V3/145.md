### 最终结论
## 原因

从待办进入时，业务主键在 URL 的末段或 `:tableid` 上（`navigateToTodoTask` → `buildTableIdNavigation`），应通过全局 **`getId()`**（`@/utils/ruoyi.js` 的 `resolveIdFromRoute`）解析。

`DeveloperBasicInfoDetail` 原先：

- **基本信息**：只调 `getOwnCompany`，忽略路径 ID  
- **入网认证**：`getEntryNetworkDetail()` 不传 `companyRecordId`（主管部门/待办场景需要传 ID）

## 修改

1. 增加计算属性 **`routeCompanyRecordId`**：仅 `this.getId()` + `query.companyRecordId`（不用 `form.companyRecordId`，避免 B 端刷新后误走 `detail` 接口）。
2. **`getDetail`**：有 `routeCompanyRecordId` 时走 `getCompanyRecordDetail`；否则仍走 `getOwnCompany`。
3. **`loadEntryNetworkDetail`**：仅当路由有 ID 时 `getEntryNetworkDetail(routeRecordId)`，本企业菜单无路径 ID 时仍不传 ID。

与 `DeveloperEntryNetworkAdminDetail`、`AgencyBasicInfoDetail` 的管理端按 ID 拉数方式一致。可在待办带 ID 的入网/基本信息详情页验证接口请求体是否带上 `companyRecordId`。
