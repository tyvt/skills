### 最终结论
根因是：之前用 **`npm_lifecycle_event` 推断 `runMode` 再 `loadEnv(runMode)`**。在 **`npx uni build`**、**CI 里直接调 `uni build`**、或 **未通过 npm script 跑** 时，`npm_lifecycle_event` 常常是空的，会被当成 **`development`**，结果 **`loadEnv` 读的是 `.env.development`**；若 CI 又没把 `.env.development` 拷进去，**`VITE_APP_H5_PUBLIC_BASE` 为空**，Vite 的 **`base` 就退回默认 `/`**，打包出来的 JS/CSS 就不会带 **`/h5/`**。

### 已做修改（`vite.config.ts`）

1. **用 Vite 传入的 `mode` 做 `loadEnv(mode, …)`**  
   与 `uni build`（`production`）、`uni build -m test`（`test`）一致，不再依赖 `npm_lifecycle_event`。

2. **`base` 来源顺序**  
   - 小程序：`process.env.UNI_PLATFORM` 以 `mp-` 开头时固定 **`./`**。  
   - H5：**`VITE_APP_H5_PUBLIC_BASE`** → 若没有，则读 **`src/manifest.json` → `h5.router.base`**（例如 `/h5/`）→ 再没有才用 **`./`**。  
   这样即使 CI 没带 `.env.production`，只要 **`manifest` 里配了 `h5.router.base`**，静态资源仍会带 **`/h5/`**。

3. **顺带**合并了 `build` 里重复的 **`sourcemap`** 配置，去掉 esbuild 的 duplicate key 告警。
