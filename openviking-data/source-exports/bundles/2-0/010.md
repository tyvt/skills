### 1. 用根目录的 `dev:bun` / `test:bun` / `build:bun` 时

- 是 **Bun** 在解析并执行 `bun run --filter zhi2-web-admin …`。
- 子包里的 `dev` / `test` / `build` 写的是 **`vite`、`cross-env` 等**，没有写 `npm`，所以链路大致是：**Bun → 子进程跑这些命令**，**不会**因为 `package.json` 在子模块里就变成「实际是 npm 在开发」。

也就是说：**日常开发/构建，本质是 Bun 当任务入口，真正干活的是 Vite / Node 工具链，不是 npm。**

### 2. 子模块里唯一「真的是 npm」的脚本

```14:14:d:\repository\园区物管2.0\zhi2-web-admin\package.json
    "install-dependencies": "npm install -f",
```

只有当你 **显式跑** `install-dependencies`（或根目录若写成去调这个脚本）时，脚本字符串里写了 `npm`，这时才会 **再调起 npm**。

根目录我们配的 `install-dependencies:bun` 是 **`bun install`**，一般 **不会**走上面这条，除非你改成 `bun run --filter zhi2-web-admin install-dependencies`。

### 3. 「子模块还是 npm」到底指什么

- **`package.json` 本身**不绑定包管理器，没有写死必须用 npm 或 Bun。
- **node_modules 是谁装的**：你在根目录用 `bun install` 就是 Bun 解析依赖；同事用 `npm install` 就是 npm。**两边不要混交两种 lock 策略**，避免锁文件冲突。

**简短结论**：  
用 `dev:bun` / `test:bun` / `build:bun` 时，**入口是 Bun，执行的是 Vite 等命令，不是 npm**；只有跑 **`install-dependencies` 那条脚本**（或脚本里写了 `npm` 的命令）时，才会 **用到 npm**。
