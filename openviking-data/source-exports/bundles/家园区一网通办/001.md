## 原因说明

这是 **uni-app H5 版 `picker-view` 与 `uv-picker` 行高算法不一致** 导致的典型问题，在微信小程序 **web-view 嵌入的 H5** 里更容易暴露。

1. 项目在 `main.ts` 里把 `uni.$uv.config.unit` 设成了 **`rpx`**，所有 `uv-picker` 的 `itemHeight="132"` 会变成内联样式 **`height: 132rpx; line-height: 132rpx`**。
2. H5 的 `picker-view` 用 **指示器实测高度（px）** 作为滚动步长，并通过 CSS 变量 `--picker-view-column-indicator-height` 约束子项高度。
3. **内联 `height` / `line-height` 优先级更高**，会盖掉上述变量，滚动按指示器高度算、选项按 rpx 渲染，**最后一项往往滚不到中间选中框**，只能点选。
4. 这与 DCloud 社区里「不要给 picker 项单独设 height/line-height」的结论一致。

## 已做修复

在 `src/style/index.scss` 增加了 **仅 H5 生效** 的全局样式，强制选项行高与指示器一致：

```18:35:src/style/index.scss
/* #ifdef H5 */
/*
 * 微信内置浏览器 / 小程序 web-view 中的 picker-view：
 * 滚动按 --picker-view-column-indicator-height（指示器实测 px）计算，
 * uv-picker 内联的 height/line-height（如 132rpx）会覆盖 uni 子项高度，导致最后一项无法滑入选中框。
 */
.uni-picker-view-content > * {
  height: var(--picker-view-column-indicator-height) !important;
  line-height: var(--picker-view-column-indicator-height) !important;
  box-sizing: border-box;
}

.uni-picker-view-group {
  touch-action: none;
}
/* #endif */
```

该修复会作用于项目中所有 `uv-picker`（含 `uv-datetime-picker`），**无需逐个改页面**。
