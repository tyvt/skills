### 用户诉求 1
多加了一个筛选条件之后按钮位置从右边跑到左边了，有时候图标加载不出来搜索按钮就看不到了 [图片]
[图片]

### 最终结论
**根因**

两处叠加，不是图标问题：

1. 新增“推送状态”后筛选条件从 10 个变 11 个。占位符 `<el-form-item style="width:76%">`（18% 宽 + 2% 右边距 = 第 3 行占 98%）+ 新项 20% 撑满第 3 行，把 `.search` 挤到第 4 行；而 `.search` 只有 19% 宽且 `justify-content:flex-end`，按钮就在那 19% 盒子内侧，落点跑到左侧。
2. 4 个按钮（搜索/重置/批量导入查询/导出excel表格）最小宽度 ≈ 380px，远超 19% 盒子（≈330px）。`flex-end` + 不可换行时，溢出会向**左**挤 —— 第一个按钮“搜索”被推出可视区，所以看不到。图标字体没加载时字形变宽（截图里的 `þ^`、`^` 乱码），溢出更多，“搜索”就彻底消失。

**改动**（`contAllQueryList.vue`，仅此一处）

- 删掉固定宽度占位 `<el-form-item style="width:76%">`
- 加 scoped 覆盖：

```scss
#contAllQueryList .table-search .search {
  flex: 0 1 auto;        /* 不再固定 19%，按内容自适应 */
  width: auto;
  flex-wrap: wrap;       /* 放不下就换行，不再向左溢出隐藏 */
  justify-content: flex-end;
  margin: 10px 0 10px auto;  /* 无论在第几行，永远右对齐 */
}
```

**效果/健壮性**

- 按钮回到右侧，与“推送状态”同行右对齐（顺带省掉一整行空白，表格多 40px）。
- `margin-left:auto` + `flex-wrap` 不依赖行号，以后再加/减筛选条件都不会再跑到左边或被裁掉。
- 图标字体未加载时按钮文字仍完整可见，不再因宽度变化把“搜索”挤出屏幕。

**顺带提示**：截图里按钮图标是乱码（`þ^`），说明 element-ui 的 `element-icons.woff` 在你当前环境没加载成功 —— 与本次布局 bug 无关，需要的话可以单独排查字体路径/打包配置。

未改动全局 `_zsForm.scss`，避免影响其余 ~200 个列表页；`netSignFilingsList.vue` 也有同款 74% 占位写法（未出现该问题），需要时可用同样方式处理。
