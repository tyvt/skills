## 为什么

**1. 你的项目本身不调 LLM** — 我扫了 `zhi2-web-admin`，除了 `public/assets/js/element-ui.js`（第三方 UI 库命中的关键词）没有任何 `openai/anthropic/langchain/litellm` 调用。headroom 的**库模式**（`compress(messages)` 内联进自己的代码）对你没有任何作用对象。

**2. 真正有用的那部分不是"库"，是代理/包裹层** — headroom 的价值场景是：
- `headroom wrap claude` / `headroom proxy --port 8787` — 截住 coding agent 发给模型的流量做压缩
- 它还会装 Serena MCP、注册 agent 配置、起本地 proxy

这和你记忆里"删除需配置的重型套件、要求零额外工作量"的偏好直接冲突：它是一个常驻代理 + 全局 agent 配置 + 一大堆 extras（`torch`、`transformers`、`onnxruntime`、`sqlite-vec`…`uv tool install "headroom-ai[all]"` 是 GB 级依赖）。而且你现在跑在 pi 框架里，pi 自己管理模型请求，外部 proxy 要么接不进去，要么要改 pi 的 provider 配置——又是一层配置。

**3. 它压缩的东西，你已经有更轻的方案在管** — 你 shell 里每次都在打印的 `[rtk] No hook installed` 就是同类工具：`rtk` 已经装了，专门做 CLI 输出压缩（`rtk grep` / `rtk read` / `rtk ls` / `rtk json`），这正是 headroom 里"压缩 tool output"那一块，而且零常驻进程。

## 如果真想再省 token，按性价比排序

1. **跑一次 `rtk init -g`** — 一行命令装上 hook，之后 CLI 输出自动压缩，这是你已有的东西，边际成本最低。
