### 最终结论
## 根因

`SelectEntryDialog.vue` 内部对 **prop 直接赋值**，靠 `:visible.sync="visible"` 关闭弹窗：

```vue
<el-dialog :visible.sync="visible" ...>   <!-- visible 是 prop -->
...
handlePick() { this.visible = false }      <!-- 改 prop，不通知父组件 -->
```

后果链：
1. 点「选择录入数据」→ 父组件 `showSelectEntryDialog = true` → 打开弹窗，请求 `selectableEntryPage`。
2. 关闭弹窗时只把**子组件本地的 prop 值**改成 `false`，父组件 `showSelectEntryDialog` **仍是 `true`**（无 `update:visible` 事件）。
3. 之后列表页任何一次 re-render（点「搜索」→ `handleQuery` → `getList` → `loading` 变化就会触发），子组件 prop 被父组件重置回 `true` → 弹窗重新打开 → `watch visible` 触发 `getList()` → **又调了一次 `selectableEntryPage`**。

这就是「点搜索却调弹窗接口」的原因。

## 修复

`zhi2-web-admin/src/views/presale/leaseContract/components/SelectEntryDialog.vue`，改用 computed 代理（与本目录 `PropertyVerifyDialog.vue` 既有约定一致）：

- 新增 `dialogVisible` 计算属性：`get` 返回 `this.visible`，`set` 发 `this.$emit('update:visible', val)`。
- 模板改为 `:visible.sync="dialogVisible"`。
- `handlePick` 改为 `this.dialogVisible = false`。

父组件已使用 `:visible.sync="showSelectEntryDialog"`，现在能正确收到 `update:visible`，状态会真正回到 `false`，re-render 不再把弹窗顶开。

已扫描 `src/views/presale` 下同类写法，无残留 `this.visible = ` 的 prop 直改。
