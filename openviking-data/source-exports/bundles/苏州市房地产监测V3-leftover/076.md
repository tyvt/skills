## 机制核对

**根因（修复前）**

`buildDetailNavigation` 在匹配到无 `:tableid` 的命名详情路由时返回 `{ name: routeName, query }`，`query` 原先只有 `formMode`、`backUrl`。详情页通过 `detailMixins` 的 `id` → `getId()` 取主键；`resolveIdFromRoute` 在无 `query.id` 时会从 `path` / `params.tableid` / `findIdInPathSegments` 推断。企业管理员等模块路径末段为 `companyAdmin` 这类**纯字母模块段**时，可能得到错误 ID（例如字面量 `companyAdmin`），进而 `init()` → `getDetail()` 用错主键。

**修复后（`ruoyi.js` 463–469）**

```463:469:zhi2-web-admin/src/utils/ruoyi.js
export function buildDetailNavigation(rowId, formMode, listRoute = router.currentRoute) {
  const query = { formMode, backUrl: listRoute?.path }
  const id = String(rowId)
  // 命名路由且路径无 :tableid 时，主键只能走 query.id，否则 getId() 会从路径段误解析（如 companyAdmin）
  if (isNavigableDataId(rowId)) {
    query.id = id
  }
```

与 `getId()` 首段逻辑对齐：

```105:108:zhi2-web-admin/src/utils/ruoyi.js
  const queryId = route?.query?.id

  }
```

**`isNavigableDataId` 边界**

- `'add'`、空值、纯模块路径段（如 `companyAdmin`）→ **不写** `query.id`（新增、非法 ID 行为与改前一致）。
- 典型数字/雪花 ID、含数字或特殊字符的主键 → **会写** `query.id`。

**调用面**

- `listMixins` 的 `handleView` / `handleUpdate` 及 `companyAdmin/index.vue` 等均经 `buildDetailNavigation(row[primaryKey], …)`，会受益。
- `handleAdd('add')` 不满足 `isNavigableDataId`，不会误带 `query.id`。
