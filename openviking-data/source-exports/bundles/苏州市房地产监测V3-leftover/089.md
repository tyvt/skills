## 审查结论

针对 `AgencyApplyDialog.vue` 中 `recordAgentIds` 的规则（约第 71–74 行）：

```71:74:zhi2-web-admin/src/views/institution/record/components/AgencyApplyDialog.vue
          { required: true, type: 'array', message: '请选择3位备案经纪人', trigger: 'change' },

```

`zs-form` 是对 `el-form` 的薄封装，星号与校验逻辑均走 Element UI 2.x + async-validator，行为与项目内其它多选字段（如 `TransferToKBDialog.vue` 的 `type: 'array'` + `required`）一致。

### 必填星号（`*`）

- `el-form-item` 的 `isRequired` 来自该 `prop` 的规则里是否存在 `required: true`。
- 原先只有 `validator: validateAgents` 时**不会**显示星号；补上 `required: true` 后「设置备案经纪人」会正常出现必填标识。
- 这与同表单「要件」`attachments` 使用 `required: true` 的方式一致。

### 校验行为

| 场景 | `required` + `type: 'array'` | `validateAgents` | 提交 `validate()` |
|------|------------------------------|------------------|-------------------|
| `[]` / 非数组 | 失败（空数组在 `type: 'array'` 下算 empty） | 失败（`length !== 3`） | 不通过 |
| 选 1～2 人 | 通过（非空数组） | 失败 | 不通过 |
| 选 3 人 | 通过 | 通过 | 通过 |

- **`type: 'array'` 有必要**：若只有 `required: true` 而没有 `type: 'array'`，空数组 `[]` 在部分 async-validator 行为下可能不被当作 empty，星号有了但「未选」边界可能不稳；与 `attachments` 显式写 `type: 'array'` 的惯例一致。
- **`trigger: 'change'`**：选择变化时会触发校验；点「确认」时 `this.$refs.form.validate(...)` 会**无视 trigger** 执行全部规则，空或未满 3 人仍会被拦住。
- **`multiple-limit="3"`** 与 `validateAgents` 的「恰好 3 人」一致，不会出现选超过 3 人仍通过校验的情况。
- **重复失败**：未选时两条规则可能都失败且文案相同，Element 通常只展示一条错误，不影响可用性。

### 与 `validateAgents` 的分工

- 第一条：必填 + 类型/空数组（主要服务于星号与「完全未选」）。
- 第二条：业务规则「必须恰好 3 位」。
- 逻辑正确，无冲突。
