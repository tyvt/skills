### 最终结论
你贴的日志里其实有**两个独立问题**，我都修了。

## 1. DuckDB「被占用」——其实是 `report.py` 自己搞出来的

报错：
```
另一个程序正在使用此文件
Can't open a connection to same database file with a different configuration
Unique file handle conflict: Cannot attach "market"
```

根因在 `duckdb_cache.py` 的 `_conn()`：

- **读数据时也开写连接**（还调了 `ensure_schema()`）
- **连接用完不 `close()`**
- `report.py` 一次要读十几个缓存键，进程内就堆了多个 DuckDB 连接，自己把自己锁死

所以不一定是别的程序占着，**跑报告时进程内部就会冲突**，然后部分数据回退 CSV。

**修复**：拆成 `_read_connection()`（只读 + 自动关闭）和 `_write_connection()`（写入 + 自动关闭）。

---

## 2. `incompatible merge keys M8[ns] vs M8[us]`——DuckDB 日期精度不一致

DuckDB 读出来是 `datetime64[us]`，CSV 是 `datetime64[ns]`。上面 DuckDB 读失败后混用两种来源，在 `us_index_data.build_valuation_panel` 的 `merge_asof` 就炸了。

**修复**：
- `duckdb_store.load_wide_frame` 统一转成 `datetime64[ns]`
- `data_cache.load_dataframe` 解析日期时也统一精度
