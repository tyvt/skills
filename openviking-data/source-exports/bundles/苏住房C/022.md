## 改造思路

**旧方案（宿迁）**：每个业务接口单独上架一个 `interface_id`  
**新方案**：苏服办开放平台只上架 **2 个** `interface_id`（GET / POST），前端统一调 `gateway.do`，真实路径由 `header` 里的 `zs-path` 告诉后端，后端内部转发。

## 请求格式（与宿迁一致）

开启 `VITE_APP_USE_SFB_DISPATCHER = 1` 后，所有接口统一 POST 到：

`https://ydzt.jszwfw.gov.cn/jpaas-jags-server/interface/gateway.do`

FormData 字段：

| 字段 | 内容 |
|------|------|
| `app_id` | 应用 ID |
| `interface_id` | GET 类接口 ID 或 POST 类接口 ID |
| `biz_content` | 业务参数 JSON，如 `{"pageNum":1,"pageSize":10}` |
| `header` | 含 `Authorization`、`zs-path`、`zs-sign` 等 |
| `sign` | SM3 网关签名 |
| `timestamp` / `charset` / `origin` / `version` | 网关固定字段 |

例如调用 `/company/companyRecordAuth/page?pageNum=1&pageSize=10`：

- `interface_id` → GET 类 ID（`VITE_APP_SFB_GET_INTERFACE_ID`）
- `header` → `{"Authorization":"Bearer xxx","zs-path":"/company/companyRecordAuth/page","zs-sign":"...","zs-timestamp":"...","zs-nonce":"..."}`
- `biz_content` → `{"pageNum":1,"pageSize":10}`

业务代码**不用改**，仍然 `api.get('/company/companyRecordAuth/page', { params: { pageNum: 1, pageSize: 10 } })`。

- `sign.js` — 跳过对 `gateway.do` 的重复签名
- `.env.*` — 新增 `VITE_APP_SFB_GATEWAY_URL`
- `vite.config.ts` — 开发环境增加 `/sfb-gateway` 代理，避免 CORS
