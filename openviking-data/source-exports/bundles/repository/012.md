### 最终结论
## 原因说明

`index.html` 里原来依赖入口脚本的 **`onload` 里调用 `__hidePageLoading()`** 来关掉「页面加载中」遮罩。

执行 **`uni build` 后**，Vite 会**重新注入**打包后的入口，例如：

```html
<script type="module" crossorigin src="/assets/index.xxx.js"></script>
```

这条注入的脚本**不会带上**你在源码里写的 `onload` / `onerror`，所以生产环境里 **`__hidePageLoading` 从未执行**，遮罩会一直显示。  
本地 `npm run dev` 仍按开发时的 `index.html` 处理，**`onload` 还在**，所以本地表现正常。

## 修改说明

在 **H5** 应用 **`onLaunch`** 一开始调用 `window.__hidePageLoading()`（仅 `window` 存在时），与入口 JS 已执行、应用启动的时机一致，且不依赖构建是否保留 `onload`。

修改位置：`src/App.vue` 的 `onLaunch` 开头。

重新 **`npm run build`** 后，把 **`dist` 整包**部署到生产即可。

---

**补充**：`index.html` 第 105 行仍保留的 `onload` 对生产构建**无实质作用**（会被注入脚本覆盖），可保留作开发时的双保险，或以后删掉只保留 `App.vue` 里的逻辑。若部署在非站点根路径，还需确认 `VITE_PUBLIC_PATH` 与 CDN 路径一致，否则会出现资源 404（那是另一类问题）。
