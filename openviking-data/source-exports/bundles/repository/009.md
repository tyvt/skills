## 分析结论

**会复用 token。** 原因：

| 环节 | 说明 |
|------|------|
| **getToken()** | 从 `useUserStore().accessToken`（即 `state.token`）取 token。 |
| **持久化** | `stores/user.js` 里配置了 `persist`，用 `uni.setStorageSync` 把整个 store 存到本地。 |
| **恢复** | 再次打开应用时，Pinia 会从本地恢复 state，所以 **旧 token 会被恢复并继续使用**。 |

因此，若不主动清空，每次重新打开应用都会沿用上次的 token。

---

## 已做的修改（实现「每次打开都重新登录」）

1. **在 `stores/user.js` 中新增 `clear()`**
   - 清空 `token`、`userDetail`、项目/房屋等与登录相关的 state。
   - 401 时也会调用该方法，用于退出登录态（原逻辑里调了 `userStore.clear()` 但之前未定义，现已补上）。

2. **在 `App.vue` 的 `onLaunch` 开头调用 `userStore.clear()`**
   - 每次冷启动（用户重新打开应用）时先清空登录态，再执行后续逻辑（如灵犀登录等）。
   - 这样每次打开都不会带旧 token，需要重新走登录流程拿到新 token。

3. **修正 `api/index.js` 里 401 时的调用**
   - 原代码写了 `userStore.clear()`，但未定义 `userStore`，会报错。
   - 已改为 `useUserStore().clear()`，与当前文件里的用法一致。

效果：**每次从桌面/任务列表重新打开应用，都会先清空登录态，需要重新登录并使用新 token**。若你希望只在「完全退出再打开」时重新登录，而「从后台切回前台」不清理，可以把 `userStore.clear()` 从 `onLaunch` 挪到只在不持久化/不恢复 token 的时机执行，或根据场景加条件判断。
