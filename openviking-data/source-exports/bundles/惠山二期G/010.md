## 原因

Git Credential Manager（GCM）其实还在：`C:\Program Files\Git\mingw64\bin\git-credential-manager.exe`（2.6.1），系统级也配置了 `credential.helper=manager`。

问题出在**用户全局** `C:\Users\Administrator\.gitconfig` 里曾经有一条**空的** `credential.helper`。Git 会按顺序调用多个 helper，空的那条会先执行并干扰后面的 manager，表现就像「凭据管理器没了」，每次 **push / pull / fetch** 都要再输账号密码。

（纯本地 `git commit` 一般不需要联网凭据；要密码多半是推送或拉取。）

另外你配置里还有 UGit 的 SSL 证书路径，说明以前可能用过 UGit 管凭据；卸掉 UGit 后更容易只靠 GCM，这条空 helper 就更显眼。

## 已做的修复

1. 删掉全局里空的 `credential.helper`
2. 全局只保留：`credential.helper = manager`
3. 执行了 `git-credential-manager configure`

当前有效配置应为单一的 `manager`。

## 请你本地验证

在项目目录执行一次：

```bash
git fetch
# 或
git push
```

第一次可能还会弹出 GCM 登录窗（或命令行提示），输入 **gitlab.zhi.com** 的账号密码或 Token；成功后 Windows「凭据管理器」里会出现 `git:http://gitlab.zhi.com` 一类条目，之后应不再反复输入。

若仍每次都要输密码，可再试：

```bash
git credential-manager erase
# 按提示输入 protocol=http host=gitlab.zhi.com
```

然后重新 `git fetch`，让 GCM 重新保存凭据。

**建议**：内网 GitLab 若支持，长期更省事的是改用 **SSH 远程地址** + SSH 密钥，可完全不走 HTTP 密码。
