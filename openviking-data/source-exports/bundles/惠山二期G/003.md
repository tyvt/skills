CI 只有 **4GB 内存**，不能靠把堆调到 8192 解决——之前 OOM 时堆已经顶到 **4096MB 上限**了。

## 思路

在 **4GB 机器上降低构建峰值内存**，而不是继续加堆。

## 已做修改

**1. `scripts/vite-build.mjs`** — 自动检测低内存环境：
- 系统内存 < 6GB，或 `CI=true`，或 `LOW_MEMORY_BUILD=true` → 低内存模式
- 低内存堆上限：**3840MB**（给 OS 留约 256MB）
- 本地大内存机器仍用 **8192MB**

**2. `vite.config.js`** — 低内存模式下：
| 优化项 | 效果 |
|--------|------|
| `maxParallelFileOps: 1` | 串行处理，降低并行峰值 |
| test 模式关闭 JS/CSS 压缩 | 压缩阶段最吃内存 |
| 跳过 `manualChunks` | 减少 Rollup 图分析开销 |
| 跳过 visualizer | 不做 gzip/brotli 分析 |
| 跳过 SVG SVGO 压缩 | 减少 SVG 处理内存 |
| `cssCodeSplit: false` | 合并 CSS，减少 chunk 元数据 |

## 验证

模拟 CI 低内存构建已通过：
```bash
LOW_MEMORY_BUILD=true NODE_HEAP_SIZE=3840 yarn run test  # ✅ 约 3 分钟
```

## CI 注意

GitLab Runner 默认有 `CI=true`，会自动进入低内存模式。若仍 OOM，可在 CI 变量里显式加：

```yaml
variables:
  LOW_MEMORY_BUILD: "true"
  NODE_HEAP_SIZE: "3840"
  HUSKY: "0"
```

**test 环境构建产物不会压缩**，体积会大一些，但 test 部署一般可以接受。production 的 `build` 在低内存机器上仍会压缩。
